# NeuroBridge 对外发布工作流 PRD

- **文档状态**：需求评审稿
- **适用范围**：Windows 软件、银河麒麟系统 V10 软件及 GitHub Actions 发布流程
- **版本依据**：`neurobridge/version_registry.toml`

## 1. 背景与目标

当前仓库已有单元测试、北向协议文档 PDF 和部分外部文档打包流程，但缺少统一的应用版本门禁和跨平台发布产物流程。本 PRD 目标是让合入 `master` 的变更可审计、可复现，并避免业务代码变化却沿用旧版本号。

目标：

1. 在 PR 合入 `master` 前，自动识别是否改变对应软件的业务代码并执行版本号规则。
2. 形成 Windows 和银河麒麟系统 V10 两类软件的版本化发布包流程。
3. 记录每个软件产物的版本、来源、校验值、构建环境和发布状态。

## 2. 功能需求

### 2.1 应用版本门禁

- 版本唯一来源为 `neurobridge/version_registry.toml` 的 `[application].version`。
- CI 以 PR 目标分支（默认 `master`）为基线比较版本。
- 业务代码范围由配置维护，至少覆盖 `neurobridge/`、平台部署目录、运行依赖和打包配置；只改文档、测试或网页资源不强制升应用版本。
- 业务代码变化时：PR 版本等于 `master` 版本则失败并提示至少 `master patch + 1`；大于则通过；小于则失败并说明版本回退原因。
- 未改业务代码时版本可不变，但不得低于 `master`。
- Actions summary 必须包含基线版本、PR 版本、变更文件和判定理由。

### 2.2 Windows 发布包

- 按发布配置中的版本矩阵为每个 Windows 目标版本生成独立 Artifact。
- Windows 最低系统版本和 CPU 架构当前均未知，不能在 Workflow 中预设单一版本或架构；实现必须支持官方数据确认后的全部 Windows 版本/架构组合，并为每个组合分别建包。
- Windows 安装包格式至少拆分为 **EXE** 和 **MSI** 两类；两类包分别构建、校验和发布，不得仅通过重命名复用同一文件。
- 每个包包含软件文件、依赖锁定信息、启动/卸载说明、版本清单和 SHA-256 校验值。
- 尚未完成可执行包验证时只能标记为 `source-only` 或 `candidate`，不得伪称正式安装包。
- 包名、清单和 Artifact 名称必须含平台、架构和应用版本。

### 2.3 银河麒麟系统 V10 发布包

- 按已确认的银河麒麟 V10 CPU 架构分别建包，不得混用架构。
- 麒麟 V10 的具体发行版、CPU 架构和仓库格式当前均未知，不能只支持 x86_64 或 ARM64 其中之一；实现必须根据官方数据发现并覆盖全部确认的发行版/架构组合。
- 麒麟 V10 安装包格式至少拆分为 **DEB** 和 **RPM** 两类；两类包分别生成对应的安装、升级和卸载元数据。
- 版本和下载来源以麒麟官网或双方确认的官方数据为准，记录来源 URL、抓取时间和校验值。
- 每个包包含安装/升级、依赖检查、服务启动、回滚说明、版本清单和 SHA-256 校验值。
- 未完成目标架构现场验证时只能标记为 `candidate`。

### 2.4 当前流程不包含的历史交付物

- 旧版 Ubuntu 网关使用的 SSH 运维操作指南不属于当前 Windows 或银河麒麟 V10 软件包。
- 旧版 Ubuntu 网关使用的有线网络配置指南不属于当前 Windows 或银河麒麟 V10 软件包。
- 上述历史文档及旧 Ubuntu 部署物不得被当前 Workflow 自动标记为 Windows 或麒麟 V10 的交付内容；如需维护，另建独立的 Ubuntu 维护流程。

### 2.5 发布清单

每次正式发布生成 `release-manifest.json`，包含应用版本、Git commit、构建时间、Windows EXE/MSI 与麒麟 DEB/RPM 目标的版本/架构/格式/状态/文件名/SHA-256、官网来源及 `candidate`/`published` 状态。北向协议版本仍可作为软件兼容性元数据记录，但不触发本流程的文档打包。

## 3. 工作流与门禁

1. `pull_request -> master`：运行版本门禁、测试和 Windows/麒麟候选包构建，不发布正式包。
2. PR 合入默认分支后由 `push -> master` 自动触发正式构建，生成 Windows/麒麟正式 Artifact；不自动修改版本台账或历史文档。
3. 正式 Artifact 保留 **30 天**，下载权限为**所有能够访问仓库 Actions 的用户**，不做额外权限限制。
4. 正式产物不进行代码签名、安装包签名或公证；清单中的 SHA-256 仅用于完整性校验。
5. 平台构建失败、版本冲突、来源数据缺失或校验值不一致时，工作流失败并说明原因。

## 4. 非功能要求

- 固定 Python、编译器和依赖版本，保存构建日志，确保可重复构建。
- **离线优先**：构建、测试、打包和校验阶段默认不访问公网；官方版本信息、安装源和依赖在单独的联网准备阶段下载并缓存，正式构建只读取已校验的缓存。
- 缓存必须包含来源 URL、抓取时间、版本、文件大小和 SHA-256；缓存缺失或校验失败时流程直接失败，不临时联网绕过。
- 发布环境允许完全断网运行；只有版本源或安装源尚未进入受控缓存时，才需要联网准备并重新生成候选包。
- 每个 Artifact 可反查 Git commit、版本台账和官网来源。
- 不把凭据、私钥、现场配置或人体原始数据写入 Artifact/日志。
- 不改变北向报文 `protocolVersion`，不把 BLE、SDK 或算法内部细节写入对外文档。

## 5. 验收标准

- 业务代码变更且版本不变的 PR 必须失败并提示提升版本。
- 版本高于 `master` 的 PR 通过，低于 `master` 的 PR 失败并说明回退原因。
- PR 构建生成 Windows EXE/MSI 和麒麟 V10 DEB/RPM 的候选清单，状态与验证事实一致。
- `master` 构建生成带 SHA-256 的 `release-manifest.json` 和正式 Artifact。
- Artifact 可在无公网环境按清单校验。
- 现有单元测试和协议兼容性检查全部通过。

## 6. 已确认约束

- Windows 和银河麒麟 V10 的系统版本、发行版及 CPU 架构当前不预设单一值，必须支持官方数据确认后的全部适配组合。
- Windows 适配矩阵固定包含 Windows 7、Windows 10、Windows 11，并分别覆盖 32 位（x86）和 64 位（x86_64）；每个组合单独验证并记录兼容性结果。
- Windows 每个适配组合都生成 EXE 和 MSI；麒麟 V10 每个适配组合都生成 DEB 和 RPM，并分别验证安装、升级和卸载行为。
- “各个版本”专指操作系统版本适配性，不要求回溯构建历史应用版本。
- 构建、测试、打包和校验默认离线；官网版本信息、依赖和安装源先缓存并校验，正式构建只读取缓存。
- PR 合入默认分支后触发正式构建；Artifact 保留 30 天，所有可访问仓库 Actions 的用户均可下载，不做签名或公证。
- 官网版本数据中列出的 Windows 和银河麒麟 V10 版本/架构全部纳入支持矩阵，不由 Workflow 人工挑选或只支持部分版本。
- Windows EXE/MSI 与麒麟 DEB/RPM 产物统一放入一个 ZIP 包；ZIP 内按平台、系统版本、架构和安装包格式区分文件。
- ZIP 文件名必须包含应用版本号、目标平台和构建日期；包内清单还必须记录 Git commit、构建时间和各文件 SHA-256。
- 构建、下载、缓存或打包步骤失败时自动重试，单个步骤最多 3 次；3 次仍失败则 Workflow 失败并保留明确错误原因。
- Windows 安装器方案：EXE 提供可独立执行的安装/启动入口，MSI 提供标准 Windows Installer 安装、升级和卸载入口；两者都必须支持静默安装参数、版本检测和卸载。
- 运行时依赖清单基线：Python 运行时（按支持的 Windows 架构提供）、`bleak==0.19.0`、`websockets==12.0`、网关 Python 包及其锁定依赖；BLE 驱动/运行库、Windows 服务运行组件和 VC++ 运行库按每个系统组合的实际构建结果补齐并写入清单。
- 依赖必须随包提供或进入离线缓存，安装阶段不得临时访问公网；每项依赖记录版本、架构、来源和 SHA-256。

## 7. 仍需确认事项

1. 麒麟版本数据的首选官方来源已确定为 `https://www.kylinos.cn/` 的产品/服务支持入口及其官方镜像域名 `https://iso.kylinos.cn/`、`https://distro-images.kylinos.cn/`；Workflow 需在联网准备阶段抓取并缓存官方页面或索引，记录 URL、抓取时间、版本、架构和 SHA-256。当前公开资料可见 V10 服务器/桌面版本及 x86_64、ARM64、LoongArch64、MIPS64el、SW64 等架构，均纳入发现范围。
2. 麒麟 DEB/RPM 的安装器元数据、系统依赖和服务注册方式仍需以官方安装包/仓库资料确认；在确认前不得假设某一格式可用于全部 V10 发行版。Windows 安装器和依赖按本 PRD 基线实现并在矩阵中验证。

## 8. 当前实现范围

本次实现不拆分子 PR，必须在当前 Workflow 需求中一次性完成以下能力：

- PR 业务代码变更的应用版本门禁；
- Windows 全部确认系统版本/架构的 EXE 与 MSI 产物；
- 银河麒麟 V10 全部确认发行版/架构的 DEB 与 RPM 产物；
- 离线优先的官方版本信息、依赖和安装源缓存；
- PR 候选构建、合入默认分支后的正式构建、30 天 Artifact 保留和统一发布清单；
- 失败原因、来源 URL、版本、架构、格式和 SHA-256 的可审计记录。

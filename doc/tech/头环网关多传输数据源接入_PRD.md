适用范围：NeuroBridge Linux/PC 网关设备接入层

目标运行环境：同一台 N100/N150 x86_64 电脑重装银河麒麟 V10 后作为正式网关；最终安装镜像确定为 `Kylin-Desktop-V10-SP1-2503-HWE-PP-Release-20250430-X86_64.iso`，当前文件 SHA-256 为 `d858e3ac19aa317ab1d2133a6aacbe978662ce9dcc10437119841627a416cc66`。安装后的系统构建号和内核版本以目标机诊断脚本输出及 POC 记录为准。原 Ubuntu 24.04 环境仅作为重装前兼容与回归基线，不是并行部署环境或最终交付环境

## 0. 运行环境差异风险

本节的兼容结论必须绑定“具体电脑硬件 + 具体银河麒麟镜像 + 安装后的内核和依赖版本”。其他电脑安装麒麟成功，不代表 N100/N150 可用；同一电脑安装其他银河麒麟 V10 镜像成功，也不代表目标镜像可交付。

### 0.1 N100/N150 与其他麒麟电脑的硬件差异

| 差异项 | N100/N150 与其他电脑的差异风险 | 控制措施 |
|---|---|---|
| CPU 架构与指令集 | N100/N150 为 x86_64；其他电脑可能是 ARM64、LoongArch64 或其他 x86_64 平台。Python 原生扩展、C++ 算法 bridge 和第三方二进制不能跨架构复用 | 以目标机 `uname -m`、`lscpu` 和实际构建产物为准；所有原生依赖必须在目标架构构建或取得对应架构版本 |
| 芯片组与内核驱动 | 即使其他电脑也是 x86_64，其网卡、USB 控制器、核显、NVMe/SATA 控制器和电源管理器件也可能与 N100/N150 不同 | 只能在目标 N100/N150 上确认驱动可用；安装后逐项验证显示、网卡、USB、存储、重启和电源管理 |
| USB 拓扑与供电 | 不同主板的 USB 控制器、Hub 层级、端口供电和热插拔行为不同，可能影响串口枚举、设备复位和长期连接稳定性 | 在最终使用的物理 USB 端口上完成枚举、握手、持续采集、反复插拔和重启恢复测试，并固定现场接线 |

| 性能与散热 | CPU 核数、频率、内存、存储和散热差异会影响 200 ms 握手探测、600 ms 数据窗口、算法耗时和长期稳定性 | 性能与容量结论必须在目标 N100/N150 上实测；其他电脑结果只作参考，不能直接作为验收数据 |

## 1. 背景

当前网关通过 BLE 连接 Flowtime 头环，负责设备扫描、连接、通知订阅、原始数据持久化、算法调用、录播和北向 WebSocket 服务。部分部署现场可能禁用蓝牙，或设备可能提供串口、USB 等有线通信方式，因此网关需要在不改变北向业务契约的前提下支持多种设备侧传输。

当前交付场景进一步收敛为一台 N100/N150 同时运行网关后台和可视化浏览器，不再要求独立 B 端主机或数据专用网线。浏览器继续通过 WebSocket 获取实时数据和发送订阅控制，但连接只经过操作系统回环地址。为保留旧交付方案和后续扩展，前端访问拓扑也使用策略模式：默认 `local_browser`，兼容 `wired_b_side`；两种策略不得复制或分叉业务协议实现。

本需求将设备接入方式扩展为以下三种互斥策略：

1. 蓝牙（Bluetooth Low Energy，简称 BLE）；
2. 串口（系统表现为串行字符设备，包括板载 UART、USB CDC ACM 和 USB 转串口）；
3. 原生 USB（通过 HID、Bulk 或 Interrupt 等 USB 接口通信，不表现为串口）。

一次网关进程只能选择并运行一种设备数据源。网关不得同时连接多种传输，也不得在运行时自动从一种传输切换到另一种传输。

### 1.1 首期已确认场景

- 网关部署在现有 N100/N150 x86_64 电脑上，该电脑将覆盖安装麒麟系统；麒麟是首期正式运行和验收环境。
- 同一台电脑运行 systemd 网关后台和本机浏览器。默认访问链路为 `HTTP/WS → 127.0.0.1`，不配置 B 端专用网线、静态地址或 DHCP。
- 浏览器仅负责展示和协议操作，不直接使用 Web Serial/WebUSB；串口遍历、握手、算法、录制和重连仍由网关后台负责。
- 保留 `wired_b_side` 兼容策略，以便未来恢复独立 B 端主机；切换策略需要修改部署配置并重启，报文契约保持不变。
- 目标耳机通过 USB 与麒麟系统电脑进行物理连接。
- 耳机在操作系统中以串口形式提供数据，因此首期配置选择 `serial`，不按原生 USB HID/Bulk 接口开发。
- 同一电脑可能存在多个串口，目标串口不能仅凭 `/dev/ttyACM*` 或 `/dev/ttyUSB*` 的编号确定。
- 网关需要按稳定顺序逐个枚举 USB 派生的候选串口并读取握手数据；收到第一个完整固定握手帧后即判定目标、回复 ACK 并停止继续遍历。本期部署保证只连接一台目标耳机，不处理多个同时握手设备的消歧。
- 目标设备上电后每 200 ms 发送一次 7 字节握手帧 `AA 55 01 01 01 01 6F`；上位机返回完全相同的 7 字节 ACK 后，设备停止重复握手。
- 网关收到目标串口的握手后立即返回同值 ACK；设备停止重复握手。算法会话初始化成功后，网关发送单字节 `0xE1` 使能脑电；停止采集时发送单字节 `0xE0`。两条控制指令都会返回响应，但响应格式和内容不作解析：配置超时内收到任意非空响应即判定成功，超时未收到响应即判定失败。
- 串口参数已确认为 115200、8 数据位、无校验、1 停止位、无流控（115200 8-N-1）。
- 脑电心率数据包固定为 28 字节，包括 3 字节包头、1 字节包长、2 字节大端序列号、6 个 3 字节脑电值、1 字节心率和 3 字节包尾。首个有效帧的序列号作为会话基线，之后按无符号 16 位大端值递增，`0xFFFF` 后回绕到 `0x0000`。
- 设备收到上位机 ACK 并执行 `0xE1` 使能脑电后发送脑电和心率原始数据。串口适配器保存完整 28 字节设备帧，并从中提取“2 字节序列号 + 18 字节脑电”为与现有 BLE `FF31` 等价的 20 字节算法原始输入、提取 1 字节心率为与 `FF51` 等价的原始输入；不得自行重采样、缩放或重编码，最终以真实数据对现有算法回归结果为准。
- 设备方确认以串口形式接收数据；但接线图显示系统中存在 USB HOST、USB DEVICE/耳机和 TTL 串口三组接口，麒麟电脑实际读取的是哪一组接口及其对应设备节点仍需现场确认。
- 如果麒麟电脑接入的转换板接口已经生成可读写的 TTY 设备节点，则不需要再增加电脑侧 USB 转串口模块；如果电脑只连接 USB HOST、而 TTL 串口由其他控制器读取，则网关必须按实际数据路径配置，不能假定 USB HOST 侧直接提供 TTY。

协议依据：[军工耳机脑电串口协议](https://entertech.feishu.cn/docx/UwtYdp2RzoZQA4xTx8ccXwwQnOc?from=from_copylink)，读取修订号 178，读取日期 2026-08-31。

### 1.2 接线与数据链路示意

![头环 USB 串口转换板接线示意图](assets/头环USB串口转换板接线示意图.png)

图中标注的三组接口如下，颜色和引脚名称必须以设备方原理图、万用表/示波器或现场连通性测试复核，不能仅凭图片接线：

| 接口 | 图中标注 | 在本 PRD 中的暂定作用 | 必须确认 |
|---|---|---|---|
| TTL 串口排针 | `VDD \| GND \| RX \| TX` | 向网关或板上控制器提供串行数据/控制接口 | TTL 电平（如 3.3 V/5 V）、RX/TX 方向、VDD 是否供电、是否与麒麟电脑相连 |
| 上位机/PC/USB HOST 侧 | `VIN/红色`、`D−/白色`、`D+/绿色`、`GND/黑色`、`屏蔽层` | 连接麒麟系统电脑或 USB HOST | HOST 端角色、VIN 电压/电流方向、D+/D− 连通关系、屏蔽层接地方式、系统是否生成 TTY |
| USB 设备/USB 耳机/USB DEVICE 侧 | `屏蔽层`、`GND/黑色`、`D−/绿色`、`D+/白色`、`VBUS/红色` | 连接耳机 USB DEVICE | DEVICE 端角色、VBUS 供电方向和限流、D+/D− 连通关系、插拔和枚举行为 |

图中 HOST 侧与 DEVICE 侧的 D+/D− 颜色标注不同，不能据此推断信号是否交叉或直连；`VIN`、`VBUS` 和 TTL `VDD` 也不能默认等电位。接线确认前禁止给耳机或转换板反向供电，禁止把 TTL `RX/TX` 直接接到 USB D+/D−，也禁止把 5 V 信号接入未经确认的 3.3 V TTL 输入。

## 2. 产品目标

### 2.1 目标

- 允许部署人员通过本地配置明确选择 `bluetooth`、`serial` 或 `usb`。
- 支持在多个 USB 串口中按稳定顺序探测，并以首个完整握手自动发现目标设备。
- 保证三种传输在业务层呈现一致的设备连接、数据接收、错误和停止语义。
- 保留设备原始字节、接收时间戳和采集会话关联，不因传输适配而改写原始数据。
- 保持现有算法、录制、录播和北向 WebSocket 行为稳定。
- 默认提供本机回环网页和 WebSocket，不依赖专用网线；同时保留可配置的旧有线 B 端策略。
- 设备或所选传输不可用时，网关主服务继续运行；可视化前端请求数据时按现有规则使用录播。
- 为后续设备协议 POC、驱动验证、现场部署和故障定位提供清晰的验收边界。

### 2.2 非目标

- 本期不支持同时连接多个头环。
- 本期不支持蓝牙、串口、USB 并行采集、合流或去重。
- 本期不允许 B 端通过 WebSocket 选择或切换设备传输。
- 本期不做传输间自动故障转移，例如蓝牙失败后自动切到 USB。
- 本期不改变 B 端北向报文版本、请求动作、数据字段或录播规则。
- 本期不自行补充协议未给出的采样率、独立校验算法或数值缩放；已确认的固定帧、单字节启停命令和原始算法输入映射按本文执行，原生 USB 仍不作假设。
- 本期不把 USB 蓝牙适配器视为“USB 数据源”；它仍属于蓝牙传输的硬件实现。
- 本期不通过遍历波特率、校验位等参数猜测串口配置；串口参数必须由设备协议明确给出。
- 本期不把握手帧当作身份认证或安全凭据；它只用于识别协议兼容的目标设备。
- 本期不把设备接入策略与前端访问策略组合成大量业务分支；二者必须通过独立策略接口组合。
- 本期不使用 HTTP 轮询、SSE、WebTransport、WebRTC、Web Serial 或 WebUSB 替换现有 WebSocket 业务契约。

## 3. 名词与边界

| 名词 | 定义 | 判定示例 |
|---|---|---|
| 蓝牙数据源 | 网关经 BLE GATT 与头环通信 | 板载蓝牙或 USB 蓝牙适配器 + BlueZ/Bleak |
| 串口数据源 | 操作系统将设备暴露为串行字符设备 | `/dev/ttyS*`、`/dev/ttyUSB*`、`/dev/ttyACM*` |
| 原生 USB 数据源 | 网关直接访问 USB 接口或端点，不经 TTY | HID、Bulk、Interrupt；具体类型待设备协议确认 |
| 传输适配器 | 封装一种设备连接方式，并向网关核心提供统一生命周期和原始包回调 | BLE、Serial、USB Adapter |
| 设备协议 | 规定原始字节的分帧、字段、字节序、校验和启停命令 | BLE 已确认部分以 Flowtime 协议为准；串口固定握手、参数、帧结构、大端序列号、单字节启停和算法原始输入映射已确认；原生 USB 待确认 |
| 候选串口 | 由 USB 设备派生、允许网关进行握手探测的 TTY | `/dev/serial/by-id/*`、`/dev/ttyACM*`、`/dev/ttyUSB*` |
| 握手识别 | 网关逐个只读候选串口，完整匹配固定 7 字节内容；首个匹配即为目标并停止遍历 | 设备名义周期为 200 ms；不校验周期精度，探测超时默认 1000 ms 并允许配置 |
| 录播 | 从已保存的原始数据和算法结果回放 | 不属于第四种物理数据源，也不参与互斥配置 |

串口与原生 USB 的分类以操作系统接口为准。即使物理线缆使用 USB，只要设备在 Linux 上呈现为 `/dev/tty*`，产品配置仍选择 `serial`。

USB/udev 的 VID、PID、序列号、驱动和物理路径在现场识别后可用于缩小候选范围；当前未知时按稳定排序枚举 USB 派生 TTY，完整匹配应用层握手的第一个串口就是目标。不得只凭易变化的 `/dev/ttyUSB0`、`/dev/ttyACM0` 等编号认定设备，也不得在已选中目标后继续遍历。

## 4. 用户与使用场景

### 4.1 部署人员

部署人员根据现场设备和驱动条件选择唯一传输方式，填写该传输所需参数，安装服务并完成设备读写权限配置。

### 4.2 运维人员

运维人员通过服务状态和日志确认当前选择的传输、连接状态、最近数据时间范围以及错误原因，不需要读取敏感原始数据。

### 4.3 本机可视化前端与兼容 B 端

默认由同一台麒麟主机上的浏览器连接网关回环 WebSocket；兼容模式允许独立 B 端经专用有线网络连接。两者都不感知设备使用蓝牙、串口还是 USB，继续使用 `getStatus`、`getLatest`、`subscribe` 和 `unsubscribe`。

### 4.4 开发与测试人员

开发和测试人员可以为不同传输注入模拟设备数据，验证相同原始包经算法、录制和北向链路产生兼容结果。

## 5. 核心产品规则

### 5.1 单选规则

- 部署配置必须使用一个枚举字段选择传输类型，不使用三个可独立开启的布尔开关。
- 合法值只有 `bluetooth`、`serial`、`usb`。
- 一次进程只创建所选传输的适配器，不初始化、探测或占用其他传输资源。
- 未选择、选择未知值或所选传输缺少必需参数时，配置校验必须明确失败并给出可操作的错误原因。
- 传输切换属于部署配置变更，需由运维人员修改本地配置并重启服务后生效。
- B 端请求、网页操作或设备异常都不得触发传输切换。

### 5.2 不自动跨传输降级

所选传输连接失败、设备拔出或数据非法时，网关只重试当前传输。不得扫描或连接其他传输上的设备，也不得把另一个已接入设备当作替代数据源。

当所选设备不在线时：

- 网关北向服务继续监听；
- `getStatus` 返回现有设备离线/异常状态语义；
- B 端发起 `getLatest` 或 `subscribe` 时，网关按现有规则自动使用录播；
- 设备恢复并完成初始化后，网关停止录播并恢复实时模式；
- 旧的 B 端订阅与重连规则保持现有协议定义。

### 5.3 原始数据原则

- 适配器必须保存设备协议定义的全部原始字节，不得只保存解析后的数值。
- 网关接收时间戳由数据进入适配器后的统一边界产生，使用毫秒时间戳。
- 分帧、校验和控制字节属于设备协议层；适配器不得为迁就旧 SDK 示例而自行重编码。
- 算法输入必须保留已确认的字节序和完整分组。
- 串口和 USB 数据在真实录制数据完成比对前，不得假定与 BLE 通知具有相同分帧边界。

### 5.4 前端访问策略

- 配置使用单一枚举 `access.mode`，当前合法值为 `local_browser` 和 `wired_b_side`；
- 默认 `local_browser`：HTTP 页面、WebSocket 和可选下载均只监听 `127.0.0.1`，不配置专用网卡或 DHCP；
- 本机网页必须由回环 HTTP 服务加载，WebSocket 校验固定页面 Origin，不以生产方式使用 `file://`；
- 兼容 `wired_b_side`：关闭本机网页服务，WebSocket/下载绑定批准的非回环私有地址，并沿用隔离专网规则；
- 两种策略共享同一个 Gateway、请求处理器、消息结构、录播和订阅实现；策略只负责配置校验、监听暴露、Origin 策略和网页服务；
- 切换访问策略需要修改配置并重启服务，不允许运行时由网页切换；
- 兼容旧配置：没有 `access.mode` 时，回环 `server.host` 推断为 `local_browser`，非回环私网地址推断为 `wired_b_side`；保存或升级配置时应补写显式模式；
- 新增未来策略时实现统一策略接口并注册，不得在业务、算法或设备适配器中增加拓扑判断。

### 6.2 统一适配器生命周期

三种适配器必须向网关核心提供等价的生命周期语义：

| 能力 | 产品要求 |
|---|---|
| 启动 | 打开所选传输，寻找或等待目标设备 |
| 连接中 | 报告 `connecting`，但不提前声明实时数据可用 |
| 初始化 | 完成必要订阅、端点声明、参数设置和采集启动命令 |
| 就绪 | 算法会话初始化成功后才能报告 `connected` |
| 数据 | 输出设备协议通道、未改写的原始字节和接收时间 |
| 异常 | 报告可观察错误，释放不完整连接，再按配置重试当前传输 |
| 停止 | 尽力发送设备停止采集命令，并关闭连接、端口或 USB 句柄 |

| 编号 | 需求 | 优先级 |
|---|---|---|
| SER-001 | 支持 `auto` 发现模式，从 `/dev/serial/by-id/` 及 USB 派生的 `/dev/ttyACM*`、`/dev/ttyUSB*` 中枚举候选串口 | P0 |
| SER-002 | 首期串口参数使用协议确认的 115200、8-N-1、无流控，不遍历尝试其他串口参数 | P0 |
| SER-003 | 串口打开失败、权限不足、设备消失、读超时和帧校验失败须转换为可观察状态 | P0 |
| SER-004 | 设备拔出后关闭失效句柄，并按配置间隔重新枚举同一串口传输下的候选设备 | P0 |
| SER-005 | 连续字节流必须使用已确认的分帧和校验规则处理半包、粘包和损坏帧 | P0 |
| SER-006 | 必须限制接收缓冲区和最大帧长，非法流量不得导致内存无限增长或主进程退出 | P0 |
| SER-007 | 识别阶段只允许读取和校验握手；握手未通过前不得发送订阅、停止或其他设备控制指令 | P0 |
| SER-008 | 不得探测主板控制台、调试串口、蓝牙串口或其他非 USB 派生的系统 TTY | P0 |
| SER-009 | 候选串口按 `/dev/serial/by-id/`、USB 物理路径和接口号形成稳定顺序后逐个探测；不得并行探测，也不得在找到目标后继续打开其他端口 | P0 |
| SER-010 | 首个返回完整固定握手帧的候选就是目标：立即 ACK、保留该端口并停止遍历；一轮没有目标则保持离线并等待重试。本期部署前提为只连接一台目标耳机 | P0 |
| SER-011 | 选中目标后记录其 `/dev/serial/by-id/`、VID/PID、USB 序列号、父设备、接口号、驱动和物理路径（系统实际提供哪些就记录哪些），用于诊断和后续缩小范围；重新连接仍须校验握手 | P0 |
| SER-012 | 打开串口时的 DTR、RTS、HUP 和流控行为必须由设备方确认，避免候选探测导致设备复位或误动作 | P0 |
| SER-013 | 目标握手通过后立即返回同值握手 ACK；算法会话就绪后发送一次单字节 `0xE1` 使能脑电。在配置超时内收到任意非空响应即成功，不校验响应内容；超时即本次启动失败，关闭端口并进入当前串口策略的重连流程。首个完整有效数据帧作为采集真正产生数据的附加证据 | P0 |
| SER-014 | 停止服务、设备仍在线或协议要求停止采集时，发送一次单字节 `0xE0` 并等待配置超时内的任意非空响应；收到即成功，超时或读写异常记录失败后仍关闭串口，不阻塞服务退出 | P1 |
| SER-015 | 握手阶段必须识别完整的 7 字节 `AA 55 01 01 01 01 6F`，不得用部分前缀或单个字节认定目标 | P0 |
| SER-016 | 设备名义上每 200 ms 发送握手；网关不校验相邻握手的精确周期。单候选默认探测 1000 ms（覆盖 5 个名义周期），允许配置；目的是容忍 USB、驱动和系统调度抖动，避免超时过短造成假离线 | P0 |
| SER-017 | 2 字节序列号按无符号大端解析；首帧只建立基线，后续期望值为 `(last + 1) mod 65536`，即 `0xFFFF → 0x0000`。不连续时记录期望值、实际值和异常计数，但不得因此退出主进程 | P0 |
| SER-018 | 完整 28 字节串口帧必须原样持久化；算法兼容层提取偏移 4～23 的 20 字节作为现有 EEG 原始输入，提取偏移 24 的 1 字节作为现有心率原始输入，不重采样、不缩放、不改变字节序 | P0 |
| SER-019 | 按 16 位大端序列号的扩展序列计算累计和区间丢包：`expectedPackets = extendedHighestSequence - baseSequence + 1`，`lostPackets = max(0, expectedPackets - receivedUniquePackets)`，`lossRatePercent = lostPackets / expectedPackets × 100%`。重复包不增加唯一接收数，有限窗口内乱序补包可降低累计丢包数，支持 `0xFFFF → 0x0000` 回绕 | P0 |
| SER-020 | 控制响应日志只记录命令名、响应字节数、耗时和成功状态，不记录响应原文。发现阶段必须记录 by-id、`ttyACM*`、`ttyUSB*` 节点数量和固定路径是否存在；必须区分“串口打开后无任何握手字节”与“收到字节但没有完整固定握手”，后者只记录读取/字节/丢弃/截断计数、最长握手前缀匹配长度和耗时，不记录串口原文。数据阶段须区分非法长度、非法包尾、重同步丢弃、缓冲溢出和有效帧超时；非法输入日志限频，但累计计数不丢失。周期、断开和重连汇总必须包含连接阶段/原因、字节/帧/缓冲计数、累计/区间期望包、唯一接收包、丢包数、丢包率、重复、乱序、迟到和控制超时，便于无 Codex 现场定位 | P0 |

#### 6.4.1 首期串口发现与订阅流程

```text
耳机通过 USB 接入麒麟系统电脑
  → 操作系统加载 CDC ACM 或 USB-Serial 驱动并生成一个或多个 TTY
  → 网关按稳定顺序生成 USB 派生候选串口列表
  → 使用固定 115200 8-N-1 参数逐个打开候选端口
  → 当前候选在 1000 ms 默认窗口内未出现完整握手：关闭并探测下一个
  → 首次读取到完整固定握手：立即返回同值 ACK，保留该端口并停止遍历
  → 一轮全部候选均未握手：保持离线并等待下一轮重试
  → 设备停止每 200 ms 重复握手
  → 初始化新的算法会话
  → 通过目标串口直接发送单字节 0xE1 使能脑电
  → 配置超时内收到任意非空响应即判定命令成功；超时则关闭并重连
  → 以首个完整有效的 28 字节数据帧确认采集已实际产生数据
  → 接收脑波和心率原始数据
  → 原样保存 28 字节帧，提取现有算法所需 EEG 20 字节和 HR 1 字节
  → 通过既定北向协议向软件或网页分发
```

候选串口必须串行探测并在首个完整握手处短路停止。这样符合“现场只连接一台目标耳机”的部署约束，也避免先 ACK 多个端口后无法确定使用哪一个。应限制候选数量、单端口超时、单轮时长、读取缓冲区和日志频率；当前目标处于正常 `connected` 状态时不得继续扫描或切换到其他串口。

#### 6.4.2 已确认的握手与控制指令

| 项目 | 已确认定义 | 仍需确认 |
|---|---|---|
| 握手发送条件 | 设备上电后、尚未收到有效 ACK | 串口重开、电脑重启或异常恢复时是否自动回到握手状态 |
| 握手周期 | 名义上每 200 ms 一次；网关不验证周期精度，默认每个候选等待 1000 ms | 只需在目标麒麟机实测 1000 ms 是否足够，不要求设备方给出周期误差范围 |
| 握手帧 | 固定内容 `AA 55 01 01 01 01 6F`，共 7 字节；不解析各字节含义，也不把 `0x6F` 单独当作校验值 | 无 |
| 上位机 ACK | 与握手帧完全相同；收到完整握手后立即发送 | ACK 丢失后的设备重发与恢复行为在拔插 POC 中观察 |
| ACK 后行为 | 设备停止重复握手 | ACK 后等待 `0xE1` 的超时和恢复规则 |
| 开启脑电 | 直接发送单字节 `0xE1`；配置超时内收到任意非空响应即成功，不解析响应格式或内容 | 响应成功后仍以首个有效数据帧确认实际出数；超时关闭端口并按配置重连 |
| 关闭脑电 | 直接发送单字节 `0xE0`；配置超时内收到任意非空响应即成功，不解析响应格式或内容 | 超时或设备已拔出时记录失败并关闭本地资源，不阻塞服务退出 |

收到完整的 7 字节握手帧后，网关必须立即向该串口回复同值 ACK；ACK 不等待算法初始化。该串口立即成为本轮目标，遍历结束，未打开的候选不再探测。部署和验收必须保证电脑只连接一台目标耳机；如果违反此前提而连接多个相同设备，网关只会选择稳定排序中第一个成功握手的串口，不提供多设备消歧保证。

“握手周期误差”不再作为协议验收字段。它原本只用于估算上位机至少要等多久：如果设备名义每 200 ms 发一次，而网关只等 200 ms，USB 传输、驱动缓冲和系统调度的少量延迟就可能让窗口内一帧都收不到，产生假离线。默认 1000 ms 覆盖 5 个名义周期；现场只需要验证该超时不会漏掉正常设备，也不会让多串口发现耗时不可接受。

#### 6.4.3 已确认的数据帧结构

协议给出的数据帧总长为 28 字节（`0x1C`）：

| 偏移 | 长度 | 字段 | 已确认值/含义 | 仍需确认 |
|---:|---:|---|---|---|
| 0 | 3 | 包头 | `AA AA AA` | 无 |
| 3 | 1 | 包长字段 | `0x1C`，按包长 28 处理 | 暂不追究原文“校验位(包长)”中的其他含义，不实现额外 CRC/checksum |
| 4 | 2 | 序列号 | 无符号大端；首帧为基线，之后逐帧 `+1`，`0xFFFF` 后为 `0x0000` | 跳号、重复或乱序只先记录异常；具体归因在真实链路 POC 中确认 |
| 6 | 3 | 脑电左 1 | 第 1 个左通道样本 | 大小端、有符号性、单位、量程和缩放 |
| 9 | 3 | 脑电右 1 | 第 1 个右通道样本 | 同上 |
| 12 | 3 | 脑电左 2 | 第 2 个左通道样本 | 同上 |
| 15 | 3 | 脑电右 2 | 第 2 个右通道样本 | 同上 |
| 18 | 3 | 脑电左 3 | 第 3 个左通道样本 | 同上 |
| 21 | 3 | 脑电右 3 | 第 3 个右通道样本 | 同上 |
| 24 | 1 | 心率 | 示例 `0x5A` | 单位、范围、无效值和刷新语义 |
| 25 | 3 | 包尾 | `BB BB BB` | 无 |

当前先不处理独立 CRC 或 checksum。实现只校验固定包头、`0x1C` 包长和固定包尾，不得把某个业务字段当作 CRC，也不得自行增加或改写设备帧。

算法兼容不要求把六个 24 位值先转换成新的数值协议。串口适配器将偏移 4～23（2 字节大端序列号 + 6 × 3 字节脑电）作为现有 20 字节 EEG 原始输入，将偏移 24 的 1 字节作为现有 HR 原始输入，从而替代原 BLE `FF31`/`FF51` 数据来源。完整 28 字节串口帧仍须另行原样保存；上线前使用同一时段真实数据确认算法分组、结果和性能与当前 BLE 路径兼容。

一次串口 `read()` 返回的数据不等于一个完整协议帧。实现必须维护有界滚动缓冲，按“查找帧头 → 读取长度 → 等待完整帧 → 校验 → 分发”的顺序解析，并能从损坏字节中重新同步。

#### 6.4.4 丢包率与日志口径

丢包率采用 RTP/实时流常用的扩展序列统计思路。每次连接以首个有效 16 位序列号为 `baseSequence`，将回绕后的序列扩展到单调空间，并按下式计算：

```text
expectedPackets = extendedHighestSequence - baseSequence + 1
lostPackets = max(0, expectedPackets - receivedUniquePackets)
lossRatePercent = lostPackets / expectedPackets × 100%
```

`receivedUniquePackets` 只统计唯一序列号；重复包单独计入 `duplicates`，不改善丢包率。有限窗口内后到的乱序包计入 `outOfOrder` 并补回此前缺口，因此累计 `lostPackets` 可下降；超过窗口的旧包计入 `late`。`0xFFFF → 0x0000` 视为正常回绕。周期日志以相邻快照差值给出 `intervalExpectedPackets`、`intervalReceivedUniquePackets`、`intervalLostPackets` 和 `intervalLossRatePercent`，同时保留连接累计值，避免只看瞬时跳号或只看全程平均值造成误判。

日志不得记录控制响应原文、完整 28 字节帧或算法输入。控制命令只记录 `command`、`responseBytes`、`durationMs`、`success`；串口汇总记录目标路径、运行时长、帧/字节数、非法帧、丢弃/溢出、首末序列、累计与区间丢包、重复/乱序/迟到、控制响应次数/字节数/超时次数。持续收到垃圾字节但没有有效帧时仍必须按有效帧超时断开重连，不能把“有字节”误判为链路健康。

## 7. 状态与异常处理

### 7.1 期望状态流

```text
服务启动
  → 校验唯一数据源配置
  → 创建所选适配器
  → connecting
  → 设备连接及协议初始化
  → 算法会话初始化
  → connected / live
  → 断开或错误
  → disconnected
  → 释放资源
  → 等待配置的重试间隔
  → 仅重试当前所选适配器
```

### 7.2 错误分类

| 类别 | 示例 | 期望行为 |
|---|---|---|
| 配置错误 | 未选择传输、未知类型、缺少所选传输必需参数 | 拒绝以错误配置启动，指出具体字段 |
| 设备不存在 | BLE 未发现、串口路径不存在、USB 未枚举 | 北向服务保持可用，记录状态并重试当前传输 |
| 单设备部署前提被违反 | 同时连接多个可返回相同固定握手的目标设备 | 本期不做消歧，只选择稳定排序中首个握手目标；部署、验收和运维检查必须保证只连接一台目标耳机 |
| 权限错误 | TTY 或 USB 接口无权限 | 记录设备路径/VID/PID 等非敏感定位信息和修复提示，不无限高频重试 |
| 连接中断 | BLE 断连、串口拔出、USB reset/disconnect | 关闭失效资源，状态变为离线，按配置重连 |
| 非法数据 | 包头/包长/包尾错误、帧不完整、未知通道 | 丢弃或隔离当前非法帧，计数并限频记录，不退出主进程 |
| 数据积压 | 串口/USB 接收速度超过处理能力 | 使用有界缓冲和可观察丢弃策略；具体上限待性能 POC 确认 |
| 算法异常 | 初始化或计算失败 | 标记结果无效并记录原因，保留原始数据，主服务继续运行 |

## 8. 非功能需求

### 8.1 可靠性

- 任一设备侧异常不得中断 WebSocket 监听、录播或其他网关管理能力。
- 设备重连、服务重启和系统重启后，只恢复配置指定的传输。
- 适配器必须幂等停止，避免重复关闭导致主进程异常。
- 所有读取缓冲区、待处理队列和重试频率必须有上限并可配置。

### 8.2 性能

- 新增传输抽象不得改变现有每 600 ms 的北向连续数据分组语义。
- 串口和 USB 的接收吞吐必须覆盖设备协议确认的峰值数据率，并保留安全余量。
- 端到端延迟、CPU、内存和丢包率须在重装麒麟后的 N100/N150 目标电脑上实测。重装前 Ubuntu 结果仅用于差异对照；如需继续执行 Ubuntu 回归，必须使用可恢复镜像或另一台同规格主机，且结论单独记录。

### 8.3 安全与权限

- 服务仅获得所选设备所需的最小访问权限。
- 不允许使用全局可写的 TTY/USB 权限作为交付方案。
- 日志不得记录完整敏感原始数据、受试者隐私数据或凭据。
- USB/串口设备标识不得被误当作北向鉴权凭据。

### 8.4 可观测性

日志和内部指标至少包括：

- UTC 毫秒时间、网关应用版本、进程 PID、目标系统/内核/架构、配置文件 SHA-256 和当前选择的传输类型；不得记录配置内容或凭据；
- 连接状态变化及时间；
- 非敏感设备匹配信息；
- 候选串口数量和稳定顺序，by-id、`ttyACM*`、`ttyUSB*` 实际节点数量，配置路径是否存在，逐个握手超时、首个成功目标、ACK 及停止遍历结果；
- 串口已打开但无握手字节，或已收到字节但握手不匹配；错误握手只记录计数、最长固定前缀匹配长度和耗时，不记录原始内容；
- 最近收到有效数据的时间范围、EEG/HR 包数与字节数、异常长度、窗口数及无效窗口数；
- 扫描/连接/握手/控制/数据流阶段、轮次、耗时、重连次数和原因，非法长度/包尾帧数、重同步丢弃字节数、缓冲溢出计数、有效帧超时时的已读字节和待解析字节；
- 算法会话初始化、进程、单窗口耗时、输出字段名及异常状态，不记录算法输入或结果值；
- WebSocket 客户端数、请求 action/requestId、订阅、录播、下载来源/大小、中断和进程退出原因。

目标麒麟系统必须提供无需 Codex、无需联网的一键诊断包导出命令。诊断包至少覆盖系统/内核、N100/N150 硬件、依赖和二进制校验、systemd 状态与当前/上次启动 journal、应用及轮转日志、USB/TTY/驱动、网络监听、资源与采集警告；同时满足以下约束：

USB 串口识别必须提供无需拔插的一键命令：耳机保持连接，命令立即遍历当前 `ttyACM*`、`ttyUSB*` 和 by-id 路径，同时保存 `lsusb`、`lsusb -t`、sysfs USB 身份、接口驱动、TTY/udev 属性、内核及网关日志。发现 TTY 只判定为候选，目标身份仍由网关遍历候选并读取固定握手确认；未发现 TTY 时明确返回当前状态失败并保留日志目录、`tar.gz` 及 SHA-256。另保留显式 `--plug-cycle` 故障诊断：仅在需要分析物理枚举时，由操作员先拔出记录基线，再在可配置的 5～600 秒窗口内插入，持续保存前后设备差分、内核 journal、`dmesg --follow`、`udevadm monitor` 及网关 journal，区分“生成新 TTY”、“已检测新 USB 但 TTY 超时”和“USB 枚举超时”。两种模式均不得打开串口或采集任何载荷。

- 不收集配置文件内容、环境变量、密码、Token、私钥、录播目录、完整原始 EEG/HR 或算法载荷；
- 普通文本执行凭据模式脱敏，并明确提示压缩旧日志仍需人工复核；
- 输出归现场执行用户所有、权限为 `0600`，同时生成 SHA-256 校验文件且不得覆盖旧诊断包；
- 支持复制到受控 U 盘或经批准的 SSH/SCP 通道；现有 HTTP 日志 ZIP 只作为应用文件日志的轻量导出，不能替代完整系统诊断包；
- 验收时必须在目标 N100/N150 银河麒麟 V10 实机复现一次诊断包生成、校验、解包和导出流程。

### 9.2 串口专项验收

- 覆盖正常分帧、半包、粘包、损坏帧、读超时和连续高吞吐。
- 覆盖设备启动前不存在、运行中拔出、重新插入后设备路径保持或变化的场景。
- 覆盖权限不足、端口被占用和串口参数错误。
- 构造多个 USB 串口，验证系统只探测候选 USB TTY，不打开控制台或其他非候选串口。
- 验证候选列表中前若干端口无握手、后续一个端口有握手时能够选中目标；一轮全部无握手时保持离线并重试。
- 验证同一 USB 复合设备包含多个串口时，网关能按父设备与接口号分组并从握手端口识别目标。
- 验证重新插拔导致 `/dev/ttyUSB*` 或 `/dev/ttyACM*` 编号变化后仍可重新发现目标。
- 验证收到完整握手前不发送 `0xE1`、`0xE0` 或订阅指令；首个握手后立即返回同值 ACK 并停止继续遍历，候选探测不会因 DTR/RTS 行为使设备异常复位。
- 按接线图逐项核对 HOST、DEVICE/耳机和 TTL 三组接口，验证电源方向、TTL 电平、RX/TX 方向、D+/D− 连通关系和屏蔽层处理。
- 验证麒麟电脑实际读取路径：USB HOST 侧、TTL 串口侧或转换板的其他 TTY 接口；记录对应稳定设备节点。
- 验证错误接线或反向供电不会损坏耳机、转换板或麒麟电脑，并在文档中保留现场照片和测试结论。
- 验证设备名义上每 200 ms 重复发送 `AA 55 01 01 01 01 6F`；不以周期间隔偏差拒绝设备，默认 1000 ms 单候选超时在目标麒麟机上不会产生假离线。
- 验证算法会话就绪后发送一次单字节 `0xE1`，配置超时内任意非空响应均成功，响应内容不解析且不写日志；超时进入重连。响应成功后以首个完整有效数据帧确认实际出数。停止时发送一次 `0xE0` 并按相同口径等待响应，超时仍能完成资源关闭。
- 验证 28 字节数据帧的 `AA AA AA` 包头、`0x1C` 包长、2 字节大端序列号、6 个 3 字节脑电值、1 字节心率和 `BB BB BB` 包尾；覆盖连续递增、跳号和 `0xFFFF → 0x0000` 回绕。
- 构造跳号、重复、有限窗口乱序补包、迟到包和回绕，核对累计/区间 `expectedPackets`、`receivedUniquePackets`、`lostPackets`、`lossRatePercent` 与公式一致；验证持续垃圾字节仍触发有效帧超时。
- 使用真实录制数据核对字节序、帧边界、时间戳，以及偏移 4～23 的 EEG 20 字节和偏移 24 的 HR 1 字节能兼容当前算法输入分组与结果。

### 9.3 原生 USB 专项验收

- 覆盖同 VID/PID 多设备时的唯一匹配策略。
- 覆盖接口声明失败、端点错误、短读、超时、USB reset、拔出和重新枚举。
- 验证 udev 权限仅作用于目标设备。
- 使用 USB 抓取与网关保存数据核对原始字节和包边界。

## 11. 风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 串口/USB 协议与 BLE 数据格式不同 | 复用旧解析器可能产生静默错误 | 以正式设备协议和逐字节真实数据比对为准 |
| USB CDC 被误配置为原生 USB | 重复实现或无法打开设备 | 按 Linux 是否呈现 `/dev/tty*` 明确分类 |
| 现场同时连接多台同协议设备 | 固定握手不含唯一身份，网关会选中稳定排序中第一个握手端口 | 本期明确只允许连接一台目标耳机；若未来支持多设备，必须新增可验证唯一身份并升级发现策略 |
| 无差别遍历系统串口 | 干扰控制台、调试设备或其他业务外设 | 只枚举 USB 派生候选 TTY，并允许配置 VID/PID 等候选范围 |
| 候选串口数量较多 | 逐个等待超时会拉长离线发现时间 | 只枚举 USB 派生 TTY，现场识别 VID/PID/父设备/接口后缩小范围；首个握手即停止遍历 |
| 打开候选串口触发 DTR/RTS | 设备复位或进入非预期模式 | 由设备方确认控制线行为，探测阶段禁止发送控制指令 |
| `0xE1`/`0xE0` 响应无结构定义 | 任意响应只能证明设备有回包，不能区分具体状态、错误码或固件含义 | 配置超时内任意非空响应只作为命令成功判据，日志仅记录长度/耗时/成功状态；`0xE1` 仍以首个有效帧确认实际出数，真实响应语义后续由设备方补充 |
| 数据帧未定义独立校验 | 传输损坏可能只靠帧头、长度和包尾发现 | 不自行发明 CRC；记录非法帧并推动设备方明确校验能力 |
| 串口数据与现有 BLE 算法输入不完全等价 | 即使长度一致，也可能因固件字段语义不同造成算法结果偏差 | 不自行转换 24 位数值；按原始字节切片映射，使用真实数据逐字节和算法结果回归后才进入生产 |
| Linux 设备节点重枚举 | 固定路径失效 | 使用稳定 udev 标识或经确认的唯一设备属性 |
| 权限配置过宽 | 增加本机设备访问风险 | 使用最小 udev 规则和专用服务用户 |
| 热插拔导致句柄或任务泄漏 | 长时间运行不稳定 | 统一生命周期、幂等清理和压力测试 |
| 适配器抽象泄漏传输细节 | 业务层出现分支扩散 | 固定统一事件契约并进行模拟适配器测试 |
| 未经确认直接重采样或重编码 | 算法结果不可信 | 原始字节持久化，真实数据回归前禁止转换 |
| 在 N100/N150 上误用 ARM64 或 LoongArch64 镜像 | 安装介质无法启动，且对应架构的二进制、驱动和验收结果均不可用 | 仅允许使用已核验 SHA-256 的 x86_64 镜像；安装前复核完整文件名和架构标识 |
| 复用其他电脑或其他银河麒麟 V10 构建的验收结果 | N100/N150 专属的内核驱动、USB 拓扑、性能或依赖问题被遗漏 | 验收记录绑定目标主机硬件清单、镜像、内核和依赖版本；更换任一项后执行受影响范围回归 |
| 覆盖安装麒麟前未备份 Ubuntu 环境 | 配置、录制数据、日志和差异对照基线丢失，安装失败时无法快速回退 | 安装前完成数据备份、环境清单、恢复介质和恢复演练，敏感原始数据按项目安全要求转移 |
| 将 Ubuntu 回归结果等同于麒麟验收 | 依赖、驱动、权限、性能或部署问题在现场暴露，造成交付误判 | 执行本文“运行环境差异风险”门禁，在目标麒麟硬件上独立完成 POC 与验收 |

## 12. 确认结论与剩余现场项

本轮已确认以下产品结论：

1. N100/N150 最终安装镜像确定为 `Kylin-Desktop-V10-SP1-2503-HWE-PP-Release-20250430-X86_64.iso`，当前下载文件 SHA-256 为 `d858e3ac19aa317ab1d2133a6aacbe978662ce9dcc10437119841627a416cc66`。安装后运行 `sudo ./linux/collect-kylin-runtime-diagnostics.sh`，诊断包会采集 `/etc/os-release`、银河麒麟版本文件（存在时，其中 `.kyinfo` 只提取非敏感版本/构建字段）、`hostnamectl`、`uname -a` 和 `uname -m`，由此记录系统构建信息、内核和 x86_64 架构；也可手工执行这些命令交叉核对。
2. 电脑侧具体读取 USB HOST TTY、TTL 侧 TTY 还是转换板其他接口仍未知；安装后用 `lsusb`、`lsusb -t`、`udevadm`、内核日志及 `/dev/serial/by-id/`、`/dev/ttyACM*`、`/dev/ttyUSB*` 现场识别。
3. TTY 类型、CDC ACM/USB-Serial 芯片和驱动仍未知；这不阻止先安装系统，但是真机串口 POC 和 udev 权限规则的前置条件，不能在未识别时写死设备节点或驱动。
4. VID、PID、USB 序列号、父设备和多串口接口号仍未知；首期发现不依赖这些值，按稳定顺序逐个探测 USB 派生 TTY，以首个完整握手为目标。现场采集到这些属性后应记录并用于缩小候选范围和故障定位。
5. `VDD`、`VIN`、`VBUS`、TTL 电平及 `RX/TX` 方向与软件协议无直接关系，但与硬件安全和链路稳定性有关：错误电压或反向供电可能损坏耳机、转换板或电脑，3.3 V/5 V TTL 不匹配会导致损坏或乱码，RX/TX 方向错误会完全收不到数据。如果现场只使用厂家完成的 USB 接口和线缆、完全不接 TTL 排针，可将 TTL `VDD/RX/TX` 标记为“不适用”，但仍需确认 USB 供电不会反灌。
6. D+/D−、屏蔽层、接口线序和限流同样不改变应用层代码，但决定 USB 能否枚举、是否会频繁掉线以及抗干扰/ESD 表现。标准 USB 通常是 D+ 对 D+、D− 对 D−，不能仅因图中颜色不同就自行交叉；若使用厂家成品转换板和成品线缆，项目软件人员无需自行设计线序，但应由设备方确认接法并在最终物理端口完成枚举、持续采集和反复插拔测试。
7. 握手内容固定为 `AA 55 01 01 01 01 6F`，各字节没有需要网关解释的业务含义，`0x6F` 不单独作为校验字段；只做完整 7 字节相等匹配。设备名义上每 200 ms 发送一次，网关不验证周期精度。“周期误差”仅影响探测超时：等待太短可能因 USB/驱动/调度延迟漏帧并误报设备离线，因此默认每个候选等待 1000 ms 并允许配置。
8. 本期不会同时连接多个握手设备。候选串口串行遍历，收到第一个完整握手后立即 ACK、选中该端口并停止遍历；不再要求遍历全部候选或设计多设备唯一字段。
9. `0xE1`、`0xE0` 都是直接发送的单字节指令，没有外层包头、长度、序号、包尾或校验。两者都会有响应，但当前不定义响应结构：配置超时内收到任意非空响应即成功，超时即失败；日志只记录命令、响应字节数、耗时和成功状态，不记录响应原文。`0xE1` 成功后仍以首个完整有效数据帧证明实际出数；`0xE0` 超时也要关闭端口。
10. 数据帧第 4 字节 `0x1C` 当前只按 28 字节包长处理，不继续追究额外校验语义，也不实现独立 CRC/checksum；仍使用固定包头、包长和包尾做分帧校验并原样保存设备帧。
11. 2 字节序列号为无符号大端。每次连接收到的首个有效序列号作为基线，之后正常情况依次加一，`0xFFFF` 的下一帧为 `0x0000`。累计丢包率按 `max(0, 扩展最高序列跨度内期望包数 - 唯一接收包数) / 期望包数 × 100%` 计算；重复包不增加唯一接收数，有限窗口乱序补包可修正累计丢包，迟到包单独计数。日志同时给出累计与区间统计，不因此退出或改写原始数据；丢包原因通过真实链路 POC 完善。
12. 算法继续兼容现有 BLE 原始输入：从串口帧提取偏移 4～23 的 20 字节（序列号 + 六个 24 位脑电值）替代原 `FF31`，提取偏移 24 的 1 字节心率替代原 `FF51`。不自行重采样、缩放或重编码；采样率、窗口触发和超时继续使用当前算法集成约束，并以真实串口数据回归确认最终兼容性。

因此，当前真正阻塞实机串口适配和 udev 配置的剩余项是第 2～4 项的现场枚举结果，以及第 5～6 项的硬件接线安全确认；它们不再阻塞软件接口设计、模拟器和解析器单元测试。

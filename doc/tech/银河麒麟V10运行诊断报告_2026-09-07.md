# 银河麒麟 V10 网关运行诊断报告（2026-09-07）

## 1. 结论

本次网关未启动的直接原因是 `linux/setup-kylin-autostart.sh` 生成的 systemd 单元在目标机 systemd 245 上校验失败。生成器把项目根目录包在字面双引号内，目标机将其解析为不以 `/` 开头的 `WorkingDirectory` 值，因此报错：

```text
WorkingDirectory= path is not absolute: "/home/.../NeuroBridge"
neurobridge.service: Unit configuration has fatal error
ERROR: Generated systemd unit failed verification; no system file was changed.
```

脚本在写入 `/etc/systemd/system` 前主动停止，所以本次没有出现“服务已安装但启动后崩溃”，而是“服务根本未安装”。诊断时 `neurobridge.service` 为 `not-found/inactive/dead`，本机也没有 NeuroBridge 的 HTTP/WebSocket 监听端口。

当前 USB 串口硬件与驱动不是这次启动失败的原因：系统已枚举 CP2102、创建 `/dev/ttyUSB0` 并绑定 `cp210x`，诊断时也未发现其他进程占用该端口。

## 3. 证据链

### 3.1 一键启动在 systemd 预校验阶段失败

`application-logs/.runtime-logs/setup-kylin-gateway-20260907T021111Z-96986.log` 显示：

1. USB/串口检查成功，找到 CP2102 对应串口候选。
2. 串口运行配置已存在，本地算法已构建并启用。
3. 执行 `setup-kylin-autostart.sh enable` 时，临时单元的 `WorkingDirectory` 被报为非绝对路径。
4. 脚本明确输出 `no system file was changed`，该步骤返回 1。

两次相邻操作（10:10 与 10:11）都以相同错误结束，因此不是偶发性系统状态。

### 3.2 服务确实没有安装和运行

- `service-status.txt`：`Unit neurobridge.service could not be found`。
- `service-properties.txt`：`LoadState=not-found`、`ActiveState=inactive`、`SubState=dead`、`MainPID=0`。
- `service-journal-current-boot.txt` 和 `service-journal-previous-boot.txt`：均无该服务日志。
- `listening-sockets.txt`：未出现预期的 `127.0.0.1:8080`、`127.0.0.1:8765` 或 `127.0.0.1:8766`。
- `coredump-list.txt`：无 NeuroBridge core dump。

这些证据与“写入单元前预校验失败”完全一致。

### 3.3 源码中的触发点

`linux/setup-kylin-autostart.sh` 中：

- `systemd_quote()` 总是把值包装为 `"..."`。
- `quoted_root=$(systemd_quote "$root_dir")` 后直接用于 `WorkingDirectory=$quoted_root`。
- 目标机的 `systemd-analyze verify` 将开头的引号保留在路径值中，遂判定该值不是绝对路径。

`tests/test_deployment.py` 当前只断言脚本文本含有 `WorkingDirectory=$quoted_root`与 `systemd-analyze verify`，并未在 systemd 245 环境中生成单元并执行真实校验。因此这个兼容性问题未被现有测试拦截。

## 4. 串口状态：与当前主故障分开处理

### 4.1 当前快照

- CP2102 USB-UART 已绑定 `cp210x` 驱动。
- `/dev/ttyUSB0` 存在，权限为 `root:dialout` 可读写。
- 稳定的 `/dev/serial/by-id/` 链接已指向 `/dev/ttyUSB0`。
- `lsof /dev/ttyUSB0` 未列出占用进程。

但是因为服务未启动，这份 9 月 7 日的快照没有执行网关级的被动流观察、ACK/`0x01` 验证和连续帧采集，不能用来宣称当前耳机已验收通过。

### 4.2 历史日志证明这条硬件链路曾经成功

`application-logs/.runtime-logs/neurobridge.log` 中 2026-09-04 的进程 `pid=82103` 记录了：

- 串口成功打开；
- 写入固定 7 字节 ACK 后 6 ms 内收到独立 `0x01`；
- 连接状态进入 `validated`；
- 算法 bridge 成功启动并进入 `ready`；
- 末期统计已处理约 29.5 万帧，窗口统计中 `invalidWindows=0`。

同日后一次前台进程 `pid=90086` 虽然可以重复打开串口，但在没有观察到合法流后发送 ACK，每次都未收到独立 `0x01`，最终停留在 `validation_failed/not_connected`。这是一个独立的历史设备交互问题；它不能解释 9 月 7 日的失败，因为当天网关进程根本未被 systemd 启动。

## 5. 修复与验证顺序

### 5.1 已完成的代码修复

1. 新增 `linux/lib/kylin-systemd-unit.sh`，将受管 systemd 单元渲染拆成可独立调用和测试的函数。
2. `WorkingDirectory` 不再包装外层双引号，以原始绝对路径输出，仅将 systemd 说明符 `%` 转义为 `%%`；换行输入会被拒绝。
3. `ExecStart` 继续使用 systemd 命令行支持的引号和转义规则，与 `WorkingDirectory` 的单路径解析分开。
4. `tests/test_deployment.py` 现在会实际使用中文绝对路径渲染完整单元，断言 `WorkingDirectory` 不带引号；运行环境提供 `systemd-analyze` 时还会执行真实 `verify`。
5. 保留现有“校验失败则不写系统目录”的安全门禁。

本地已通过两个 Shell 文件的 `bash -n`、针对性单元测试和全部 174 项自动化测试。当前开发机不是银河麒麟 V10，因此 systemd 245 目标机回归仍是完成修复验收的必要步骤。

### 5.2 目标机回归

修复版部署到原银河麒麟 V10 x86_64 目标机后，按顺序验证：

```bash
./linux/setup-kylin-autostart.sh enable
systemctl is-enabled neurobridge.service
systemctl is-active neurobridge.service
systemctl --no-pager --full status neurobridge.service
ss -lntp
journalctl -u neurobridge.service -n 300 --no-pager -o short-iso-precise
```

通过条件：

1. 单元校验、安装与启动全部成功，`enabled=enabled`且 `active=active`。
2. 仅在 `127.0.0.1` 出现配置中的本机 HTTP/WebSocket 监听端口。
3. 日志先显示串口候选打开，随后为“已观察到合法流”或“ACK 后收到独立 `0x01`”，状态进入 `validated`。
4. 算法进入 `ready`，持续帧统计增长，拔插、服务重启和浏览器断开/恢复场景均通过。

如服务修复后再次出现“ACK 后未收到独立 `0x01`”，再将其作为第二个问题单独排查，重点核对耳机供电/工作状态、转接板连线、当时实际收发字节计数以及协议修订号 181 的固定 ACK 应答行为。

## 6. 非主因告警

诊断包还包含以下系统级告警，但它们没有出现在直接失败链上：

- 其他银河麒麟单元文件的权限或未知键告警；

- `kylin-source-update-timer.service` 处于 failed；

这些项可作为主机运维债务单独处理，不应代替本次 `WorkingDirectory` 兼容性修复。磁盘、inode、内存和交换空间均充足，也不是当前瓶颈。

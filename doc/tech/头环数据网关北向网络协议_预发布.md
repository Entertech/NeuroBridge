## 预发布变更（v0.3）

本节优先于本文其他与录播 `getLatest` 有冲突的描述。以下内容依据当前网关实现及版本变更记录整理；仍须经 B 端联调与现场验收确认。

- 网关在未连接头环时使用一个全局录播进度。显式配置的非空录制会话优先；未指定、无效或为空时，自动选择最新的非空历史会话。
- 首个 `subscribe` 或 `getLatest` 会在对应成功响应发送后启动该全局录播。`getLatest` 不创建订阅，也不会自行发送连续录播事件。
- 录播结果依次为 `1,2,3,4,5,6,7,8`，当前网关已回放出 `4` 后，`getLatest` 必须返回 `4`，不得预读 `5` 至 `8`。尚未回放出算法结果时，它返回所选录制会话的最新有效算法结果；若不存在有效结果，返回 `valid=false` 和空 `payload`。
- 所有订阅加入同一录播进度。慢客户端发送积压或断开时，仅移除该客户端的订阅，不得中断其他订阅者的录播。
- 最后一个 B 端 WebSocket 连接断开时，网关停止录播并清空进度；只要仍有连接，录播文件读到末尾后从首条继续循环。每个循环边界仍发送 `replayEnded`，随后继续发送下一轮数据。
- USB 串口设备发现过程中，已有合法数据流或设备校验成功都会直接进入 `validated`；不再对外经过 `connected`、`validating`，采集使能及后续首帧不改变验证状态。

### 相对 v0.2 的改动

| 项目 | v0.2 → v0.3 预发布 | B 端处理要求 |
| --- | --- | --- |
| 录播会话选择 | v0.2 未规定配置缺失、无效或空会话时的选择规则；v0.3 自动选择最新的非空历史会话 | 不依赖固定录制会话标识；以事件的 `recordingId` 识别本轮录播 |
| 录播进度 | v0.2 未规定多个请求或连接之间的进度关系；v0.3 使用网关级单一进度，后加入订阅者加入当前进度 | 不假定每个订阅均从第一条数据开始 |
| 串口连接状态 | 设备验证成功时直接使用 `validated`，不再使用串口专属的 `connected`、`validating` 中间状态 | 以 `validated` 判断设备验证与实时路径选择；无持续数据时同时参考算法和数据有效性状态 |
| `getLatest` | v0.2 未规定与录播进度的关系；v0.3 已回放时返回当前游标的最后有效结果，未回放时返回所选会话的最新有效结果 | 不预读尚未回放的数据；`valid=false` 时不展示或保存为有效结果 |
| 响应与录播启动顺序 | v0.2 未规定；v0.3 的 `subscribe`、`getLatest` 成功响应先发送，随后启动录播 | 在成功响应后处理可能到达的录播事件 |
| 循环与结束事件 | v0.2 未规定循环；v0.3 每轮末尾发送 `event="replayEnded"`，含 `recordingId`、`endedAtMs` | 将其作为循环边界，不要取消同一订阅 |
| 单客户端发送失败 | v0.2 未规定；v0.3 仅移除失败或积压的订阅，不中断其他订阅 | 单个客户端断开后，其他客户端继续接收数据 |
| 报文兼容性 | 根对象、请求动作、流名称和 `protocolVersion="1.0"` 保持不变 | 无需仅因文档 v0.3 更新而修改基础解析逻辑 |

## 1. 使用范围

本文只定义第三方 B 端主机接入头环设备网关时可见的 WebSocket 接口、消息格式和字段含义。不描述设备 UUID、算法 SDK 或录制文件组织。

- 网关是 WebSocket 服务端，B 端主机是客户端。
- 通过专用有线网络连接：`ws://{gateway-host}:{port}/neurobridge/v1/ws`。
- WebSocket 子协议为 `neurobridge.v1`；负载为 UTF-8 JSON 文本帧，一个文本帧对应一个完整业务消息。
- v0.3 不使用 TLS、证书、Token、账号密码或业务帧鉴权。该端口只能部署在网关与 B 端主机的专用有线直连网络中，不得暴露至公网、其他网络或不受控局域网。
- 不使用应用层保活：双方不得发送 WebSocket Ping/Pong 或 JSON 心跳。断线后，网关继续监听新连接；B 端重新连接后先调用 `getStatus`，再重新订阅。
- v0.3 为单头环、单网关实例，不传 `deviceId` 或 `gatewayId`。

推荐调用顺序：`getStatus` → `subscribe`（连续展示），或 `getStatus` → `getLatest`（读取一次当前结果）。

## 2. 通用消息格式

### 2.1 网关输出包络

网关的成功响应、失败响应、数据事件和状态事件均使用以下根对象；根对象只能包含四个字段。

```json
{
  "protocolVersion": "1.0",
  "code": 200,
  "data": {},
  "message": "OK"
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `protocolVersion` | string | 是 | 固定为 `"1.0"` |
| `code` | int | 是 | `200` 表示成功；非 `200` 表示失败 |
| `data` | JSON object | 是 | 成功结果、事件负载或错误上下文；无内容时为 `{}`，不用 `null` |
| `message` | string | 是 | 成功时固定为 `"OK"`；失败时为可读的错误原因 |

### 2.2 B 端请求根对象

```json
{
  "protocolVersion": "1.0",
  "messageType": "request",
  "requestId": "e99942e1-e9ce-4d29-a6f4-8e0bd50a6e42",
  "action": "getStatus",
  "params": {}
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `protocolVersion` | string | 是 | 固定为 `"1.0"` |
| `messageType` | string | 是 | 固定为 `"request"` |
| `requestId` | UUID string | 是 | B 端生成的唯一标识；响应在 `data.requestId` 原样返回 |
| `action` | string | 是 | `getStatus`、`getLatest`、`subscribe` 或 `unsubscribe` |
| `params` | JSON object | 是 | 动作参数；无参数时为 `{}` |

成功请求响应的 `data` 均包含以下字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `data.requestId` | UUID string | 是 | 与请求的 `requestId` 完全相同 |
| `data.action` | string | 是 | 与请求的 `action` 相同 |
| `data.result` | JSON object | 是 | 动作结果；无结果时为 `{}` |

### 2.3 字段约定

| 标记 | 含义 |
| --- | --- |
| 是 | 字段必须存在且不得为 `null` |
| 否 | 字段可省略 |
| 条件 | 满足表中条件时必须存在 |
| 可空 | 字段必须存在，但值可为 `null` |

数值字段不得使用 `NaN`、`Infinity` 或字符串化数字。值暂不可用时，按字段表使用 `null`，不得以 `0` 代替未知值。

## 3. 请求接口

### 3.1 `getStatus`

读取网关、头环连接和当前可用流。B 端每次建连后应先调用本接口。

```json
{
  "protocolVersion": "1.0",
  "messageType": "request",
  "requestId": "e99942e1-e9ce-4d29-a6f4-8e0bd50a6e42",
  "action": "getStatus",
  "params": {}
}
```

| `data.result` 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `gatewayBootId` | string | 是 | 网关进程启动标识；值变化表示网关已重启，B 端应重新订阅 |
| `subjectId` | string | 可空 | 当前实时或录播数据源的受试者标识；未配置时为 `null` |
| `mode` | string | 是 | `live` 或 `replay`；以此判断数据来源 |
| `connectionState` | string | 是 | USB 串口策略为 `not_connected`、`connecting`、`validation_failed`、`validated` 或 `disconnected`；已有合法数据流或设备对网关校验返回成功时立即为 `validated`。兼容设备策略可继续使用 `connected` 表示可用 |
| `wearState` | string | 是 | `worn`、`notWorn` 或 `unknown` |
| `batteryPercent` | number | 可空 | 设备电量百分比；未读取或不支持时为 `null` |
| `signalQuality` | number | 可空 | 当前信号质量；未产生或无法评估时为 `null` |
| `algorithmState` | string | 是 | `ready`、`warmingUp`、`unavailable` 或 `error` |
| `availableStreams` | string array | 是 | 当前可订阅流，见第 4 节 |
| `serverTimeMs` | int64 | 是 | 网关当前 Unix Epoch 毫秒（UTC） |

实时数据路径不可用但网关已配置录播时，`mode` 为 `replay`。USB 串口尚未找到目标设备时 `connectionState` 可为 `not_connected`，已识别连接关闭后为 `disconnected`；应用必须以 `mode` 判断数据来源，以 `validated` 判断串口实时路径是否可用。

### 3.2 `getLatest`

获取最近一次有效算法结果，不创建持续订阅。`params.streams` 仅允许 `eeg` 与 `hr`；缺省时两者均返回。

```json
{
  "protocolVersion": "1.0",
  "messageType": "request",
  "requestId": "a671a32d-4ba7-4d18-a6e5-fabc54df3f8e",
  "action": "getLatest",
  "params": { "streams": ["eeg", "hr"] }
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `params.streams` | string array | 否 | 仅允许 `eeg`、`hr`；缺省时两者均返回 |
| `data.result.mode` | string | 是 | 本次结果的数据来源：`live` 或 `replay` |
| `data.result.timestampMs` | int64 | 是 | 结果对应的 Unix Epoch 毫秒（UTC） |
| `data.result.valid` | boolean | 是 | `true` 表示 `payload` 可展示和保存；无结果时为 `false` |
| `data.result.payload` | JSON object | 是 | 仅包含请求且已产生的算法字段，见第 5 节 |

没有可用结果时仍返回 `code: 200`，但 `data.result.valid=false` 且 `data.result.payload={}`。

### 3.3 `subscribe`

建立独立的连续订阅。成功响应仅确认订阅；随后网关主动推送数据或状态事件。连续流以 600 ms 窗口发送，每窗口至多一条事件；窗口没有新数据时不补发空数据事件。

```json
{
  "protocolVersion": "1.0",
  "messageType": "request",
  "requestId": "fa3af4d9-1dc1-436d-af45-5855d3994fe7",
  "action": "subscribe",
  "params": {
    "streams": ["eeg", "hr", "eeg.raw", "hr.raw", "status"],
    "includeInvalid": true
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `params.streams` | string array | 是 | 至少一个流名称，见第 4 节；重复项按一个流处理 |
| `params.includeInvalid` | boolean | 否 | `true` 时推送 `valid=false` 的数据窗口；缺省为 `false` |
| `data.result.subscriptionId` | string | 是 | 当前连接内唯一的订阅标识，用于取消订阅 |
| `data.result.streams` | string array | 是 | 网关实际接受的流；不得包含未请求的流 |
| `data.result.mode` | string | 是 | 建立订阅时的数据来源；后续以每条事件的 `data.mode` 为准 |
| `data.result.intervalMs` | int | 是 | 固定为 `600` |

### 3.4 `unsubscribe`

取消当前 WebSocket 连接创建的订阅。成功确认后，网关不得再推送该订阅的数据事件。

```json
{
  "protocolVersion": "1.0",
  "messageType": "request",
  "requestId": "7bf79a85-f5d1-4fd6-997f-25aa99a0f1e5",
  "action": "unsubscribe",
  "params": { "subscriptionId": "sub-01HXYZ" }
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `params.subscriptionId` | string | 是 | 待取消的、当前连接创建的订阅标识 |
| `data.result.subscriptionId` | string | 是 | 已取消的订阅标识，与请求相同 |

重复取消或取消其他连接的订阅返回 `SUBSCRIPTION_NOT_FOUND`。

## 4. 可订阅流与事件

### 4.1 流名称

| 流 | 事件负载字段 | 发送规则 |
| --- | --- | --- |
| `eeg` | `data.payload.algorithm` 中的脑电相关字段 | 算法结果更新时，最多每 600 ms 一组 |
| `hr` | `data.payload.algorithm` 中的心率相关字段（包括压力值） | 算法结果更新时，最多每 600 ms 一组 |
| `eeg.raw` | `data.payload.eegRaw` | 原始 EEG 字节窗口，最多每 600 ms 一组 |
| `hr.raw` | `data.payload.hrRaw` | 原始 HR 字节窗口，最多每 600 ms 一组 |
| `status` | `data.payload.status` | 状态变化时；连续订阅时最多每 600 ms 一组 |

网关只发送已订阅且已产生的字段。未订阅 `eeg.raw` 或 `hr.raw` 时，不得在算法流中夹带原始数据。压力值属于 `hr` 流，不使用独立的 `pressure` 流；订阅 `hr` 或以 `getLatest` 请求 `hr` 后，才可能返回压力值。

### 4.2 连续事件包络

```json
{
  "protocolVersion": "1.0",
  "code": 200,
  "data": {
    "event": "data",
    "subscriptionId": "sub-01HXYZ",
    "gatewayBootId": "20260804T100000Z-7bf0",
    "subjectId": "SUBJECT-001",
    "mode": "live",
    "timestampMs": 1785800000600,
    "valid": true,
    "payload": {}
  },
  "message": "OK"
}
```

| `data` 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `event` | string | 是 | `data`（连续数据）、`status`（状态变化）或 `replayEnded`（单个录播循环结束） |
| `subscriptionId` | string | 条件 | `data`、`status` 事件必须存在；`replayEnded` 可省略 |
| `gatewayBootId` | string | 是 | 网关进程启动标识；与 `getStatus` 中的值不同表示需重新订阅 |
| `subjectId` | string | 可空 | 当前数据源的受试者标识 |
| `mode` | string | 是 | `live` 或 `replay` |
| `timestampMs` | int64 | 是 | 数据组或状态事件的 Unix Epoch 毫秒（UTC） |
| `valid` | boolean | 是 | `false` 时 B 端不得将测量结果展示或保存为有效数据 |
| `payload` | JSON object | 是 | 已订阅流的业务负载；`status` 事件至少包含 `status` |
| `payload.invalidReasons` | string array | 条件 | 仅 `valid=false` 时出现，列出无效原因 |
| `recordingId` | string | 条件 | 仅 `event="replayEnded"` 时存在 |
| `endedAtMs` | int64 | 条件 | 仅 `event="replayEnded"` 时存在，表示结束事件产生时间 |

### 4.3 状态负载字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `payload.status` | JSON object | 条件 | 订阅 `status` 或 `event="status"` 时存在 |
| `payload.status.connectionState` | string | 是 | USB 串口策略使用 `not_connected`（未找到目标设备）、`connecting`（遍历候选）、`validation_failed`（候选未通过设备验证）、`validated`（已有合法数据流或设备校验成功）和 `disconnected`（已识别连接断开）；兼容设备策略可继续使用 `connected` 表示可用 |
| `payload.status.wearState` | string | 是 | `worn`、`notWorn` 或 `unknown` |
| `payload.status.batteryPercent` | number | 可空 | 设备电量百分比；尚未读取或不支持时为 `null` |
| `payload.status.signalQuality` | number | 可空 | 信号质量；未产生或无法评估时为 `null` |
| `payload.status.algorithmState` | string | 是 | 本地算法状态：`ready`、`warmingUp`、`unavailable` 或 `error`；USB 串口只有算法为 `ready` 后才允许发送 `E1` |

状态事件必须携带完整的 `payload.status`，而非仅发送变更字段。

### 4.4 原始数据负载字段

原始字节按接收顺序以 Base64 发送。B 端如需解析，须使用双方确认的头环解析规范；不得从本协议推断采样率、通道布局或字节数值类型。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `payload.eegRaw` | JSON object | 条件 | 仅订阅 `eeg.raw` 时存在 |
| `payload.hrRaw` | JSON object | 条件 | 仅订阅 `hr.raw` 时存在 |
| `*.encoding` | string | 是 | 固定为 `"base64"` |
| `*.sampleFormat` | string | 是 | 固定为 `"bytes"`，表示未转换的原始 设备 字节串 |
| `*.packetBytes` | int | 是 | 单包字节数；由网关按实际原始数据填写，B 端不得据此推断设备内部协议 |
| `*.packetCount` | int | 是 | 本窗口实际收到的包数；不预设固定数量 |
| `*.byteLength` | int | 是 | 必须等于 `packetBytes × packetCount` |
| `*.windowStartMs` | int64 | 是 | 窗口起始 Unix Epoch 毫秒（UTC） |
| `*.windowEndMs` | int64 | 是 | 窗口结束 Unix Epoch 毫秒（UTC）；正常窗口约为 600 ms |
| `*.bytesBase64` | string | 是 | 保持接收顺序的完整原始字节，经 Base64 编码 |

其中 `*` 分别表示 `payload.eegRaw` 或 `payload.hrRaw`。

### 4.5 算法负载字段

仅在订阅相应算法流且网关已产生结果时出现。除睡眠分期外，数值范围和单位以双方验收的算法结果为准；B 端不得自行假定为 0-100。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `payload.algorithm` | JSON object | 条件 | 订阅 `eeg` 或 `hr` 且产生结果时存在 |
| `payload.algorithm.eeg.wave.left` / `.right` | number array | 条件/可空 | 双通道左右脑波；单通道时为 `null` |
| `payload.algorithm.eeg.wave.single` | number array | 条件/可空 | 单通道脑波；双通道时为 `null` |
| `payload.algorithm.eeg.bandPower.alpha` / `.beta` / `.theta` / `.delta` / `.gamma` | number | 条件 | 对应 EEG 频段能量 |
| `payload.algorithm.eeg.bandPower.lowBeta` / `.highBeta` | number | 条件/可空 | 对应频段能量；算法未提供时为 `null` |
| `payload.algorithm.eeg.quality` | number | 条件 | 脑电质量值 |
| `payload.algorithm.sleep.updated` | boolean | 条件 | 当前窗口是否产生新的睡眠结果；为 `false` 时不是新的睡眠判定 |
| `payload.algorithm.sleep.degree` / `.state` / `.spindle` | number / int / number | 条件 | 睡眠相关结果 |
| `payload.algorithm.sleep.stage` | int | 条件 | `0=WAKE`、`1=NREM1`、`2=NREM2`、`3=NREM3`、`4=REM` |
| `payload.algorithm.relaxation` | number | 条件 | 放松度 |
| `payload.algorithm.pleasure` | number | 条件 | 愉悦度 |
| `payload.algorithm.attention` | number | 条件 | 注意力 |
| `payload.algorithm.flow.meditation` / `.meditationTips` | number | 条件 | 心流/冥想结果 |
| `payload.algorithm.hr.value` | int | 条件 | 心率结果 |
| `payload.algorithm.hr.hrv` | number | 条件 | 心率变异性结果 |
| `payload.algorithm.pressure` | number | 条件 | 压力水平；由心率算法输出。仅算法已启用且产生有效结果时存在，未产生时省略，不以 `0` 代替 |
| `payload.algorithm.coherence` / `.arousal` | number | 条件 | 和谐度 / 激活度；与压力值同属心率算法输出 |

## 5. 实时、录播与重连

- 已连接头环时，网关返回或推送 `mode="live"` 的实时数据。
- 实时设备路径不可用时，`subscribe` 与 `getLatest` 自动使用网关部署配置的录播；B 端不能选择录播或切换数据源。此时 `mode="replay"`；USB 串口状态可为 `not_connected`、`connecting`、`validation_failed` 或 `disconnected`，`validated` 表示设备验证完成并切换到实时路径。
- 录播与实时使用相同字段结构；录播的 `timestampMs` 保持录制时的原始时间，不能改写为发送时刻。
- 最后一个 B 端 WebSocket 连接断开时，网关停止录播并清空当前录播进度；只要仍有 B 端连接，录播读到文件末尾后从首条继续。每轮结束发送 `event="replayEnded"`，该事件后同一订阅继续接收下一轮的 `data` 事件。
- 没有可用录播时，网关返回 `REPLAY_NOT_AVAILA设备`，且不创建订阅或录播任务。
- 发生连接、佩戴、电量、信号或算法状态变化时，网关向订阅 `status` 的连接发送 `event="status"`。
- WebSocket 实际断开后，网关释放该连接的订阅。B 端重新连接后必须重新调用 `subscribe`。

## 6. 错误与限流

失败响应仍使用第 2.1 节根对象，示例如下：

```json
{
  "protocolVersion": "1.0",
  "code": 503,
  "data": {
    "requestId": "fa3af4d9-1dc1-436d-af45-5855d3994fe7",
    "reason": "REPLAY_NOT_AVAILA设备",
    "retryable": true,
    "details": {}
  },
  "message": "No replay data is available."
}
```

| `data` 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `requestId` | UUID string | 条件 | 请求触发的错误必须存在；连接级错误可省略 |
| `reason` | string | 是 | 稳定的机器可读错误标识 |
| `retryable` | boolean | 是 | `true` 表示可按退避策略重试；`false` 表示需修正请求或配置 |
| `details` | JSON object | 是 | 错误上下文；无额外信息时为 `{}` |

| `code` | `data.reason` | 含义 | 可重试 |
| --- | --- | --- | --- |
| `400` | `INVALID_REQUEST` | 缺少字段、类型错误或枚举值错误 | 否 |
| `404` | `DEVICE_NOT_FOUND` / `SUBSCRIPTION_NOT_FOUND` | 设备或订阅不存在 | 否 |
| `409` | `STREAM_NOT_AVAILA设备` | 流不支持、算法未启用或设备 profile 不匹配 | 否，需调整请求或配置 |
| `429` | `RATE_LIMITED` | 请求频率或订阅数超过部署限制 | 是 |
| `500` | `INTERNAL_ERROR` | 未预期的网关错误 | 是 |
| `503` | `REPLAY_NOT_AVAILA设备` / `ALGORITHM_NOT_READY` | 没有可用录播，或尚无可用算法结果 | 是 |
| `505` | `UNSUPPORTED_VERSION` | 协议版本不支持 | 否 |

默认限制为每连接最多 4 个订阅、每连接每流最多 1 个相同订阅、单条 JSON 负载最大 256 KiB。超限时返回 `429` 或 `400`；网关不得静默丢弃事件。端口、静态 IP、子网掩码和实际启用的流由双方在部署前确认。

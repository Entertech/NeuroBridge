## PR14-DEPLOY-01：服务账户没有串口访问权限

### 触发条件与影响

在干净的银河麒麟 V10 x86_64 主机安装原生 DEB 或 RPM，`neurobridge` 服务账户尚未获得 USB 派生 TTY 的访问权限。例如设备节点为 `root:dialout`、权限为 `0660` 时，该账户仅属于 `neurobridge` 组，不能打开串口。服务进程可以存在，但耳机连接及实时采集无法完成。

设备节点的实际所属组必须在目标机确认；`dialout` 只是说明该问题的例子，不是所有目标机的固定配置。

### 源码证据

- [DEB postinst（312–318 行）](https://github.com/Entertech/NeuroBridge/blob/dd7c68c3bab2994a076d03a53b3b7e1fe544ca89/tools/build-native-package.py#L312) 与 [RPM %post（375–382 行）](https://github.com/Entertech/NeuroBridge/blob/dd7c68c3bab2994a076d03a53b3b7e1fe544ca89/tools/build-native-package.py#L375) 只创建账户、目录及单元，没有为账户追加实际 TTY 所属组或等效授权。
- [随包服务单元](https://github.com/Entertech/NeuroBridge/blob/dd7c68c3bab2994a076d03a53b3b7e1fe544ca89/packaging/kylin/neurobridge.service#L7) 固定使用 `User=neurobridge`、`Group=neurobridge`。
- [既有候选包安装入口](https://github.com/Entertech/NeuroBridge/blob/dd7c68c3bab2994a076d03a53b3b7e1fe544ca89/packaging/kylin/install.sh#L24) 会查找实际 USB TTY 所属组并调用 `usermod -aG`；原生包维护脚本没有调用该入口，因此不能沿用它的授权结论。

### 后续处理与验收

- [x] 为原生 DEB/RPM 追加实际 USB TTY 非 root 组；无设备输出未就绪提示，授权失败或无可用组时脚本报错，不放宽节点权限。
- [x] 执行生成的 DEB/RPM 维护脚本回归，覆盖两种实际设备组、无设备、root 组、未知组、授权失败和重复安装；系统账户及命令使用模拟，不代表目标机权限验证。
- [ ] 在银河麒麟 V10 x86_64 上分别验证 DEB/RPM 安装后的实际服务进程权限、合法帧采集、耳机拔插重连、服务重启和浏览器断开恢复。
- [ ] 串口离线且存在历史录制时，确认不读取历史数据、不创建录播任务、不输出 `mode="replay"`。
- [ ] 补充内部安装与排障文档，记录目标机、源码提交、包摘要、验证时间和结果后再关闭问题。

## PR14-DEPLOY-02：升级后未切换到新服务进程

### 触发条件与影响

已安装的原生 DEB/RPM 网关服务正在运行时，安装新版本或覆盖安装。升级过程替换 `/opt/neurobridge` 下的程序，但既不停止旧进程，也不在安装结束后请求进程切换。安装显示成功后，原进程仍继续运行已加载的旧代码；新版本不会因此自动生效，直到人工重启服务或整机重启。

`Restart=always` 只在进程退出后触发重启；`systemctl daemon-reload` 和 `systemctl enable` 都不会重启当前进程。不能据此认定 systemd 已完成版本切换。

### 源码证据

- [DEB 升级保护（301–303 行）](https://github.com/Entertech/NeuroBridge/blob/dd7c68c3bab2994a076d03a53b3b7e1fe544ca89/tools/build-native-package.py#L301) 对 `upgrade` 等参数直接返回，不停止服务。
- [DEB postinst（316–319 行）](https://github.com/Entertech/NeuroBridge/blob/dd7c68c3bab2994a076d03a53b3b7e1fe544ca89/tools/build-native-package.py#L316) 只更新单元、`daemon-reload` 和 `enable`，没有升级后的进程切换。
- [RPM %post/%preun（375–388 行）](https://github.com/Entertech/NeuroBridge/blob/dd7c68c3bab2994a076d03a53b3b7e1fe544ca89/tools/build-native-package.py#L375) 同样只在真实卸载时停止服务，升级后没有重新启动进程。

### 后续处理与验收

- [ ] 明确原生包升级的切换时点、允许的中断、停止时限及失败恢复方式，并实现可观察的新进程启动；保留原本已停止服务的状态。
- [ ] 增加运行中升级、已停止服务升级、覆盖安装及失败恢复的生命周期回归，验证实际执行行为，而不只检查脚本文本。
- [ ] 在银河麒麟 V10 x86_64 上分别验证 DEB/RPM：升级前后记录进程标识、启动时间与日志应用版本，确认新程序实际运行且没有重复网关进程。
- [ ] 确认配置及录制数据保留、录制会话正常收尾；恢复串口后继续合法帧采集，离线时即使存在历史录制也不启动录播。
- [ ] 验证浏览器断线恢复时重新建连、先调用 `getStatus` 再订阅，不复用旧 `subscriptionId`；整机重启后仍可运行。
- [ ] 更新内部升级与恢复说明，保存目标机证据后再关闭问题；不得把脚本生成或模拟测试通过写成现场验收通过。

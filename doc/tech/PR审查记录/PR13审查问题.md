## 问题

### P1：未发布协议被源码直接修改

`neurobridge/adapters/northbound/codec.py` 的 `GatewayWireCodec.envelope()` 会在成功数据的 EEG 波形全为 `FF` 时，把根对象 `message` 自动改为 `未佩戴：脑波数据全为 FF`。这会让当前运行时直接向客户端发送新的可观察协议语义，而 PR 同时声明已发布北向协议 v0.2 未修改；没有协议版本协商或能力开关，使用 v0.2 的客户端会收到未约定的成功消息。

处理要求：将该行为限定到已发布的新协议版本或显式能力开关，并完成对应的正式协议发布、PDF 和锁定台账流程；在此之前保持 v0.2 的成功消息语义。

证据：`neurobridge/adapters/northbound/codec.py:12-20`；PR 描述“已发布 B 端北向协议 v0.2 的 Markdown、报文 protocolVersion、发布日期和摘要均未修改”。

### P2：麒麟操作手册仍描述已移除的 ACK/01 握手

`linux/README.md:34` 仍要求串口模式先回写握手 ACK 并等待设备独立 `01`，`linux/README.md:352` 的排障表仍要求检查 ACK 后的 `01`。当前代码、README 顶部和 2026-09-10 的需求规则已经改为并行准备算法与设备，静默候选直接发送无响应 `E1`，以完整 28 字节帧验证连接，不再发送 ACK/使用 `01`。

处理要求：删除或改写这些旧流程，统一说明当前 E1/合法帧验证时序，并同步检查麒麟脚本、内部手册和排障页面中的同类旧表述，避免现场人员按旧流程操作。

证据：`linux/README.md:34`、`linux/README.md:352`；`README.md` 的“2026-09-10 用户确认”段落；`neurobridge/serial/adapter.py` 的 `startupPolicy=direct_e1` 路径。

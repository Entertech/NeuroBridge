# 银河麒麟 V10 新设备配置与启动手册

状态：内部操作手册

适用设备：N100/N150 x86_64 主机、银河麒麟 V10、USB 串口耳机

本手册只说明一件事：在新机器上配置 USB 串口耳机并启动 NeuroBridge。现场按顺序执行即可。

## 1. 已安装程序时：直接按这 5 步启动

适用于已经存在以下文件的机器：

```text
/opt/neurobridge/venv/bin/neurobridge
/opt/neurobridge/linux/setup-kylin-serial.sh
/etc/systemd/system/neurobridge.service
```

### 第 1 步：连接耳机

把耳机通过 USB 接到主机。只连接一台耳机。

### 第 2 步：确认系统识别到串口

```bash
ls -l /dev/serial/by-id 2>/dev/null || true
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null || true
```

正常情况至少出现一个 `/dev/ttyACM*`、`/dev/ttyUSB*` 或 `/dev/serial/by-id/*`。

### 第 3 步：一键配置串口

```bash
cd /opt/neurobridge
sudo ./linux/setup-kylin-serial.sh
```

脚本会自动完成：

- 创建或备份 `/etc/neurobridge/gateway.toml`；
- 配置 `serial` 数据源；
- 配置 115200、8-N-1、无流控；
- 自动遍历 `ttyACM*` 和 `ttyUSB*`；
- 给 `neurobridge` 服务账户补充串口设备组权限；
- 校验配置；
- 重启已经安装的服务。

成功时最后会看到：

```text
Serial setup complete
service=active
```

### 第 4 步：启动程序并设置开机自启

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now neurobridge.service
sudo systemctl status neurobridge.service --no-pager -l
```

`Active: active (running)` 表示程序已经启动。

### 第 5 步：打开页面

在这台麒麟电脑的浏览器中打开：

```text
http://127.0.0.1:8080/
```

到这里，配置和启动完成。

## 2. 全新机器首次安装

如果第 1 节列出的程序文件不存在，先执行本节。只需安装一次。

### 2.1 准备文件

在新机器上准备：

1. 已审核的完整 NeuroBridge 源码目录；
2. Python 3.11 或更高版本；
3. 与银河麒麟 x86_64 和当前 Python 小版本匹配的离线 `wheelhouse`；
4. 已在银河麒麟上验证的算法 bridge（需要显示算法结果时必须提供）。

先进入源码目录：

```bash
cd /实际路径/NeuroBridge
export NB_SOURCE_DIR=$PWD
export NB_WHEELHOUSE=/实际路径/wheelhouse
```

检查系统和安装文件：

```bash
cat /etc/os-release
uname -m
python3.11 --version
test -f "$NB_SOURCE_DIR/pyproject.toml"
test -f "$NB_SOURCE_DIR/requirements.lock"
test -d "$NB_WHEELHOUSE"
```

必须满足：

- 系统是银河麒麟；
- `uname -m` 输出 `x86_64`；
- Python 不低于 3.11；
- 源码和 `wheelhouse` 完整。

### 2.2 创建服务账户和目录

```bash
sudo groupadd --system neurobridge 2>/dev/null || true
id -u neurobridge >/dev/null 2>&1 || \
  sudo useradd --system --gid neurobridge --home /nonexistent --shell /usr/sbin/nologin neurobridge

sudo install -d -o root -g root -m 0755 /opt/neurobridge
sudo install -d -o root -g neurobridge -m 0750 /etc/neurobridge
sudo install -d -o neurobridge -g neurobridge -m 0750 /var/lib/neurobridge/recordings
sudo install -d -o neurobridge -g neurobridge -m 0750 /var/log/neurobridge
```

### 2.3 安装程序和 Python 依赖

```bash
sudo rsync -a --delete \
  --exclude .git --exclude .venv --exclude venv \
  "$NB_SOURCE_DIR/" /opt/neurobridge/

sudo python3.11 -m venv /opt/neurobridge/venv
sudo /opt/neurobridge/venv/bin/python -m pip install \
  --no-index --find-links "$NB_WHEELHOUSE" \
  -r /opt/neurobridge/requirements.lock
sudo /opt/neurobridge/venv/bin/python -m pip install \
  --no-index --no-deps --no-build-isolation /opt/neurobridge
```

检查安装结果：

```bash
/opt/neurobridge/venv/bin/python --version
/opt/neurobridge/venv/bin/python -c \
  'import neurobridge, serial, websockets; print("runtime OK")'
/opt/neurobridge/venv/bin/python -m pip check
```

必须看到 `runtime OK`，并且 `pip check` 不能报错。

### 2.4 安装 systemd 服务和日志轮转

```bash
sudo install -m 0644 \
  /opt/neurobridge/linux/systemd/neurobridge.service \
  /etc/systemd/system/neurobridge.service
sudo install -m 0644 \
  /opt/neurobridge/linux/logrotate/neurobridge \
  /etc/logrotate.d/neurobridge
sudo systemctl daemon-reload
```

### 2.5 检查算法 bridge

```bash
sudo test -x /usr/local/lib/neurobridge/neurobridge_affective_bridge
```

命令没有输出且返回成功，表示算法 bridge 已安装。需要算法可视化数据时，这个文件必须由审核后的银河麒麟部署包提供，并完成真实数据验证。

如果命令失败，先继续执行下一步生成配置；启动服务前必须关闭算法，或者补齐审核后的算法 bridge。

### 2.6 连接耳机并完成配置

接好耳机后执行：

```bash
cd /opt/neurobridge
sudo ./linux/setup-kylin-serial.sh --no-restart
```

如果上一步确认算法 bridge 不存在，执行：

```bash
sudoedit /etc/neurobridge/gateway.toml
```

把配置改为：

```toml
[algorithm]
enabled = false
```

关闭算法后可以验证串口、原始数据和页面连接，但不会产生算法可视化结果。

然后启动服务：

```bash
sudo systemctl enable --now neurobridge.service
sudo systemctl status neurobridge.service --no-pager -l
```

最后打开：

```text
http://127.0.0.1:8080/
```

## 3. 串口配置说明

一键脚本会自动写入以下核心配置，通常不需要手工修改：

```toml
[data_source]
type = "serial"

[serial]
device = "auto"
candidate_types = ["ttyACM", "ttyUSB"]
baud_rate = 115200
handshake_timeout_ms = 1000
command_response_timeout_ms = 1000
data_timeout_seconds = 5
reconnect_delay_seconds = 3
stats_interval_seconds = 10
max_buffer_bytes = 65536
dtr = false
rts = false
```

`device = "auto"` 表示逐个检查所有 USB 派生串口。收到完整握手数据后立即回复 ACK，选择该串口并停止继续遍历。

识别出稳定设备路径后，也可以固定设备：

```bash
cd /opt/neurobridge
sudo ./linux/setup-kylin-serial.sh \
  --device /dev/serial/by-id/实际设备名称
```

没有确认稳定路径时继续使用 `auto`。

## 4. 判断耳机是否连接成功

插入 USB 前，先打开两个终端。

终端 1 跟踪网关日志：

```bash
sudo journalctl -u neurobridge.service -f -o short-iso-precise
```

终端 2 跟踪内核 USB 和串口枚举：

```bash
sudo dmesg --follow
```

保持两个终端打开，再插入耳机 USB。另开一个终端记录插入后的设备现状：

```bash
date --iso-8601=seconds
lsusb
lsusb -t
ls -l /dev/serial/by-id 2>/dev/null || true
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null || true
```

这三组输出可以分清是“系统没枚举 USB”、“枚举了 USB 但没生成 TTY”，还是“程序打开了 TTY 但协议不对”。

正常连接应依次看到类似内容：

```text
transport=serial
Serial discovery started
Serial candidate opened
Serial handshake accepted and ACK sent
Serial target selected
Serial control response received: command=start ... success=true
Connection state changed: ... current=connected
Serial capture summary
```

关键判断：

| 日志 | 含义 |
|---|---|
| `Serial discovery found no usable candidates` | 本轮没有可用候选 TTY；同行的 `byIdEntries`、`ttyACMEntries`、`ttyUSBEntries` 显示各类节点数量。固定路径模式下 `configuredPathExists` 显示路径是否存在，`auto` 模式为 `not_applicable` |
| `Serial candidate probe failed` | 找到候选串口但打开、配置、读写或握手过程异常；查看 `path`、`errorType` 和受限的 `reason` |
| `Serial candidate produced no handshake bytes` | 串口已打开，但探测窗口内一个字节都没收到；检查接线、接口、串口参数和设备供电 |
| `Serial candidate produced bytes but no valid handshake` | 串口有数据，但未出现完整固定握手；重点查看 `readBytes`、`discardedBytes`、`bufferTruncations` 和 `longestHandshakePrefixBytes` |
| `longestHandshakePrefixBytes=6` | 收到过与固定握手前 6 字节相同的内容，很可能最后 1 字节不同或帧被截断；日志不输出收到的原文 |
| `Serial unexpected bytes discarded before valid handshake` | 最终找到了正确握手，但其前收到过异常字节并已丢弃 |
| `ACK sent` | 已识别目标耳机并回复 ACK |
| `command=start ... success=true` | `0xE1` 已收到非空响应 |
| `current=connected` | 网关进入实时采集状态 |
| `frames` 持续增加 | 持续收到有效 28 字节数据帧 |
| `lossRatePercent` | 当前累计丢包率 |
| `Serial invalid frame rejected: reason=length` | 找到帧头，但长度字段不是协议要求的值 |
| `Serial invalid frame rejected: reason=tail` | 帧长度满足，但包尾不正确 |
| `Serial bytes discarded while resynchronizing` | 解析器为重新寻找有效帧头丢弃了字节 |
| `Serial valid-frame timeout` | 可能一直有读取，但持续没有任何有效 28 字节帧；查看 `readBytes`、`invalidFrames`、`discardedBytes` 和 `bufferOverflows` |
| `Serial reconnect scheduled` | 当前连接已结束，程序将按 `delaySeconds` 自动重新枚举 |

错误握手、控制响应和数据帧日志中的 `payloadLogged=false` 表示程序只记录字节数、读取次数、匹配长度、异常类型和耗时，不写入未知串口原文或完整生理数据。非法字节和非法帧日志会限频，但累计计数会继续增加，避免垃圾数据导致日志占满磁盘。

查看最近 300 行日志：

```bash
sudo journalctl -u neurobridge.service -b -n 300 --no-pager -o short-iso-precise
```

查看应用文件日志：

```bash
sudo tail -n 300 /var/log/neurobridge/neurobridge.log
```

## 5. 常用启停命令

启动：

```bash
sudo systemctl start neurobridge.service
```

停止：

```bash
sudo systemctl stop neurobridge.service
```

重启：

```bash
sudo systemctl restart neurobridge.service
```

查看状态：

```bash
sudo systemctl status neurobridge.service --no-pager -l
```

设置开机自启：

```bash
sudo systemctl enable neurobridge.service
```

取消开机自启：

```bash
sudo systemctl disable neurobridge.service
```

## 6. 最常见问题

### 6.1 没有串口设备

```bash
lsusb
lsusb -t
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null || true
sudo dmesg | tail -n 100
```

如果 `lsusb` 也没有新设备，先查电源、USB 线、USB 口和接触。如果 `lsusb` 有新设备但没有 `ttyACM*`/`ttyUSB*`，重点查内核驱动绑定、设备接口类型和 `dmesg` 报错。系统没有生成 TTY 时，程序无法按串口方式连接。

### 6.2 串口有字节但握手不正确

先查网关日志：

```bash
sudo journalctl -u neurobridge.service -b --no-pager -o short-iso-precise | \
  grep -E 'no valid handshake|longestHandshakePrefixBytes|unexpected bytes'
```

如果出现 `produced bytes but no valid handshake`，说明 USB、TTY 和读操作基本已通，但实际字节不符合固定 7 字节握手。优先向设备方核对固件版本、实际接口、115200 8-N-1 参数以及设备是否已被其他上位机 ACK。不要为排障将未知串口原文加入日志。

### 6.3 串口权限不足

```bash
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null || true
id neurobridge
```

重新运行一键配置，让脚本补充设备组权限：

```bash
cd /opt/neurobridge
sudo ./linux/setup-kylin-serial.sh
```

不要使用 `chmod 777`。

### 6.4 串口被其他程序占用

把节点换成实际设备：

```bash
sudo fuser -v /dev/ttyACM0 2>/dev/null || true
sudo lsof /dev/ttyACM0 2>/dev/null || true
```

确认占用程序可以停止后再处理，不要直接结束不认识的系统进程。

### 6.5 服务启动失败

```bash
sudo systemctl status neurobridge.service --no-pager -l
sudo journalctl -u neurobridge.service -b -n 500 --no-pager -o short-iso-precise
/opt/neurobridge/venv/bin/python -m pip check
```

重点检查：Python 环境、配置文件、串口权限、算法 bridge、日志目录和录制目录。

### 6.6 页面打不开

```bash
sudo systemctl is-active neurobridge.service
sudo ss -lntp | grep -E '127\.0\.0\.1:(8080|8765|8766)' || true
sudo journalctl -u neurobridge.service -b -n 200 --no-pager
```

只能使用本机浏览器打开：

```text
http://127.0.0.1:8080/
```

## 7. 配置和数据位置

| 路径 | 用途 |
|---|---|
| `/opt/neurobridge` | 程序文件 |
| `/opt/neurobridge/venv` | Python 运行环境 |
| `/etc/neurobridge/gateway.toml` | 运行配置 |
| `/var/log/neurobridge/neurobridge.log` | 应用日志 |
| `/var/lib/neurobridge/recordings` | 录制数据 |
| `/var/lib/neurobridge/recordings/internal-device` | 完整串口设备帧内部记录 |
| `/usr/local/lib/neurobridge/neurobridge_affective_bridge` | 算法 bridge |

配置文件备份由一键脚本自动生成，路径类似：

```text
/etc/neurobridge/gateway.toml.before-serial-20260901T120000Z
```

## 8. 导出诊断包

现场无法判断问题时，在程序目录执行：

```bash
cd /opt/neurobridge
sudo ./linux/collect-kylin-runtime-diagnostics.sh \
  --output-dir /tmp \
  --journal-lines 10000
```

生成：

```text
/tmp/neurobridge-kylin-runtime-diagnostics-<时间>-<进程号>.tar.gz
/tmp/neurobridge-kylin-runtime-diagnostics-<时间>-<进程号>.tar.gz.sha256
```

校验：

```bash
bundle=$(ls -1t /tmp/neurobridge-kylin-runtime-diagnostics-*.tar.gz | head -n 1)
sudo sha256sum -c "$bundle.sha256"
```

诊断包不包含配置正文、录制数据、完整脑波原始数据或算法载荷。导出前仍需人工检查，只能通过项目批准的内部渠道传递。

## 9. 启动完成检查表

逐项确认：

- [ ] `uname -m` 输出 `x86_64`；
- [ ] `/opt/neurobridge/venv/bin/neurobridge` 存在；
- [ ] `/etc/neurobridge/gateway.toml` 存在；
- [ ] 系统出现 `ttyACM*`、`ttyUSB*` 或稳定 by-id 路径；
- [ ] `setup-kylin-serial.sh` 执行成功；
- [ ] `neurobridge.service` 为 `active (running)`；
- [ ] 日志出现 `ACK sent`；
- [ ] 日志出现 `command=start ... success=true`；
- [ ] 日志出现 `current=connected`；
- [ ] `frames` 持续增加；
- [ ] 浏览器可以打开 `http://127.0.0.1:8080/`；
- [ ] 需要算法结果时，算法 bridge 已安装且日志显示算法状态正常。

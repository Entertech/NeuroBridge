# 银河麒麟 V10 USB 串口耳机配置与启动手册

状态：内部操作手册

适用环境：N100/N150 x86_64 主机、银河麒麟 V10、USB 连接且枚举为串口的耳机设备

本手册只描述当前现场方案：一台耳机通过 USB 接入麒麟电脑，NeuroBridge 从项目目录直接运行，使用本机浏览器查看数据。不需要配置蓝牙、网线或另一台 B 端主机。

## 1. 新设备最短上手流程

先插好耳机 USB。完整项目中的现场入口是 `linux/neurobridge-kylin-bootstrap.sh`，进入 NeuroBridge 后只执行它，不要加 `sudo`：

```bash
cd /实际路径/NeuroBridge
bash linux/neurobridge-kylin-bootstrap.sh
```

操作员不需要逐个执行其他脚本。这个单文件入口会检查项目位置和权限；旧代码缺少数字菜单时，会识别当前分支。设备不在 `codex/serial-usb-transport` 时，明确询问是否切换到该分支，获取完成后直接打开菜单。PR #13 合入 `master` 前，不能依赖 `master` 上的普通 `git pull` 获得本方案。

看到数字菜单后输入 `1`。助手会依次完成：

1. 检查并按需修复当前项目权限；
2. 准备项目内 Python 3.11、`.venv` 和锁定依赖；
3. 直接检查当前已经连接的 USB/串口，不要求拔插；
4. 生成串口配置并处理最小设备组权限；
5. 询问 `是否现在启动网关？[yes/no]`，输入 `yes` 立即启动。

启动后保持终端打开，用本机浏览器访问：

```text
http://127.0.0.1:8080/
```

按 `Ctrl+C` 停止程序。以后启动只需再次运行 `bash linux/neurobridge-kylin-bootstrap.sh` 并输入 `5`。每一步都会在屏幕上显示结果和“下一步命令”，完整过程保存在：

```text
.runtime/logs/setup-kylin-gateway-<UTC时间>-<进程号>.log
```

## 2. 助手菜单怎么选

```text
1. 新设备首次配置
2. 修复项目权限并更新代码
3. 检查当前 USB/串口（无需拔插）
4. 生成 USB 串口配置
5. 启动网关
6. 导出完整诊断包
0. 退出
```

菜单只输入数字。只有一个判断时只询问 `yes/no`；也兼容简写 `y/n`，输入其他内容会重新询问。

| 场景 | 输入 | 结果和下一步 |
|---|---:|---|
| 新电脑第一次配置 | `1` | 自动串起完整流程，并询问是否启动 |
| 重启后 `git pull` 报索引权限不足 | `2` | 安全修复当前项目权限，再以普通用户执行 `git pull --ff-only` |
| USB 已插好，只想确认系统是否生成串口 | `3` | 立即检查现有 TTY 并保存诊断，不要求拔插 |
| Python 已准备好，只需重新生成配置 | `4` | 生成 `.runtime/config/gateway.toml` |
| 日常启动 | `5` | 启动网关并提示浏览器地址 |
| 现场问题无法判断 | `6` | 生成完整诊断压缩包和 SHA-256 |

代码发生更新时，助手会立即退出并提示重新执行 `bash linux/neurobridge-kylin-bootstrap.sh`，避免继续运行已被替换的旧脚本。

## 3. 项目权限和 Git 更新

如果曾经执行 `sudo git pull`、用 root 解压/复制项目，重启后可能看到“打开索引文件失败”或“权限不够”。完整项目直接运行 `bash linux/neurobridge-kylin-bootstrap.sh`；入口文件会先处理阻止运行的项目权限，进入菜单后也可输入 `2` 主动修复并更新。修复前会验证：

- 目标不是 `/` 等宽泛目录；
- 当前目录确实包含 `pyproject.toml`；
- `.git` 是当前项目内的真实目录，不是符号链接；
- 一键助手存在于该项目的 `linux/` 目录。

确认后输入 `yes`，助手只对当前 NeuroBridge 项目修复所有权和 Git 所需权限。不要再执行 `sudo git pull`、`sudo git checkout` 或 `sudo git add`。

助手不会自动删除 `.git/index.lock`。若提示存在该文件，先确认没有其他 Git 进程，再按屏幕给出的精确命令人工处理。

如果问题电脑无法拉取新代码，只需把单个 `neurobridge-kylin-bootstrap.sh` 文件复制到该电脑的 NeuroBridge 项目根目录后运行。该文件在仓库中的来源是 `linux/neurobridge-kylin-bootstrap.sh`。即使通过微信或 U 盘复制后没有执行权限，也不需要执行 `chmod`：

```bash
cd /实际路径/NeuroBridge
bash neurobridge-kylin-bootstrap.sh
```

入口文件自身会验证项目根目录，询问 `yes/no` 后只修复这个项目，并在需要时获取目标分支。复制到根目录的文件名不会与仓库中 `linux/` 下的跟踪文件冲突，因此后续拉取不会因“未跟踪文件将被覆盖”失败。不要把它放在主目录或其他目录执行，也不要运行 `sudo bash neurobridge-kylin-bootstrap.sh`。

## 4. USB、配置和启动规则

- 日常检测直接遍历当前 `/dev/serial/by-id/*`、`/dev/ttyACM*` 和 `/dev/ttyUSB*`，无需拔插。
- 检测到 TTY 只表示它是候选。网关启动后会逐个打开候选，收到固定握手并发送 ACK 后立即选中第一个目标设备并停止遍历。
- 只有当前没有任何 TTY 时，助手才询问是否进行 60 秒拔插枚举诊断。该操作用于区分物理 USB 未枚举和 USB 已枚举但未生成 TTY，不代替握手判断。
- 串口配置固定为 115200、8-N-1、无流控，保存于 `.runtime/config/gateway.toml`。
- 不要使用 `chmod 777`，也不要用 `sudo` 启动网关。账号已加入 `dialout` 但当前会话尚未激活时，启动脚本会尝试通过 `sg` 自动激活一次。

首次配置成功应看到 `Runtime import check: OK`、`Python environment ready`、`Serial setup complete` 和 `runtimeReady=true`。麒麟系统只有 Python 3.8 时，脚本会把锁定的独立 Python 3.11 放入项目 `python-runtime/`，不会替换系统 Python。

## 5. 分步命令（仅用于故障恢复）

正常情况只使用第 1 节的单文件入口。以下命令仅供开发或故障恢复人员单独重试某一步：

```bash
# 初始化 Python，不使用 sudo
./linux/setup-kylin-python.sh

# 检查当前已连接的 USB/串口
sudo ./linux/diagnose-kylin-usb-serial.sh

# 仅在需要观察物理拔插枚举时使用
sudo ./linux/diagnose-kylin-usb-serial.sh --plug-cycle --timeout 60

# 生成项目串口配置
sudo ./linux/setup-kylin-serial.sh

# 启动网关，不使用 sudo
./linux/start-kylin-gateway.sh
```

所有生成内容留在项目中：`.venv/` 保存虚拟环境，`python-runtime/` 保存独立 Python，`wheelhouse/` 保存离线依赖，`.runtime/` 保存配置、日志、录制和诊断。以上目录都已加入 `.gitignore`，不得使用 `git add -f` 强制提交。

## 6. 实时查看日志

程序日志：

```bash
tail -f .runtime/logs/neurobridge.log
```

启动控制台及启动前异常：

```bash
tail -f .runtime/logs/neurobridge-console.log
```

最近 300 行：

```bash
tail -n 300 .runtime/logs/neurobridge.log
```

正常连接应依次出现类似日志：

```text
transport=serial
Serial discovery started
Serial candidate opened
Serial handshake accepted and ACK sent
Serial target selected
Serial control response received: command=start ... success=true
Connection state changed: ... current=connected
Serial capture summary
```

| 日志特征 | 含义 |
|---|---|
| `Serial discovery found no usable candidates` | 当前没有可用 TTY，查看 `byIdEntries`/`ttyACMEntries`/`ttyUSBEntries` |
| `Serial permission preflight` | 启动前检查 TTY、所需组、账号成员关系和当前会话权限 |
| `Unable to open any usable serial candidate` | 所有候选均未成功打开；查看 `lastPath`、`lastErrorType`、`lastReason` |
| `Serial candidate probe failed` | 单个候选打开、配置或读取失败；程序会继续检查下一个候选 |
| `Serial candidate produced no handshake bytes` | 串口已打开，握手窗口内一个字节都没收到 |
| `Serial candidate produced bytes but no valid handshake` | 收到了数据，但不是约定的完整握手 |
| `longestHandshakePrefixBytes=6` | 曾收到前 6 字节一致的内容，可能末字节错误或帧被截断 |
| `ACK sent` | 已识别目标设备并立即回复 ACK |
| `command=start ... success=true` | 发送 `0xE1` 后收到任意非空响应，按成功处理 |
| `Serial control response timeout` | 已发送控制指令，但等待窗口内没有响应 |
| `current=connected` | 网关进入实时采集状态 |
| `frames` 持续增加 | 持续收到有效 28 字节数据帧 |
| `lossRatePercent` | 基于 16 位大端序列号跳号统计的累计丢包率 |
| `Serial invalid frame rejected` | 帧长度或包尾不符合协议 |
| `Serial valid-frame timeout` | 持续没有收到有效数据帧 |
| `Serial reconnect scheduled` | 连接已结束，程序将延时后重新遍历串口 |

日志不写入未知串口的完整原文，也不在错误日志中输出完整生理数据。错误字节和非法帧日志会限频，累计计数仍会增加。

## 7. 常见问题

### 7.1 `/dev/ttyACM*`、`/dev/ttyUSB*` 和 by-id 都为空

重新运行单文件入口并输入 `3`，不要只截图最后一行。

默认直接检测显示“未检测到当前串口节点”时，先查看诊断目录中的当前 USB、接口和驱动快照。如果还需要区分“插入时未枚举 USB”与“USB 已枚举但没有 TTY”，在助手询问时输入 `yes` 执行可选拔插诊断，并查看：

```text
after-lsusb-tree.log
after-usb-interfaces.log
kernel-journal-window.log
udev-monitor.log
dmesg-follow.log
```

确认 USB interface class、绑定驱动和设备是否真正提供串口。麒麟没有生成 TTY 时，NeuroBridge 无法按串口连接。

### 7.2 收到字节，但握手不正确

```bash
grep -E 'no valid handshake|longestHandshakePrefixBytes|unexpected bytes' \
  .runtime/logs/neurobridge.log | tail -n 100
```

如果出现 `produced bytes but no valid handshake`，USB、TTY 和基本读取通常已正常，但实际字节不匹配固定握手。向设备方核对固件版本、实际 USB 接口类型、115200 8-N-1 和设备是否已被其他上位机占用。

### 7.3 串口权限不足

```bash
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null || true
id
```

新版启动脚本会在进入握手前执行权限预检，并优先自动激活已经写入账号的串口组。若日志显示 `accountGroupMember=false`，先执行 `sudo ./linux/setup-kylin-serial.sh`，然后直接重新运行启动脚本；若显示 `accountGroupMember=true` 但自动重启后仍无读写权限，再注销重登或重启系统。

权限不足时，连接错误会保留 `Permission denied` 和具体串口路径，不会再被统一改写成“未收到握手”。只有串口已经成功打开但固定握手未匹配时，才会报告握手错误。

### 7.4 串口被其他程序占用

将节点改为实际路径：

```bash
sudo fuser -v /dev/ttyACM0 2>/dev/null || true
sudo lsof /dev/ttyACM0 2>/dev/null || true
```

确认进程用途后再停止，不要直接结束不认识的系统进程。

### 7.5 启动立即失败

```bash
./.venv/bin/python -m pip check
tail -n 300 .runtime/logs/neurobridge-console.log
tail -n 300 .runtime/logs/neurobridge.log 2>/dev/null || true
```

重点检查 Python 依赖、`.runtime/config/gateway.toml`、串口权限和端口占用。项目默认关闭算法，可先完成 USB 串口原始数据联调；启用算法前必须提供已在当前麒麟环境验证的 bridge。

### 7.6 页面打不开

```bash
ss -lntp | grep -E '127\.0\.0\.1:(8080|8765|8766)' || true
tail -n 200 .runtime/logs/neurobridge-console.log
```

只使用本机浏览器打开 `http://127.0.0.1:8080/`。

## 8. 一键导出完整诊断包

现场无法判断时，在项目根目录执行：

```bash
sudo ./linux/collect-kylin-runtime-diagnostics.sh \
  --journal-lines 10000
```

生成：

```text
.runtime/diagnostics/neurobridge-kylin-runtime-diagnostics-<UTC时间>-<进程号>.tar.gz
.runtime/diagnostics/neurobridge-kylin-runtime-diagnostics-<UTC时间>-<进程号>.tar.gz.sha256
```

校验最新诊断包：

```bash
bundle=$(find .runtime/diagnostics -maxdepth 1 -type f \
  -name 'neurobridge-kylin-runtime-diagnostics-*.tar.gz' \
  -printf '%T@ %p\n' | sort -nr | head -n 1 | cut -d' ' -f2-)
sha256sum -c "$bundle.sha256"
```

诊断包包含系统、内核、USB/TTY、端口、项目版本、Python 依赖和项目 `.runtime/logs` 的日志；不包含配置正文、录制数据、完整生理数据、密码、Token 或私钥。导出前仍要人工检查，只能通过批准的项目内部渠道传递。

## 9. Git 防误提检查

检查运行目录是否被忽略：

```bash
git check-ignore -v .venv .runtime wheelhouse python-runtime
git status --short --ignored
```

不得使用 `git add -f` 添加下列内容：

- `.runtime/config/` 中的现场配置和备份；
- `.runtime/logs/` 中的运行日志；
- `.runtime/recordings/` 中的原始设备数据、算法结果和录制数据；
- `.runtime/diagnostics/` 中的 USB 日志、主机信息和诊断包；
- `.venv/`、`venv/`、`python-runtime/` 和 `wheelhouse/` 中的本地运行环境与依赖包。

正常 `git status --short` 不应显示上述任何运行产物。

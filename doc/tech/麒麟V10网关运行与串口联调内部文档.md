## 1. 当前结论与安全边界

- 物理链路为“头环设备 → USB 线缆/转换板 → 麒麟 V10 主机”。如果 Linux 将 USB 设备枚举为 `/dev/ttyACM*` 或 `/dev/ttyUSB*`，网关按 `serial` 数据源接收；这不等同于原生 USB endpoint 接入。
- 目标主机为 N100/N150 x86_64，最终安装镜像已确定为 `Kylin-Desktop-V10-SP1-2503-HWE-PP-Release-20250430-X86_64.iso`，当前文件 SHA-256 为 `d858e3ac19aa317ab1d2133a6aacbe978662ce9dcc10437119841627a416cc66`。ARM64 和 LoongArch64 银河麒麟 V10 镜像不适用于该主机；详细差异与门禁见[多传输数据源接入 PRD](头环网关多传输数据源接入_PRD.md#02-三个银河麒麟-v10-镜像的差异)。
- 当前仓库运行入口通过设备策略创建 `FlowtimeAdapter`（BLE）或 `SerialAdapter`（USB 派生 TTY），配置中一次只能选择一种。串口源码、单元测试和一键配置脚本已具备，但尚未在最终 N100/N150、目标麒麟镜像和真实耳机上完成 POC，因此只能写“源码支持”，不能写“麒麟串口生产运行已验收”。
- `linux/install-ubuntu.sh`、`linux/prepare-ubuntu24.04-environment.sh` 面向 Ubuntu 24.04 x86_64；麒麟 V10 不应直接执行，需按本文先做手工环境和依赖 POC。
- 算法 bridge 的银河麒麟 V10 x86_64 构建、麒麟内核驱动、USB 转串口芯片型号和 TTL 电平均未在本仓库完成现场验收。
- 默认由同机浏览器通过回环 WebSocket 连接网关，不选择设备传输方式。设备未连接时按既有录播规则提供 `mode="replay"`；串口和访问策略均不改变北向报文版本。

网络与数据安全要求：

- 默认网页、WebSocket 和下载只监听 `127.0.0.1`，不经过物理网卡；浏览器页面使用固定 HTTP Origin，其他 Origin 被拒绝；
- 只有切换 `wired_b_side` 时才使用双方批准的专用有线网络；两种模式都不得暴露公网或不受控网络；
- 不得为了安装或排障把业务接口接入公网、无线网络或不受控局域网；
- 不得在日志、问题单或聊天群中粘贴配置正文、密码、Token、SSH 私钥、完整原始 EEG/HR 或算法输入；
- 原始采集数据和算法结果通过项目受控数据流程交接，不与普通诊断包混装。

- `uname -m` 为 `x86_64`，并能从 `/etc/os-release`、`/etc/kylin-release`、`/etc/.kyinfo` 或 `nkvers` 中至少一个来源确认银河麒麟 V10 构建；`uname -a`/`uname -r` 记录实际运行内核；

- 完成至少一次重启，确认系统可启动且网卡、磁盘和 USB 控制器仍可识别。

### 4.3 离线 Python 依赖包

在与目标机相同银河麒麟构建、x86_64 架构和 Python 小版本的隔离准备环境生成 wheel 目录。保存 `requirements.lock`、全部包、Python 运行时、源码包、生成命令、准备机系统信息和 `SHA256SUMS`。示例：

```bash

python -m pip download --dest wheelhouse -r requirements.lock
```

### 4.4 服务账户和设备权限

使用专用 `neurobridge` 服务账号。串口节点通常可能属于 `dialout`，但必须以目标麒麟 udev 结果为准，不能预设：

```bash
id neurobridge
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null || true
getent group dialout || true
sudo -u neurobridge test -r /dev/ttyACM0 && echo readable
sudo -u neurobridge test -w /dev/ttyACM0 && echo writable
```

不要用 root、`chmod 777` 或关闭安全策略长期绕过权限；应修复最小组权限、udev 规则或 systemd 设备依赖并记录变更。

### 4.5 算法 bridge 门禁

首次麒麟冒烟建议关闭算法。启用前必须在最终镜像：锁定编译器/CMake/Eigen3/SDK/NumCpp；清理其他系统生成的 CMake cache；保存构建日志、二进制 SHA-256 与 `ldd`；使用批准的真实录制数据比对结果和性能。当前 `linux/build-algorithm-bridge.sh` 有 Ubuntu 硬门禁，不能把复制 Ubuntu 二进制或删除门禁当成麒麟验证。

## 5. USB 与串口设备发现

插入前先保存基线：

```bash
date --iso-8601=seconds
lsusb
lsusb -t
ls -l /dev/serial/by-id 2>/dev/null || true
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null || true
```

在一个终端执行 `sudo dmesg --follow`，再插入耳机/转换板；在另一个终端执行：

```bash
lsusb
lsusb -t
ls -l /dev/serial/by-id 2>/dev/null || true
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null || true
udevadm info --query=all --name=/dev/ttyACM0 2>/dev/null || true
udevadm info --attribute-walk --name=/dev/ttyACM0 2>/dev/null || true
```

把示例节点替换为实际新增节点。优先使用 `/dev/serial/by-id/*` 的稳定路径，避免把会随插拔变化的 `/dev/ttyUSB0` 或 `/dev/ttyACM0` 当成设备身份。记录枚举前后节点、VID/PID、序列号、USB 父设备、接口号、驱动、权限和所用物理端口。

检查服务账户权限和占用：

```bash
ls -l /dev/ttyACM0
id neurobridge
sudo -u neurobridge test -r /dev/ttyACM0 && echo readable
sudo -u neurobridge test -w /dev/ttyACM0 && echo writable
sudo fuser -v /dev/ttyACM0 2>/dev/null || true
sudo lsof /dev/ttyACM0 2>/dev/null || true
```

桌面系统可能由 ModemManager 等服务抢占新 TTY。先确认占用进程是否承担其他业务，再针对目标 VID/PID 做最小排除；不要全局卸载、停止未知服务或使用 `chmod 777`。

现场接线参考：[USB 串口转换板接线示意图](assets/头环USB串口转换板接线示意图.png)。图片只用于识别接口标注，不能替代电气和连通性复核。

接线图中有 USB HOST、USB DEVICE/耳机和 TTL `VDD/GND/RX/TX` 三组接口。不得仅凭颜色推断 D+/D− 是否交叉，`VIN`、`VBUS` 和 TTL `VDD` 也不能默认等电位；未确认 TTL 电压前禁止接线，禁止把 TTL `RX/TX` 接到 USB D+/D−。如果 USB 只枚举为 HID/Bulk/Interrupt 而没有 TTY，则它属于原生 USB 路径，不能套用串口流程。

这些电气信息不改变应用层协议，但会决定设备是否安全、是否能枚举以及链路是否稳定。若现场只使用厂家成品 USB 接口和成品线缆、完全不接 TTL 排针，可以把 TTL 电平和 RX/TX 方向标为“不适用”；仍须由设备方确认 USB 供电不反灌、D+ 对 D+、D− 对 D−，并在最终物理端口完成持续采集和插拔测试，不能根据接线图颜色自行交叉 D+/D−。

`lsusb` 有设备但没有 TTY 时，检查 `lsusb -t` 驱动列和内核日志，确认是缺少 `cdc_acm`/USB-Serial 驱动，还是设备本身为 HID/Bulk/Interrupt。禁止通过伪造 TTY 或套用串口参数绕过原生 USB 适配器开发。

## 6. 已确认的串口联调流程

以下内容来自设备方协议沟通记录；固定握手、单字节启停、大端序列号和现有算法原始输入映射已确认，真实链路行为仍须在目标麒麟机 POC。

| 项目 | 当前值 |
|---|---|
| 端口参数 | 115200 baud，8-N-1，无流控 |
| 未连接状态 | 耳机名义上每 200 ms 发送固定握手；网关不校验周期精度，单候选默认等待 1000 ms |
| 握手/ACK | 固定 7 字节 `AA 55 01 01 01 01 6F`；只做完整相等匹配，收到后立即回同值 ACK |
| 开启脑电 | 直接发送单字节 `0xE1`；配置超时内收到任意非空响应即成功，不解析响应内容；首个有效帧进一步证明实际出数 |
| 停止脑电 | 直接发送一次单字节 `0xE0`；配置超时内收到任意非空响应即成功，超时记录失败后仍关闭端口 |
| 数据帧 | 28 字节：`AA AA AA` + `0x1C` + 2 字节大端序号 + 6 个 3 字节脑电值 + 1 字节心率 + `BB BB BB`；序号以首帧为基线并逐帧 `+1`，`0xFFFF → 0x0000` |
| 算法映射 | 偏移 4～23 的 20 字节作为现有 EEG 原始输入，偏移 24 的 1 字节作为现有 HR 原始输入；不重采样、缩放或重编码 |
| 丢包率 | `expected = 扩展最高序列 - 基线 + 1`，`lost = max(0, expected - receivedUnique)`，`lossRate = lost / expected × 100%`；重复不增加唯一接收数，有限窗口乱序补包可修正累计丢包 |

多串口处理必须遵循以下顺序：

1. 只枚举 USB 派生的候选 TTY，按 `/dev/serial/by-id/`、物理路径和接口号形成稳定顺序；不要遍历波特率或发送未知控制字节。
2. 按顺序逐个打开候选端口，只读并完整匹配固定握手；单候选默认超时 1000 ms，不验证 200 ms 周期精度，也不并行探测。
3. 首个候选收到完整握手后，立即向该端口返回同值 ACK；ACK 不等待算法初始化。保留该端口并立刻停止遍历，未打开的候选不再探测。
4. 一轮零个通过时记录超时并按配置重试当前传输。本期现场必须只连接一台目标耳机；若违规连接多个相同设备，只会选中稳定排序中第一个握手端口，不提供消歧能力。
5. 算法初始化后发送一次单字节 `0xE1`，配置超时内收到任意非空响应即成功；响应原文不写日志。超时则关闭当前端口并按配置重新发现。响应成功后以首个有效 28 字节帧确认实际出数。读取帧时校验包头、长度和包尾，序号按大端无符号值检查递增/回绕；异常只记录摘要和计数，不改写原始数据。
6. 完整 28 字节帧原样持久化；偏移 4～23 和偏移 24 分别进入现有 EEG/HR 算法输入。停止且设备仍在线时发送一次单字节 `0xE0` 并按同一口径等待响应；响应超时或设备已拔出仍关闭端口并释放句柄，不阻塞服务退出。
7. 每 10 秒（可配置）和断开时输出累计/区间丢包、重复、乱序、迟到、非法帧、丢弃字节和控制响应统计。持续收到无效字节不能刷新有效帧超时。

当前源码已实现上述串口适配器和自动配置入口；真实硬件、驱动、接线、设备响应、算法结果和长稳仍须在目标麒麟机填写 POC/验收证据。

串口日志记录发现轮次、候选数量、候选路径、各阶段耗时、首个握手目标、ACK、单候选超时、全轮零目标、有效帧、长度/头尾错误、序号期望/实际值、累计/区间丢包、重枚举、控制响应长度/耗时和句柄释放；不得记录控制响应原文、完整 EEG/HR 帧或算法输入。受控串口 POC 必须先确认打开端口时的 DTR/RTS 行为，避免设备意外复位。

配置规则：

- 默认 `local_browser` 强制网页、WebSocket 和下载绑定 `127.0.0.1`，并禁止配置专用网卡、子网或 DHCP；
- 网页地址为 `http://127.0.0.1:8080/`，WebSocket 地址由服务动态注入为 `ws://127.0.0.1:8765/neurobridge/v1/ws`；
- 本机 WebSocket 只接受上述网页 Origin；不要双击 `file://` 作为生产运行方式；
- 旧配置缺少 `access.mode` 时，非回环私网 `server.host` 会推断为 `wired_b_side` 以保持兼容；完成升级后仍应显式补写策略；
- 下载接口无鉴权，但本机模式仅回环可访问；切换旧有线模式时仍须专网隔离；
- `[data_source].type = "serial"` 启用 USB 派生 TTY 策略，`"bluetooth"` 切回 BLE；修改后必须重启服务，一次只能选择一种；
- `serial.device = "auto"` 只遍历 `/dev/serial/by-id/`、`ttyACM*` 和 `ttyUSB*` 候选；识别稳定路径后也可填写绝对路径，不要写易变化编号作为未经验证的固定值；
- `command_response_timeout_ms` 同时用于 `0xE1`/`0xE0`：任意非空响应即成功，超时失败；不要根据未定义内容判断成功；
- 算法 bridge 未完成麒麟构建和真实数据验证前保持关闭；
- 配置只允许 root 写、服务账户读；问题单只记录 SHA-256，不粘贴正文。


#### 7.4.1 一键启用串口策略（推荐）

完成源码/运行环境安装、确认 `/etc/neurobridge/gateway.toml` 存在后，在当前已审核源码目录执行一条命令：

```bash
sudo ./linux/setup-kylin-serial.sh
```

脚本会验证银河麒麟 x86_64 和 `pyserial`，为当前配置生成带 UTC 时间的备份，原子写入 `[data_source]`/`[serial]`，自动列出 USB 派生 TTY 候选，把 `neurobridge` 服务账户加入候选设备所属串口组，复核配置，然后启用并重启服务。它保留服务地址、录制、算法、日志和其他已有配置，不写入设备数据。重复执行不会产生重复配置段，但每次仍会保留一份回退备份。

需要固定现场已确认的稳定节点时使用：

```bash
sudo ./linux/setup-kylin-serial.sh --device /dev/serial/by-id/<已确认设备>
```

```bash

```

若脚本失败，它会以非零退出并打印简短原因；不要手工放宽到 `chmod 777`。根据输出检查运行环境、`pyserial`、配置文件和设备组权限。配置备份路径会在成功输出的 `backup=` 行显示。

### 7.5 选择前端访问策略

#### 7.5.1 默认本机浏览器

#### 7.5.2 切换旧有线 B 端

## 8. systemd 安装、启动与分层验证

服务单元应在设备节点、网络和权限完成现场确认后落地。设备依赖可以使用 `/dev/serial/by-id/...` 对应的 systemd 转义名，但必须由 `systemd-escape -p --suffix=device` 生成，不能手写猜测。

```ini
[Unit]
Description=NeuroBridge gateway (Kylin V10 POC)
After=network-online.target
Wants=network-online.target
# 串口节点确认后再增加：
# Requires=dev-serial-by\x2did-<stable-name>.device
# After=dev-serial-by\x2did-<stable-name>.device

[Service]
Type=simple
User=neurobridge
Group=neurobridge
Environment=PYTHONUNBUFFERED=1
ExecStart=/opt/neurobridge/venv/bin/neurobridge --config /etc/neurobridge/gateway.toml
Restart=always
RestartSec=3
UMask=0027
NoNewPrivileges=yes
PrivateTmp=yes
ProtectSystem=strict
ProtectHome=yes
ReadWritePaths=/var/lib/neurobridge /var/log/neurobridge

[Install]
WantedBy=multi-user.target
```

当前仓库单元对设备传输保持中立；串口策略不依赖 `bluetooth.target`，BLE 策略由适配器在 BlueZ 未就绪时记录失败并重试。复制前复核 `ExecStart`、用户、目录和安全项：

```bash
sudo install -m 0644 /opt/neurobridge/linux/systemd/neurobridge.service \
  /etc/systemd/system/neurobridge.service
sudo install -m 0644 /opt/neurobridge/linux/logrotate/neurobridge \
  /etc/logrotate.d/neurobridge
sudo systemd-analyze verify /etc/systemd/system/neurobridge.service
sudo logrotate --debug /etc/logrotate.d/neurobridge
sudo systemctl daemon-reload
sudo systemctl enable neurobridge.service
sudo systemctl start neurobridge.service
```

不要为了快速验证删除 `NoNewPrivileges`、`ProtectSystem`、`ProtectHome` 或网络隔离。自定义录制/日志目录时必须同步更新目录权限和 `ReadWritePaths`。

### 8.1 首次启动检查

```bash

sudo journalctl -u neurobridge.service -b -n 300 --no-pager -o short-iso-precise
```

服务应为 `active (running)`，日志应出现应用版本、Python、`arch=x86_64`、配置 SHA-256、`accessMode`、网页地址和 WebSocket 监听地址。如果端口已占用，先识别冲突业务，不得直接结束未知进程。

### 8.2 无设备与录播冒烟

保持 `data_source.type = "serial"`、`ble.enabled = false`、算法关闭且不连接设备时：

1. 没有设备也不应导致主进程退出；
2. 在同机浏览器访问 `http://127.0.0.1:8080/`，页面自动使用子协议 `neurobridge.v1` 连接并先调用 `getStatus`；
3. 有批准的非空录制会话时，`getLatest` 或 `subscribe` 自动回放并输出 `mode="replay"`；
4. 录播按已保存时间间隔发送且不重新计算算法；
5. 浏览器断线重连后先 `getStatus`，再重新订阅，旧 `subscriptionId` 不可复用；
6. 服务重启后 `gatewayBootId` 改变，WebSocket 继续接受新连接。

安全负向检查：使用 `file://`、`http://localhost:8080`、其他端口或外部网页连接回环 WebSocket，应因 Origin 不匹配被拒绝；使用错误 Host 请求本机 HTTP 页面也应被拒绝。旧有线策略不启动 `8080` 本机网页服务。

### 8.4 串口实时验证

先执行第 7.4.1 节的一键配置，连接一台目标耳机，再实时查看日志：

## 9. 运行日志与取证

网关日志同时写入 systemd journal 和 `/var/log/neurobridge/neurobridge.log`。应用文件日志使用 UTC ISO 时间并保留毫秒，格式包含进程 PID、级别、logger 和消息，便于与设备时间戳、B 端日志及诊断包对齐。推荐命令：

```bash
journalctl -u neurobridge.service -b --no-pager
journalctl -u neurobridge.service -f
tail -n 200 /var/log/neurobridge/neurobridge.log
```

### 9.1 日志内容和级别

默认 `INFO` 日志应能定位：

- 进程启动：应用版本、PID、Python、平台、CPU 架构、内核、配置路径及配置文件 SHA-256；只记录哈希，不记录配置内容；
- 安全配置摘要：当前传输、扫描/重连参数、北向和下载监听地址、网络模式与接口、录制目录、算法开关/可执行文件、日志级别与路径；不记录 `subjectId`、密码或密钥；
- 设备接入：连接状态变化、BLE 扫描轮次、发现/匹配数量、阶段、耗时、RSSI、通知订阅、启停命令、断开、异常类型和重连计划；
- 串口接入：候选串口数量/路径、探测阶段、首个握手目标/单候选超时/全轮零目标、ACK、`0xE1`/`0xE0` 响应字节数/耗时/成功状态、分帧和序号错误、累计/区间丢包、重复/乱序/迟到、无有效帧超时、重枚举和重连；禁止记录控制响应原文和完整原始帧；
- 数据采集：录制标识、EEG/HR 包数与字节数、长度异常数、窗口数、无效窗口数、首末包时间、采集时长、算法状态、客户端及订阅数；约 10 秒输出一次汇总；
- 算法 bridge：初始化、进程 PID、停止返回码、单窗口耗时、输出字段名、异常类型和原因；不记录算法输入 Base64 或结果值；
- 北向与导出：WebSocket 客户端、请求动作/requestId、订阅、录播、错误码、下载来源、路径、文件大小及中断；
- 进程退出：关闭开始/完成、进程运行时长、最终采集汇总和未处理异常栈。

需要复现偶发问题时，可临时将 `/etc/neurobridge/gateway.toml` 中的日志级别改为：

```toml
[logging]
level = "DEBUG"
```

随后重启服务并立即复现：

```bash
sudo systemctl restart neurobridge.service
sudo journalctl -u neurobridge.service -f -o short-iso-precise
```

`DEBUG` 会额外记录每个 600 ms 窗口、WebSocket 文本帧字节数和算法窗口耗时，但仍不得记录完整业务载荷。DEBUG 日志增长更快，只在受控复现窗口使用；诊断包导出后恢复 `INFO` 并再次重启服务。

日志禁止包含：完整脑电/心率原始字节、完整 Base64 载荷、个人敏感信息、密码、Token、私钥。采集统计只记录包数、窗口数、字节长度、时间范围、错误原因和会话/录制标识。

串口周期汇总字段可直接用于问题单，无需在设备上临时写分析脚本：

| 字段 | 含义 |
|---|---|
| `expectedPackets` / `receivedUniquePackets` | 从连接首帧到扩展最高序列的累计期望包数 / 唯一接收包数 |
| `lostPackets` / `lossRatePercent` | 累计丢包数 / 累计丢包率；`lost=max(0, expected-receivedUnique)` |
| `intervalExpectedPackets` / `intervalReceivedUniquePackets` | 本日志周期相对上一快照新增的期望包 / 唯一接收包 |
| `intervalLostPackets` / `intervalLossRatePercent` | 本周期未收到包数 / 区间丢包率；用来判断问题是否仍在发生 |
| `duplicates` / `outOfOrder` / `late` | 累计重复、有限窗口乱序补包、超过窗口迟到包 |
| `invalidFrames` / `discardedBytes` / `bufferOverflows` | 分帧失败、为重新同步丢弃的字节、接收缓冲截断次数 |
| `controlResponses` / `controlResponseBytes` / `controlTimeouts` | 控制响应次数、总字节数、超时次数；不含响应原文 |

### 9.2 无 Codex 环境的一键诊断包

N100/N150 现场机不需要安装 Codex，也不需要联网。复现问题后在项目目录运行：

```bash
sudo ./linux/collect-kylin-runtime-diagnostics.sh \
  --output-dir /tmp \
  --journal-lines 10000
```

命令会输出两个文件，时间戳和进程号每次不同：

```text
/tmp/neurobridge-kylin-runtime-diagnostics-<UTC时间>-<PID>.tar.gz
/tmp/neurobridge-kylin-runtime-diagnostics-<UTC时间>-<PID>.tar.gz.sha256
```

诊断包包含：

| 分类 | 内容 |
|---|---|
| 系统与硬件 | 银河麒麟版本、构建/内核、时钟、N100/N150 CPU、内存、磁盘、BIOS/主板型号和资源占用 |
| 运行依赖 | Python、systemd、glibc、CMake、编译器、系统包、虚拟环境 Python 包和算法 bridge 动态库依赖 |
| 部署身份 | 当前源码 revision/status，配置、服务文件和二进制的路径、权限、mtime、大小及 SHA-256；配置只取元数据和哈希 |
| 服务与日志 | systemd 状态/重启计数/退出码/资源、当前与上一次启动的 service/kernel journal、应用当前及轮转日志、失败单元和 core dump 列表 |
| USB/串口/蓝牙 | `lsusb`、USB 拓扑、内核模块、`ttyACM*`/`ttyUSB*` 权限、udev 属性、占用进程、rfkill 和蓝牙控制器状态 |
| 网络 | 网卡、私有地址、路由、邻居、监听端口及 nftables/iptables 状态，用于定位 WebSocket 和日志下载不可达 |

诊断包会包含主机名、私有 IP、USB VID/PID/序列属性、文件路径和运行日志，这些不是公开资料。只能在项目批准的受控渠道传递，不得上传公开网盘、公共 Issue 或聊天群。

### 9.3 校验和导出方法

先定位最新诊断包并校验完整性：

```bash
bundle=$(ls -1t /tmp/neurobridge-kylin-runtime-diagnostics-*.tar.gz | head -n 1)
sudo sha256sum -c "$bundle.sha256"
sudo tar -tzf "$bundle" | less
```

推荐按现场条件选择一种导出方式：

1. **受控 U 盘**：先用 `lsblk -f` 确认 U 盘和挂载目录，再复制诊断包及 `.sha256`，执行 `sync` 后安全卸载。不要把文件复制到未确认的系统盘或其他业务磁盘。
2. **已批准的 SSH/SCP**：只有现场已建立受限 SSH 运维入口时，才从批准的运维电脑拉取 `/tmp` 下这两个文件；不得为了传日志临时开放公网、通配监听或新账户。
3. **应用日志轻量下载**：如果只需要 NeuroBridge 应用文件日志且 `[download]` 已启用，默认在同机浏览器下载；旧有线策略才允许从批准的专网 B 端下载：

   ```text
   http://127.0.0.1:<下载端口>/downloads/logs/neurobridge-logs.zip
   ```

   该 ZIP 只含 `/var/log/neurobridge/*.log*` 和清单，不包含 journal、内核、USB/TTY、驱动、网络或依赖信息，不能替代完整诊断包。

若脚本无法执行，至少手工保存以下输出；每条命令都应记录执行时间和退出码：

```bash
cat /etc/os-release
cat /etc/kylin-release 2>/dev/null || true
sudo grep -Ei '^[[:space:]]*(name|milestone|arch|version|release|build|buildid|time|dist_id)[[:space:]]*=' /etc/.kyinfo 2>/dev/null || true
command -v nkvers >/dev/null 2>&1 && nkvers
uname -a
sudo systemctl status neurobridge.service --no-pager -l
sudo journalctl -u neurobridge.service -b -n 5000 --no-pager -o short-iso-precise
sudo journalctl -k -b -n 5000 --no-pager -o short-iso-precise
lsusb

ls -l /dev/ttyACM* /dev/ttyUSB* 2>&1
ip -brief address
ss -lntup
```

## 10. 常见故障

服务无法启动或反复重启时，先保存第一次失败证据：

```bash
sudo systemctl status neurobridge.service --no-pager -l
sudo journalctl -u neurobridge.service -b -n 500 --no-pager -o short-iso-precise
sudo systemctl show neurobridge.service \
  -p ActiveState -p SubState -p Result -p ExecMainCode -p ExecMainStatus -p NRestarts
```

依次检查虚拟环境、`pip check`、配置解析、监听 IP、端口占用、目录权限、systemd `ReadWritePaths` 和算法动态库。不要只反复执行 `restart`。

| 现象 | 检查 | 处理 |
|---|---|---|
| Python 低于 3.11 | Python 路径、venv 的 `pyvenv.cfg` | 安装独立受控 Python 并重建 venv；不替换系统 Python |
| `ModuleNotFoundError` | `pip freeze`、`pip check`、离线包哈希 | 用同系统/架构/Python 的离线包重建，不临时公网补包 |
| `Cannot assign requested address` | `ip -br addr`、配置中的 host | 先把批准静态 IP 配到专用网卡，再启动服务 |
| `Address already in use` | `ss -lntp` | 识别冲突业务；地址或端口变更需双方确认 |
| 日志/录制写入失败 | 属主、权限、磁盘、`ReadWritePaths` | 修复最小权限和容量，不使用 `chmod 777` |
| BLE 控制器不可见 | `lsusb`、BlueZ、rfkill、kernel journal | 核对驱动/固件/权限并固定适配器与物理端口 |
| 没有 `/dev/ttyACM*`/`ttyUSB*` | `lsusb`、`dmesg`、供电和线缆 | 确认 USB 角色、驱动和转换板是否实际呈现 TTY；若为原生 USB，转入 USB 适配器方案 |
| 有节点但权限不足 | `ls -l`、`id neurobridge`、journal | 修复组/udev 权限，重新登录或重启服务 |
| 串口被占用 | `fuser`、`lsof`、ModemManager | 先确认业务归属，再为目标 VID/PID 做最小排除，不全局停未知服务 |
| 同时连接多个目标设备 | 稳定路径、VID/PID、物理连线 | 本期不支持消歧；只保留一台目标耳机后重试，禁止把首个握手选择当作多设备能力 |
| 握手超时 | 端口参数、默认 1000 ms 窗口、USB/驱动、读超时、线序 | 只读抓取并与固定握手比对；不得校验 200 ms 周期精度或盲目改波特率 |
| `0xE1` 响应超时 | `command=start` 的 `timeoutMs`/`durationMs`/`success`、USB/串口是否拔出 | 任意非空响应即成功，不比对内容；超时由适配器关闭并重连，保留首次失败日志和诊断包 |
| `0xE1` 响应成功但无数据 | ACK、控制响应、`No valid serial data frame`、设备佩戴状态、包头/长度/包尾 | 响应只证明有回包，首个有效帧才证明实际出数；核对设备固件和数据帧，不把垃圾字节当作在线 |
| 丢包率偏高 | 汇总中的累计/区间丢包、重复/乱序/迟到、非法帧/丢弃字节、USB 内核日志 | 先用区间值判断是否持续发生，再对齐同一时间段 USB/TTY 日志；不要用总读取字节代替有效帧，也不要在未确认前修改波特率 |
| 数据帧长度/头尾异常 | 日志中的 `channel`、`bytes`、错误原因 | 保留原始文件供受控分析，修正分帧实现，不在日志中打印原始内容 |
| 算法 bridge 不可用 | bridge 启停日志、x86_64 架构、动态库 | 在最终银河麒麟镜像上重新构建并核对 glibc/C++ 依赖，再使用真实数据判定算法 POC |
| 本机网页打不开 | `systemctl`、`accessMode`、`ss`、8080 端口、UI 资源路径 | 确认使用 `http://127.0.0.1:8080/`，服务只监听回环且资源目录完整 |
| 网页能开但 WebSocket 被拒绝 | 浏览器 Origin、动态 endpoint、8765 监听和日志 | 必须从批准的回环 HTTP 页面访问；不要使用 `file://`、`localhost` 别名或外部网页 |
| 旧 B 端不可达 | `access.mode`、监听地址、专用网卡和静态 IP | 仅在 `wired_b_side` 下检查专网；不将网关接入公网或其他网络 |
| 录播没有数据 | 会话目录、权限、会话是否非空、选择日志 | 使用批准的完整会话，核对自动或固定会话选择结果 |
| 日志磁盘增长 | DEBUG、轮转状态、磁盘空间 | 恢复 INFO，验证 logrotate 和容量告警，受控归档 |

## 11. 停机、升级与回滚

### 11.1 正常停机

```bash
sudo systemctl stop neurobridge.service
sudo systemctl is-active neurobridge.service
sudo journalctl -u neurobridge.service -n 100 --no-pager -o short-iso-precise
```

确认日志出现关闭开始/完成。B 端会断开，服务恢复后必须重新连接、调用 `getStatus` 并重新订阅。

### 11.2 升级前门禁

- 新源码/发布包有审核记录和 commit/SHA-256；
- 已生成升级前诊断包，备份配置、必要录制数据和当前运行版本；
- 新依赖包与最终麒麟、x86_64 和 Python 小版本匹配；
- 已确认维护窗口、B 端断线影响、回归范围和上一稳定版本回滚包；
- 如果涉及算法，源码、依赖和 bridge 二进制作为一套版本管理；
- 如果涉及设备、算法或网络依赖，计划覆盖实时、录播、设备断线重连、浏览器/客户端断开与恢复；默认验证同机浏览器，只有 `wired_b_side` 才验证独立 B 端和专网恢复。

麒麟专用更新脚本完成前，不执行 `linux/update-ubuntu.sh`。手工升级先停服务，在受控暂存目录验证依赖，再同步应用文件；不得覆盖 `/etc/neurobridge/gateway.toml`、录制或日志目录。

### 11.3 升级后验证

```bash
sudo systemctl daemon-reload
sudo systemctl restart neurobridge.service
sudo systemctl status neurobridge.service --no-pager -l
sudo journalctl -u neurobridge.service -b -n 300 --no-pager -o short-iso-precise
sha256sum /etc/neurobridge/gateway.toml
```

至少回归：启动、`getStatus`、录播、实际使用的设备传输、算法、B 端断线重连、日志轮转、诊断包和服务重启。

### 11.4 回滚原则

服务无法稳定启动、配置不兼容、设备无法连接、解析异常、算法结果不一致、录播不可用、北向行为不兼容或资源持续异常时，停止扩大影响并回滚。必须成套恢复源码、Python 依赖和算法 bridge，不能只替换单个 Python 文件；配置发生迁移时恢复匹配版本。回滚后重复升级后检查，并保留失败版本的诊断包、构建日志和复现步骤。

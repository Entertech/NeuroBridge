# 麒麟 V10 网关运行与串口联调内部文档

状态：内部运行/联调手册（未代表现场验收通过）  
适用分支：`codex/serial-usb-transport` 及其后续集成分支  
维护对象：NeuroBridge 网关、设备接入和部署工程师

> 本文用于麒麟 V10 主机的环境核对、串口诊断和运行日志定位。它不是 B 端北向协议，也不替代设备方最终签字的串口协议。文中“已确认”仅表示当前项目记录中的协议结论；“源码支持”“POC 已验证”和“现场验收通过”必须分开填写。

## 1. 当前结论与边界

- 物理链路为“头环设备 → USB 线缆/转换板 → 麒麟 V10 主机”。如果 Linux 将 USB 设备枚举为 `/dev/ttyACM*` 或 `/dev/ttyUSB*`，网关按 `serial` 数据源接收；这不等同于原生 USB endpoint 接入。
- 目标主机为 N100/N150 x86_64，当前唯一候选镜像为 `Kylin-Desktop-V10-SP1-2503-HWE-PP-Release-20250430-X86_64.iso`。ARM64 和 LoongArch64 银河麒麟 V10 镜像不适用于该主机；详细差异与门禁见[多传输数据源接入 PRD](头环网关多传输数据源接入_PRD.md#02-三个银河麒麟-v10-镜像的差异)。
- 当前仓库运行入口仍固定创建 `FlowtimeAdapter`（BLE）。串口适配器和配置枚举尚未合入，不能把当前源码描述为“已支持麒麟串口生产运行”。
- `linux/install-ubuntu.sh`、`linux/prepare-ubuntu24.04-environment.sh` 面向 Ubuntu 24.04 x86_64；麒麟 V10 不应直接执行，需按本文先做手工环境和依赖 POC。
- 算法 bridge 的银河麒麟 V10 x86_64 构建、麒麟内核驱动、USB 转串口芯片型号和 TTL 电平均未在本仓库完成现场验收。
- B 端只连接网关 WebSocket，不选择传输方式。设备未连接时，网关按既有录播规则提供 `mode="replay"`；串口联调不改变北向报文版本。

## 2. 麒麟主机前置检查

在专用隔离网络和现场授权窗口内执行，保存命令输出（不上传包含个人信息或原始脑电数据的日志）。

```bash
cat /etc/os-release
uname -a
uname -m
python3 --version
systemctl --version
lsusb
ip -br addr
```

记录以下信息：N100/N150 具体型号和硬件清单、镜像完整文件名与 SHA-256、银河麒麟版本/构建号、内核版本、`uname -m`（必须为 `x86_64`）、Python 版本、systemd 版本、USB 转串口 VID/PID、网关网卡名和静态地址。若架构不是 `x86_64`，立即停止安装或部署核对；不得改用已下载的 ARM64/LoongArch64 镜像绕过。

## 3. 软件和权限准备

1. 准备 Python `>=3.11`、`venv` 模块和编译工具；依赖版本以仓库锁定文件和实际发布包为准（当前 POC 使用 `bleak==0.19.0`、`websockets==12.0`）。
2. 优先使用经过校验的离线 wheel/软件源。在专用隔离网络中禁止为了排障临时访问公网或切换到不受控局域网。
3. 使用专用服务账号（例如 `neurobridge`），将该账号加入设备节点对应的组（通常为 `dialout`，以麒麟实际 udev 规则为准）。重新登录或重启服务后再验证权限：

   ```bash
   id neurobridge
   test -r /dev/ttyACM0 && test -w /dev/ttyACM0
   ```

4. 不要用 `sudo` 长期运行网关来绕过权限问题；应修复 udev 规则、组权限或 systemd 设备依赖，并在日志中记录变更。

## 4. USB 与串口设备发现

插入耳机/转换板后执行：

```bash
ls -l /dev/serial/by-id 2>/dev/null || true
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null || true
udevadm info --query=all --name=/dev/ttyACM0 2>/dev/null || true
dmesg --follow
```

优先使用 `/dev/serial/by-id/*` 的稳定路径，避免把会随插拔变化的 `/dev/ttyUSB0` 或 `/dev/ttyACM0` 当成设备身份。记录枚举前后节点、VID/PID、序列号、驱动和权限。

现场接线参考：[USB 串口转换板接线示意图](assets/头环USB串口转换板接线示意图.png)。图片只用于识别接口标注，不能替代电气和连通性复核。

接线图中有 USB HOST、USB DEVICE/耳机和 TTL `VDD/GND/RX/TX` 三组接口。不得仅凭颜色推断 D+/D− 是否交叉，`VIN`、`VBUS` 和 TTL `VDD` 也不能默认等电位；未确认 TTL 电压前禁止接线，禁止把 TTL `RX/TX` 接到 USB D+/D−。如果 USB 只枚举为 HID/Bulk/Interrupt 而没有 TTY，则它属于原生 USB 路径，不能套用串口流程。

## 5. 已确认的串口联调流程

以下内容来自设备方协议沟通记录；帧字段、校验和响应细节仍以设备方最终版本为准。

| 项目 | 当前值 |
|---|---|
| 端口参数 | 115200 baud，8-N-1，无流控 |
| 未连接状态 | 耳机周期性发送握手帧，周期 200 ms |
| 握手/ACK | `AA 55 01 01 01 01 6F` |
| 开启脑电 | `0xE1` |
| 停止脑电 | `0xE0` |
| 数据帧 | 28 字节：`AA AA AA` + `0x1C` + 2 字节序号 + 6 个 3 字节脑电值 + 1 字节心率 + `BB BB BB` |

多串口处理必须遵循以下顺序：

1. 只枚举 USB 派生的候选 TTY，并按稳定路径去重；不要遍历波特率或发送未知控制字节。
2. 对每个候选端口只读并校验握手，设置明确的打开、读取和握手超时。
3. 每当候选端口收到完整握手帧，立即向该端口返回同值 ACK；ACK 不等待算法初始化。探测结束后仅当恰好一个候选通过握手，才将其作为目标继续初始化并发送 `0xE1`。
4. 零个通过时记录超时并按配置重试当前传输；多个通过时记录候选数量和稳定路径，不再发送 `0xE1`、`0xE0` 或订阅指令并要求现场排除歧义。由于 ACK 已按握手即时发送，后续复位/重新上电规则须由设备方确认。
5. 读取 28 字节帧时先校验包头、长度、序号和包尾；非法帧只记录通道、字节数和错误原因，不记录完整原始字节。
6. 停止或断线时尽力发送 `0xE0`，关闭端口并释放句柄；重连只重试当前选择的串口数据源。

当前运行入口尚未实现上述串口适配器，因此本节是联调基线，不是现有版本可直接执行的生产功能。

## 6. 麒麟 V10 手工运行模板

以下命令仅用于已完成依赖安装和配置审查后的 POC。配置路径、安装目录和用户需按现场替换，不要直接复制 Ubuntu systemd 单元。

```bash
cd /opt/neurobridge
python3 -m venv venv
. venv/bin/activate
python -m pip install --no-index --find-links /opt/neurobridge/wheels -r requirements.txt
python -m neurobridge --config /etc/neurobridge/gateway.toml
```

当前配置仍使用 `[ble]` 段和 BLE 入口；串口配置段只有在串口适配器实现并完成评审后才能启用。若算法 bridge 未准备好，可在 POC 配置中关闭算法，但应在验收记录中注明算法输出不可用。

## 7. systemd 运行模板（内部草案）

服务单元应在设备节点、网络和权限完成现场确认后落地。设备依赖可以使用 `/dev/serial/by-id/...` 对应的 systemd 转义名，但必须由 `systemd-escape -p --suffix=device` 生成，不能手写猜测。

```ini
[Unit]
Description=NeuroBridge gateway (Kylin V10 POC)
After=network-online.target
Wants=network-online.target
# 串口节点确认后再增加：
# Requires=dev-serial-by\x2did-<stable-name>.device
# After=dev-serial-by\x2did-<stable-name>.device

[Service]
Type=simple
User=neurobridge
Group=neurobridge
Environment=PYTHONUNBUFFERED=1
ExecStart=/opt/neurobridge/venv/bin/neurobridge --config /etc/neurobridge/gateway.toml
Restart=always
RestartSec=3
UMask=0027
NoNewPrivileges=yes
PrivateTmp=yes
ProtectSystem=strict
ProtectHome=yes
ReadWritePaths=/var/lib/neurobridge /var/log/neurobridge

[Install]
WantedBy=multi-user.target
```

启用前运行 `systemd-analyze verify /etc/systemd/system/neurobridge.service`，再用 `systemctl status neurobridge.service` 确认退出原因。不要为了快速验证关闭 `NoNewPrivileges`、`ProtectSystem` 或网络隔离。

## 8. 运行日志与取证

网关日志同时写入 systemd journal 和 `/var/log/neurobridge/neurobridge.log`。应用文件日志使用 UTC ISO 时间并保留毫秒，格式包含进程 PID、级别、logger 和消息，便于与设备时间戳、B 端日志及诊断包对齐。推荐命令：

```bash
journalctl -u neurobridge.service -b --no-pager
journalctl -u neurobridge.service -f
tail -n 200 /var/log/neurobridge/neurobridge.log
```

### 8.1 日志内容和级别

默认 `INFO` 日志应能定位：

- 进程启动：应用版本、PID、Python、平台、CPU 架构、内核、配置路径及配置文件 SHA-256；只记录哈希，不记录配置内容；
- 安全配置摘要：当前传输、扫描/重连参数、北向和下载监听地址、网络模式与接口、录制目录、算法开关/可执行文件、日志级别与路径；不记录 `subjectId`、密码或密钥；
- 设备接入：连接状态变化、BLE 扫描轮次、发现/匹配数量、阶段、耗时、RSSI、通知订阅、启停命令、断开、异常类型和重连计划；
- 串口接入实现后：候选串口数量、稳定设备属性、探测阶段、握手成功/超时/多目标结果、ACK、分帧错误、重枚举和重连；禁止记录完整原始帧；
- 数据采集：录制标识、EEG/HR 包数与字节数、长度异常数、窗口数、无效窗口数、首末包时间、采集时长、算法状态、客户端及订阅数；约 10 秒输出一次汇总；
- 算法 bridge：初始化、进程 PID、停止返回码、单窗口耗时、输出字段名、异常类型和原因；不记录算法输入 Base64 或结果值；
- 北向与导出：WebSocket 客户端、请求动作/requestId、订阅、录播、错误码、下载来源、路径、文件大小及中断；
- 进程退出：关闭开始/完成、进程运行时长、最终采集汇总和未处理异常栈。

需要复现偶发问题时，可临时将 `/etc/neurobridge/gateway.toml` 中的日志级别改为：

```toml
[logging]
level = "DEBUG"
```

随后重启服务并立即复现：

```bash
sudo systemctl restart neurobridge.service
sudo journalctl -u neurobridge.service -f -o short-iso-precise
```

`DEBUG` 会额外记录每个 600 ms 窗口、WebSocket 文本帧字节数和算法窗口耗时，但仍不得记录完整业务载荷。DEBUG 日志增长更快，只在受控复现窗口使用；诊断包导出后恢复 `INFO` 并再次重启服务。

日志禁止包含：完整脑电/心率原始字节、完整 Base64 载荷、个人敏感信息、密码、Token、私钥。采集统计只记录包数、窗口数、字节长度、时间范围、错误原因和会话/录制标识。

### 8.2 无 Codex 环境的一键诊断包

N100/N150 现场机不需要安装 Codex，也不需要联网。复现问题后在项目目录运行：

```bash
sudo ./linux/collect-kylin-runtime-diagnostics.sh \
  --output-dir /tmp \
  --journal-lines 10000
```

命令会输出两个文件，时间戳和进程号每次不同：

```text
/tmp/neurobridge-kylin-runtime-diagnostics-<UTC时间>-<PID>.tar.gz
/tmp/neurobridge-kylin-runtime-diagnostics-<UTC时间>-<PID>.tar.gz.sha256
```

诊断包包含：

| 分类 | 内容 |
|---|---|
| 系统与硬件 | 银河麒麟版本、构建/内核、时钟、N100/N150 CPU、内存、磁盘、BIOS/主板型号和资源占用 |
| 运行依赖 | Python、systemd、glibc、CMake、编译器、系统包、虚拟环境 Python 包和算法 bridge 动态库依赖 |
| 部署身份 | 当前源码 revision/status，配置、服务文件和二进制的路径、权限、mtime、大小及 SHA-256；配置只取元数据和哈希 |
| 服务与日志 | systemd 状态/重启计数/退出码/资源、当前与上一次启动的 service/kernel journal、应用当前及轮转日志、失败单元和 core dump 列表 |
| USB/串口/蓝牙 | `lsusb`、USB 拓扑、内核模块、`ttyACM*`/`ttyUSB*` 权限、udev 属性、占用进程、rfkill 和蓝牙控制器状态 |
| 网络 | 网卡、私有地址、路由、邻居、监听端口及 nftables/iptables 状态，用于定位 WebSocket 和日志下载不可达 |
| 采集说明 | `README.txt`、采集警告、脱敏报告和命令退出码，便于知道哪些命令缺失或权限不足 |

诊断脚本不会读取 `gateway.toml` 内容、进程环境变量、SSH 配置/密钥、录播目录、原始 EEG/HR 数据或算法载荷，也不会打开或配置 TTY。它会对普通文本再次执行密码、Token、Secret、API Key、Cookie、Authorization 和私钥模式脱敏；压缩轮转日志不会被二次改写，因此导出前仍须人工检查。

诊断包会包含主机名、私有 IP、USB VID/PID/序列属性、文件路径和运行日志，这些不是公开资料。只能在项目批准的受控渠道传递，不得上传公开网盘、公共 Issue 或聊天群。

### 8.3 校验和导出方法

先定位最新诊断包并校验完整性：

```bash
bundle=$(ls -1t /tmp/neurobridge-kylin-runtime-diagnostics-*.tar.gz | head -n 1)
sudo sha256sum -c "$bundle.sha256"
sudo tar -tzf "$bundle" | less
```

推荐按现场条件选择一种导出方式：

1. **受控 U 盘**：先用 `lsblk -f` 确认 U 盘和挂载目录，再复制诊断包及 `.sha256`，执行 `sync` 后安全卸载。不要把文件复制到未确认的系统盘或其他业务磁盘。
2. **已批准的 SSH/SCP**：只有现场已建立受限 SSH 运维入口时，才从批准的运维电脑拉取 `/tmp` 下这两个文件；不得为了传日志临时开放公网、通配监听或新账户。
3. **应用日志轻量下载**：如果只需要 NeuroBridge 应用文件日志，且 `[download]` 已在专用有线网络启用，可在 B 端浏览器下载：

   ```text
   http://<网关IP>:<下载端口>/downloads/logs/neurobridge-logs.zip
   ```

   该 ZIP 只含 `/var/log/neurobridge/*.log*` 和清单，不包含 journal、内核、USB/TTY、驱动、网络或依赖信息，不能替代完整诊断包。

若脚本无法执行，至少手工保存以下输出；每条命令都应记录执行时间和退出码：

```bash
cat /etc/os-release
uname -a
sudo systemctl status neurobridge.service --no-pager -l
sudo journalctl -u neurobridge.service -b -n 5000 --no-pager -o short-iso-precise
sudo journalctl -k -b -n 5000 --no-pager -o short-iso-precise
lsusb
lsusb -t
ls -l /dev/ttyACM* /dev/ttyUSB* 2>&1
ip -brief address
ss -lntup
```

## 9. 常见故障

| 现象 | 检查 | 处理 |
|---|---|---|
| 没有 `/dev/ttyACM*`/`ttyUSB*` | `lsusb`、`dmesg`、供电和线缆 | 确认 USB 角色、驱动和转换板是否实际呈现 TTY；若为原生 USB，转入 USB 适配器方案 |
| 有节点但权限不足 | `ls -l`、`id neurobridge`、journal | 修复组/udev 权限，重新登录或重启服务 |
| 多个端口均握手成功 | 稳定路径、VID/PID、物理连线 | 停止启停命令，隔离非目标设备后重试；不得随机选择 |
| 握手超时 | 端口参数、200 ms 周期、读超时、线序 | 只读抓取并与设备方协议比对；不得盲目改波特率 |
| `0xE1` 后无数据 | ACK、命令时序、设备佩戴状态、包头长度 | 保存错误摘要和时间范围，核对协议版本与设备固件 |
| 数据帧长度/头尾异常 | 日志中的 `channel`、`bytes`、错误原因 | 保留原始文件供受控分析，修正分帧实现，不在日志中打印原始内容 |
| 算法 bridge 不可用 | bridge 启停日志、x86_64 架构、动态库 | 在最终银河麒麟镜像上重新构建并核对 glibc/C++ 依赖，再使用真实数据判定算法 POC |
| B 端不可达 | `systemctl`、监听地址、专用网卡和静态 IP | 确认北向网络隔离及配置；不将网关接入公网或其他网络 |

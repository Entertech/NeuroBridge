# 银河麒麟 V10 USB 串口耳机配置与启动手册

状态：内部操作手册

适用环境：N100/N150 x86_64 主机、银河麒麟 V10、USB 连接且枚举为串口的耳机设备

本手册只描述当前现场方案：一台耳机通过 USB 接入麒麟电脑，NeuroBridge 从项目目录直接运行，使用本机浏览器查看数据。不需要配置蓝牙、网线或另一台 B 端主机。

## 1. 先确认当前目录

打开终端，进入已拷贝到麒麟电脑的 NeuroBridge 项目根目录：

```bash
cd /实际路径/NeuroBridge
test -f pyproject.toml
test -d linux
test -d neurobridge
pwd
```

以下所有 `./linux/...` 命令都要在这个目录执行，不要进入 `/opt/neurobridge`。

本方案中的持久化运行产物只保存在项目内：

```text
NeuroBridge/
├── .venv/                  Python 虚拟环境
├── wheelhouse/              麒麟离线 Python 依赖包
├── python-runtime/          项目内独立 Python 3.11 运行时
└── .runtime/
    ├── backups/             旧版 Python 虚拟环境备份
    ├── config/              实际运行配置和历史备份
    ├── cache/               Python 依赖下载缓存
    ├── logs/                配置过程、程序和控制台日志
    ├── recordings/           录制数据和内部设备帧
    ├── diagnostics/          USB 识别日志和完整诊断包
    └── tmp/                  安装过程临时文件
```

`.venv/`、`venv/`、`wheelhouse/`、`python-runtime/` 和 `.runtime/` 已加入 `.gitignore`，不得强制提交。

## 2. 一键初始化 Python 环境

每台新电脑只需在项目根目录执行一次，不要使用 `sudo`：

```bash
./linux/setup-kylin-python.sh
```

该麒麟镜像自带的是 Python 3.8.10，不满足项目要求。脚本检测到没有 Python 3.11 时，会自动下载经 SHA-256 锁定的独立运行时到项目 `python-runtime/`，不替换系统 Python。随后自动创建 `.venv`、安装并校验依赖。看到以下内容即成功：

```text
Runtime import check: OK
Python environment ready
```

项目 `python-runtime/` 中已有指定运行时压缩包、`wheelhouse/` 中已有完整离线依赖时，整个过程不访问网络。脚本会按锁定的 SHA-256 逐一校验 Python 压缩包和所有 wheel；缺少时使用当前网络下载。如果失败，直接按屏幕最后一条 `ERROR` 处理，完整过程保存在 `.runtime/logs/setup-kylin-python-<UTC时间>.log`。

## 3. 一键识别 USB 和串口

### 3.1 执行命令

先拔下耳机 USB，然后执行：

```bash
sudo ./linux/diagnose-kylin-usb-serial.sh --timeout 60
```

按提示操作：

1. 确认耳机 USB 已拔下，按 Enter；
2. 看到“请现在插入耳机 USB”后再插入；
3. 最多等待 60 秒，期间不要关闭终端。

屏幕会持续显示剩余时间、`usbDetected` 和 `ttyDetected`。无论成功还是超时，过程日志都会保存在：

```text
.runtime/diagnostics/neurobridge-usb-serial-diagnosis-<UTC时间>-<进程号>/
.runtime/diagnostics/neurobridge-usb-serial-diagnosis-<UTC时间>-<进程号>.tar.gz
.runtime/diagnostics/neurobridge-usb-serial-diagnosis-<UTC时间>-<进程号>.tar.gz.sha256
```

### 3.2 根据结果处理

| 屏幕结果 | 返回码 | 含义 | 下一步 |
|---|---:|---|---|
| `成功：检测到新的串口节点` | 0 | 系统已生成 TTY | 继续第 4 节 |
| `超时：已经检测到新 USB 设备` | 2 | USB 枚举成功，但没有 TTY | 检查设备 USB 类型和内核驱动 |
| `超时：60 秒内没有检测到新的 USB 设备` | 3 | 系统未看到本次插入 | 检查数据线、供电、USB 口和接触 |

该脚本不打开串口，不读取握手、脑波或心率载荷。

## 4. 一键生成串口配置

保持耳机 USB 已插入，执行：

```bash
sudo ./linux/setup-kylin-serial.sh
```

默认会：

- 从 `config/gateway.project.toml.example` 创建 `.runtime/config/gateway.toml`；
- 修改前在 `.runtime/config/` 保留带 UTC 时间的备份；
- 配置 115200、8-N-1、无流控和自动遍历 `ttyACM*`/`ttyUSB*`；
- 创建 `.runtime/logs/`、`.runtime/recordings/` 和 `.runtime/diagnostics/`；
- 将当前登录用户加入实际 TTY 所属设备组；
- 将完整配置过程保存到 `.runtime/logs/setup-kylin-serial-<UTC时间>.log`；
- 不创建 `/opt`、`/etc` 或 `/var` 下的 NeuroBridge 文件，不操作 systemd。

成功时应看到：

```text
Serial setup complete
mode=project
config=.../NeuroBridge/.runtime/config/gateway.toml
python=.../NeuroBridge/.venv/bin/python
runtimeReady=true
service=project-mode
run=.../NeuroBridge/linux/start-kylin-gateway.sh
```

### 4.1 遇到 Python 环境错误

如果之前看到：

```text
NeuroBridge Python environment was not found
```

新脚本会自动检查当前激活环境、项目 `.venv`、项目 `venv`、已安装环境及 `python3.11`/`python3`，并显示具体原因。

已按第 2 节创建 `.venv` 后，可显式指定：

```bash
sudo ./linux/setup-kylin-serial.sh \
  --python "$PWD/.venv/bin/python"
```

`runtimeReady=false` 表示当前 Python 缺少 `pyserial` 等运行依赖。直接重新执行 `./linux/setup-kylin-python.sh`，成功后再运行串口配置脚本。

### 4.2 串口权限刚被添加

如果输出的 `groups=` 不是 `none`，关闭当前终端并重新登录麒麟用户，再启动程序。新的用户组权限通常不会自动进入已打开的终端会话。不要使用 `chmod 777` 处理串口。

## 5. 启动程序

重新打开终端并进入项目根目录，不要使用 `sudo`：

```bash
./linux/start-kylin-gateway.sh
```

脚本会显示项目、Python、配置、日志和录制目录。保持该终端打开，然后用这台麒麟电脑的浏览器打开：

```text
http://127.0.0.1:8080/
```

按 `Ctrl+C` 停止程序。本流程是项目目录直接运行，关闭终端或重启电脑后需要重新执行启动命令。

如果自动识别 Python 失败：

```bash
./linux/start-kylin-gateway.sh \
  --python "$PWD/.venv/bin/python"
```

## 6. 实时查看日志

程序日志：

```bash
tail -f .runtime/logs/neurobridge.log
```

启动控制台及启动前异常：

```bash
tail -f .runtime/logs/neurobridge-console.log
```

最近 300 行：

```bash
tail -n 300 .runtime/logs/neurobridge.log
```

正常连接应依次出现类似日志：

```text
transport=serial
Serial discovery started
Serial candidate opened
Serial handshake accepted and ACK sent
Serial target selected
Serial control response received: command=start ... success=true
Connection state changed: ... current=connected
Serial capture summary
```

| 日志特征 | 含义 |
|---|---|
| `Serial discovery found no usable candidates` | 当前没有可用 TTY，查看 `byIdEntries`/`ttyACMEntries`/`ttyUSBEntries` |
| `Serial candidate probe failed` | 找到节点，但打开、配置、读写或握手失败 |
| `Serial candidate produced no handshake bytes` | 串口已打开，握手窗口内一个字节都没收到 |
| `Serial candidate produced bytes but no valid handshake` | 收到了数据，但不是约定的完整握手 |
| `longestHandshakePrefixBytes=6` | 曾收到前 6 字节一致的内容，可能末字节错误或帧被截断 |
| `ACK sent` | 已识别目标设备并立即回复 ACK |
| `command=start ... success=true` | 发送 `0xE1` 后收到任意非空响应，按成功处理 |
| `Serial control response timeout` | 已发送控制指令，但等待窗口内没有响应 |
| `current=connected` | 网关进入实时采集状态 |
| `frames` 持续增加 | 持续收到有效 28 字节数据帧 |
| `lossRatePercent` | 基于 16 位大端序列号跳号统计的累计丢包率 |
| `Serial invalid frame rejected` | 帧长度或包尾不符合协议 |
| `Serial valid-frame timeout` | 持续没有收到有效数据帧 |
| `Serial reconnect scheduled` | 连接已结束，程序将延时后重新遍历串口 |

日志不写入未知串口的完整原文，也不在错误日志中输出完整生理数据。错误字节和非法帧日志会限频，累计计数仍会增加。

## 7. 常见问题

### 7.1 `/dev/ttyACM*`、`/dev/ttyUSB*` 和 by-id 都为空

重新执行第 3 节一键识别，不要只截图最后一行。

如果“未检测到新 USB”，检查供电、USB 数据线、上行接口、电脑 USB 口和接触。如果“检测到 USB 但没有 TTY”，查看诊断目录中的：

```text
after-lsusb-tree.log
after-usb-interfaces.log
kernel-journal-window.log
udev-monitor.log
dmesg-follow.log
```

确认 USB interface class、绑定驱动和设备是否真正提供串口。麒麟没有生成 TTY 时，NeuroBridge 无法按串口连接。

### 7.2 收到字节，但握手不正确

```bash
grep -E 'no valid handshake|longestHandshakePrefixBytes|unexpected bytes' \
  .runtime/logs/neurobridge.log | tail -n 100
```

如果出现 `produced bytes but no valid handshake`，USB、TTY 和基本读取通常已正常，但实际字节不匹配固定握手。向设备方核对固件版本、实际 USB 接口类型、115200 8-N-1 和设备是否已被其他上位机占用。

### 7.3 串口权限不足

```bash
ls -l /dev/ttyACM* /dev/ttyUSB* 2>/dev/null || true
id
```

再次执行 `sudo ./linux/setup-kylin-serial.sh`，然后退出当前用户并重新登录。

### 7.4 串口被其他程序占用

将节点改为实际路径：

```bash
sudo fuser -v /dev/ttyACM0 2>/dev/null || true
sudo lsof /dev/ttyACM0 2>/dev/null || true
```

确认进程用途后再停止，不要直接结束不认识的系统进程。

### 7.5 启动立即失败

```bash
./.venv/bin/python -m pip check
tail -n 300 .runtime/logs/neurobridge-console.log
tail -n 300 .runtime/logs/neurobridge.log 2>/dev/null || true
```

重点检查 Python 依赖、`.runtime/config/gateway.toml`、串口权限和端口占用。项目默认关闭算法，可先完成 USB 串口原始数据联调；启用算法前必须提供已在当前麒麟环境验证的 bridge。

### 7.6 页面打不开

```bash
ss -lntp | grep -E '127\.0\.0\.1:(8080|8765|8766)' || true
tail -n 200 .runtime/logs/neurobridge-console.log
```

只使用本机浏览器打开 `http://127.0.0.1:8080/`。

## 8. 一键导出完整诊断包

现场无法判断时，在项目根目录执行：

```bash
sudo ./linux/collect-kylin-runtime-diagnostics.sh \
  --journal-lines 10000
```

生成：

```text
.runtime/diagnostics/neurobridge-kylin-runtime-diagnostics-<UTC时间>-<进程号>.tar.gz
.runtime/diagnostics/neurobridge-kylin-runtime-diagnostics-<UTC时间>-<进程号>.tar.gz.sha256
```

校验最新诊断包：

```bash
bundle=$(find .runtime/diagnostics -maxdepth 1 -type f \
  -name 'neurobridge-kylin-runtime-diagnostics-*.tar.gz' \
  -printf '%T@ %p\n' | sort -nr | head -n 1 | cut -d' ' -f2-)
sha256sum -c "$bundle.sha256"
```

诊断包包含系统、内核、USB/TTY、端口、项目版本、Python 依赖和项目 `.runtime/logs` 的日志；不包含配置正文、录制数据、完整生理数据、密码、Token 或私钥。导出前仍要人工检查，只能通过批准的项目内部渠道传递。

## 9. Git 防误提检查

检查运行目录是否被忽略：

```bash
git check-ignore -v .venv .runtime wheelhouse python-runtime
git status --short --ignored
```

不得使用 `git add -f` 添加下列内容：

- `.runtime/config/` 中的现场配置和备份；
- `.runtime/logs/` 中的运行日志；
- `.runtime/recordings/` 中的原始设备数据、算法结果和录制数据；
- `.runtime/diagnostics/` 中的 USB 日志、主机信息和诊断包；
- `.venv/`、`venv/`、`python-runtime/` 和 `wheelhouse/` 中的本地运行环境与依赖包。

正常 `git status --short` 不应显示上述任何运行产物。

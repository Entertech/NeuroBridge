# 银河麒麟 V10 网关快速上手与 USB 串口联调手册

> 受众：现场安装、测试与内部开发人员
>
> 状态：内部操作手册
>
> 适用环境：N100/N150 x86_64、银河麒麟 V10 SP1 2503、耳机通过 USB 转串口接入
>
> 更新时间：2026-09-02

本文只说明新设备怎么准备、怎么启动和怎么导出问题日志。现场不需要配置蓝牙、网线、静态 IP 或 systemd；网关在项目目录前台运行，网页由网关通过本机地址提供。

## 1. 第一次使用：只做三步

### 第一步：插好耳机 USB

先把耳机 USB 插到麒麟电脑。正常检测不需要反复拔插。当前实机曾枚举为 CP2102、`cp210x` 驱动和 `/dev/ttyUSB0`，但程序不会写死该编号，而是遍历当前 USB 派生串口并通过固定握手识别目标设备。

### 第二步：在项目根目录启动一个文件

打开终端，进入已经传到电脑上的 NeuroBridge 项目目录，然后运行：

```bash
bash linux/neurobridge-kylin-bootstrap.sh
```

这个启动入口只负责使用电脑上已有的完整代码，启动时不会执行 `git pull` 或访问网络。旧设备缺少 `linux/setup-kylin-gateway.sh` 时，不要只传 bootstrap 文件；应按第 6 节传输单个离线更新文件。

旧设备执行离线更新文件：

```bash
bash neurobridge-kylin-offline-update.run
```

更新完成后会自动打开同一个数字菜单，以后日常运行仍使用 `bash linux/neurobridge-kylin-bootstrap.sh`。

不要在命令前加 `sudo`。助手只会在安装系统依赖或修复权限时单独请求 sudo 密码。过程日志从入口开始保存在项目 `.runtime/logs/`。

### 第三步：输入 `1`

菜单出现后输入 `1`。`一键准备并启动` 会按顺序完成：

1. 检查并修复项目运行权限；
2. 已有 Python 环境可用时直接跳过，否则自动准备项目 Python；
3. 检查当前已插入的 USB 和串口，不要求拔插；
4. 已有串口配置时直接跳过，否则生成项目配置；
5. 已有可用算法时直接跳过，否则下载或读取离线 CMake、构建算法并自检；
6. 全部成功后直接启动网关。

这项操作可以重复执行。已经完成的耗时步骤会被跳过，不需要区分“首次安装”和“日常启动”。如询问是否安装系统构建依赖，正常联网环境输入 `yes`；不希望修改系统或当前处于离线环境时输入 `no`，然后按第 6 节准备离线包。

启动成功后保持终端窗口打开，用本机浏览器访问：

```text
http://127.0.0.1:8080/
http://127.0.0.1:8080/capture/
```

第二个地址用于查看耳机原始数据。网页只连接当前网关服务，不直接打开串口。网页上的开始/停止只控制当前页面的 WebSocket 订阅，不会停止网关、关闭耳机或影响后台录制。

## 2. 菜单怎么选

```text
1. 一键准备并启动（推荐，可重复执行）
2. 直接启动网关（已经配置好时）
3. 联网更新代码（可选，离线不要选）
4. 检查当前 USB/串口（无需拔插）
5. 重新生成 USB 串口配置
6. 修复/重新构建本地算法
7. 导出完整诊断包
8. 查看最近日志
0. 退出
```

普通操作只需记住：

| 目的 | 输入 |
|---|---:|
| 不确定下一步，准备好后直接启动 | `1` |
| 已确认全部配置好，只想启动 | `2` |
| 网络可用且明确需要从远端更新 | `3` |
| 没找到 USB/串口 | `4` |
| 算法构建或启动门禁失败 | `6` |
| 把完整问题信息发给开发人员 | `7` |
| 当场看最近 200 行日志 | `8` |

每项执行失败后，助手会同时提示“返回菜单输入哪个数字”和高级人员可直接执行的命令。现场人员优先使用数字，不必复制长命令。

## 3. 正常启动时应该看到什么

USB 串口链路的状态顺序如下，这不是蓝牙状态：

```text
not_connected → connecting → connected → validating → validated
```

| 状态 | 判定标志 |
|---|---|
| `not_connected` | 还没有识别到目标串口 |
| `connecting` | 正在遍历 `/dev/serial/by-id/`、`ttyACM*`、`ttyUSB*` 候选 |
| `connected` | 已收到完整固定握手并选中该串口；此时已找到设备，但还不能收业务数据 |
| `validating` | 网关正在回写相同 7 字节握手 ACK，并等待设备返回 ACK 校验结果 `01` |
| `validated` | ACK 已收到 `01`、本地算法已就绪且无响应使能指令 `E1` 已成功写入；只有此状态才允许脑波/心率数据进入算法、录制和网页 |
| `validation_failed` | 整个 ACK 窗口无独立 `01`、算法未就绪、ACK/`E1` 串口写入失败 |
| `disconnected` | 此前识别的目标串口已经关闭；之后会按配置重新遍历 |

关键成功日志应依次包含：

```text
Serial handshake request accepted
Serial target selected
Serial handshake validation started ... expectedResponse=single_byte_0x01
Serial handshake ACK written ... ackWriteCount=... ackWriteBytes=... writeSuccess=true
Serial handshake ACK response received ... command=handshake_ack ... singleByteHex=01 ... success=true
Serial handshake validation succeeded ... policy=single_byte_0x01
Serial local algorithm preparation started
Serial capture enable started ... command=E1 responseExpected=false
Serial command sent ... command=start ... responseExpected=false success=true
Serial capture enabled ... connectionState=validated
```

随后出现 `Serial capture summary`，其中应有 `frames`、`expectedPackets`、`lostPackets` 和 `lossRatePercent`。

`connected` 只代表找到了会握手的 USB 串口；握手 ACK 收到 `01` 后还必须完成算法准备和 `E1` 写入，才会报告 `validated`。网页没有数据时不能只看“找到设备”。

## 4. 控制应答规则

设备握手固定为：

```text
AA 55 01 01 01 01 6F
```

网关收到完整握手后停止遍历其他串口，立即原样返回该 7 字节作为握手 ACK。设备方名义上每 200 ms 发送一次握手；网关只校验完整内容，不校验周期误差。设备校验 ACK 成功后返回独立单字节 `01` 并停止重复握手；只有这个 `01` 是需要等待的协议响应。

ACK 校验通过后，网关准备本地算法；算法准备好以后发送单字节 `E1` 使能脑电。`E1` 不会收到响应，写入成功后直接进入数据流；停止采集时发送单字节 `E0`，`E0` 也不会收到响应。不得在 `E1` 或 `E0` 后额外读取一个字节，否则会误读下一帧数据。

ACK 等待窗口内收到单个 `AA` 时，网关不会立即失败，而是继续读取并判断它是否属于下一帧完整周期握手。完整重复握手会触发再次回写同值 ACK，随后继续等待；握手帧中的四个 `01` 不会被误判为校验成功。只有握手帧之外的独立 `01` 才能通过。整个窗口没有独立 `01`、只留下部分握手、只有其他内容或发生读写错误时才失败。

失败日志会包含 `success=false`、`totalReadBytes`、`repeatedHandshakeFrames`、`ackWriteCount`、`ackWriteBytes`、`unexpectedBytes`、`partialHandshakeBytes` 和最长握手前缀，不记录完整生理数据。算法未就绪或 `E1` 写入失败同样进入 `validation_failed`，但不会等待或分类所谓“E1 响应”。

## 5. 常见问题直接怎么做

### 5.1 没找到串口

返回菜单输入 `4`。助手会保存 USB、驱动、TTY、权限和占用情况。若显示 `no current TTY`：

1. 确认 USB 已插紧并尝试电脑另一个 USB 口；
2. 不需要先拔插，直接再次输入 `4`；
3. 仍为空时，把菜单 `7` 导出的诊断包发给开发人员。

只有需要判断“USB 插入前后到底新增了什么”时，才使用高级差分诊断：

```bash
sudo ./linux/diagnose-kylin-usb-serial.sh --plug-cycle --timeout 60
```

### 5.2 找到串口，但握手不正确

典型日志：

```text
Serial candidate produced bytes but no valid handshake
invalidHandshakeObserved=true
longestHandshakePrefixBytes=...
payloadLogged=false
```

这表示串口能打开且确实收到字节，但不是完整握手。重点检查波特率是否为 115200 8-N-1、是否选错转换板接口、电脑 RX/TX 方向、TTL 电平和设备固件协议。程序不会用错误握手选中设备。

### 5.3 握手 ACK 后一直收到完整握手

典型日志：

```text
Serial repeated handshake received while awaiting ACK result
action=ack_resent
repeatedHandshakeFrames=...
ackWriteCount=...
Serial handshake ACK response timed out
expectedAck01=true success=false
```

单次出现上述“重复握手并重新 ACK”日志不代表失败，网关仍在完整窗口内等待独立 `01`。只有随后出现超时日志才表示耳机始终没有确认上位机 ACK；此时网关进入 `validation_failed`，不会准备算法或发送 `E1`。重点核对电脑 TX → 耳机 RX 的发送链路，以及设备固件实际要求的 ACK 字节。若出现 `Serial handshake ACK response received ... singleByteHex=01 success=true`，说明校验已经通过。

### 5.4 发送 `E1` 后没有“响应日志”

这是正常现象：协议没有定义 `E1` 响应。应检查 `Serial command sent ... command=start ... responseExpected=false success=true`，并继续观察是否收到完整 28 字节数据帧。如果写入失败，会记录 `reason=control_write_error`；写入成功但长期没有有效帧，则记录有效帧超时并重连。

### 5.5 算法提示 CMake 版本过低

返回菜单输入 `6`。脚本不会使用或替换系统的 CMake 3.16.3，而是安装项目内锁定的 CMake 3.31.6 到 `.runtime/algorithm/toolchain/`。下载包会校验固定 SHA-256；校验不一致时立即失败，不会解压或构建。

### 5.6 算法提示 Eigen 版本不匹配

麒麟目标环境锁定 Eigen 3.3.7。菜单 `6` 会检查头文件中的实际版本；缺少依赖时可确认使用麒麟软件源安装。检测值不是 3.3.7 时不会继续构建，日志会同时给出 expected 和 detected。

### 5.7 提示 Git 不可用或网络无法拉取

日常运行输入 `1` 或 `2`，不会执行任何 Git 更新。菜单 `3` 只供网络可用且明确需要从远端更新时主动选择；联网更新失败不影响当前版本继续启动。

现场电脑无法访问 GitHub 时，由开发机生成单文件离线更新包并传到项目根目录：

```bash
# 开发机：提交并测试完成后生成
./tools/build-kylin-offline-update.sh

# 麒麟电脑：只接收生成的这一个文件
bash neurobridge-kylin-offline-update.run
```

离线更新文件内嵌经过 SHA-256 校验的 Git bundle，只从该本地文件快进代码，不访问 `origin`。更新时保留 `.runtime/`、现场配置、算法、日志和录制数据；项目有已跟踪修改、分支无法快进或 bundle 校验失败时会安全停止。

以后不要执行 `sudo git pull`、`sudo git checkout` 或 `sudo git add`。

如果存在 `.git/index.lock`，助手不会自动删除。先确认没有其他 Git 进程，再由开发人员处理。

### 5.8 网页打不开或没有数据

先确认启动网关的终端仍在运行，再检查：

1. 浏览器地址必须是 `http://127.0.0.1:8080/` 或 `/capture/`；
2. 日志是否到达 `validated`；
3. capture 页是否点击了“开始”；
4. 日志是否出现 `Serial valid-frame timeout` 或持续握手。

不要直接双击 `web/capture/index.html`。页面文件本身是静态资源，但必须由当前网关提供，并通过网关 WebSocket 获取数据。

## 6. 离线电脑怎么准备

### 6.1 离线更新项目源码

开发人员在已提交、测试通过且工作区干净的仓库执行：

```bash
./tools/build-kylin-offline-update.sh
```

生成文件位于：

```text
.runtime/packages/neurobridge-kylin-offline-update.run
```

只把这个 `.run` 文件传到麒麟电脑的项目根目录并执行：

```bash
bash neurobridge-kylin-offline-update.run
```

它会校验内置版本、修复经确认的项目权限、从内置本地 bundle 快进代码，然后自动打开数字菜单。全过程记录在 `.runtime/logs/kylin-offline-update-*.log`，不会执行网络 `git fetch` 或 `git pull`。

### 6.2 离线准备 Python 和算法依赖

Python 和 CMake 都放在项目目录，不替换麒麟系统运行时。离线材料可由开发人员提前放入：

```text
python-runtime/       # 锁定的 Python 3.11 运行时压缩包与解压结果
wheelhouse/           # Python wheel 与摘要清单
algorithm-packages/   # 算法构建工具包
```

麒麟 x86_64 的 CMake 离线文件名必须为：

```text
algorithm-packages/cmake-3.31.6-linux-x86_64.tar.gz
```

固定 SHA-256：

```text
5a1133ff103c71eb5120e2cc3de922733e7d8a26a98ae716397e8676adb367bf
```

准备好后仍然只运行入口并输入 `1`。这些目录和 `.runtime/` 已加入 `.gitignore`，不会因日常 `git add` 被误提交。

## 7. 日志在哪里，怎么导出

所有项目运行产物都在仓库目录内：

```text
.runtime/config/       现场配置
.runtime/logs/         助手、安装、算法和运行日志
.runtime/algorithm/    构建结果与项目内 CMake
.runtime/recordings/   内部录制数据
.runtime/diagnostics/  可传给开发人员的诊断包
```

当场查看最近日志：返回菜单输入 `8`。

向开发人员提交问题：返回菜单输入 `7`。完成后把 `.runtime/diagnostics/` 下最新的 `.tar.gz` 和同名 `.sha256` 一起发送。诊断会记录系统、USB/TTY、权限、占用、工具链、项目 revision、状态迁移、握手与控制分类、有效/非法帧、超时、丢包和重连统计。

诊断包不应包含密码、令牌、私钥、完整 28 字节脑波帧或算法输入。不要把 `.runtime/`、诊断包或人体录制数据提交到 Git。

## 9. 高级人员分步命令

只有数字菜单无法运行时才直接执行：

```bash
./linux/setup-kylin-python.sh
sudo ./linux/diagnose-kylin-usb-serial.sh
sudo ./linux/setup-kylin-serial.sh
./linux/setup-kylin-algorithm.sh
./linux/start-kylin-gateway.sh
sudo ./linux/collect-kylin-runtime-diagnostics.sh --journal-lines 10000
```

分步命令的日志仍写入项目 `.runtime/`。现场标准流程始终是：运行一个入口文件，输入 `1`；只有排障时才选其他数字。

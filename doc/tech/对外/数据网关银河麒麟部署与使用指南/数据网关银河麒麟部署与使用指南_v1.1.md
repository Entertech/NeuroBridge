# 数据网关银河麒麟部署与使用指南 v1.1

版本：v1.1

状态：已发布

创建日期：2026-10-10

## 1. 用途与边界

本指南说明如何在银河麒麟主机上安装、启动、确认运行状态、使用本机控制台页面、查看运行日志、排查常见问题和卸载数据网关。

本文只描述 B 端可观察到的安装位置、服务状态、本机页面地址、运行日志和操作步骤，不包含设备接入、数据处理、算法或其他网关内部实现细节。网关对 B 端的数据接口规则以随交付包发布的北向网络协议文档为准，本文不重复其契约内容。

本版本随本次发布 PR 更新，PR 合入后由 CI 生成正式 PDF。安装包结构和模拟回归不等于目标机现场验收通过；现场仍须记录安装、采集、断线、重连和重启结果。

本文使用以下术语：

- **网关主机**：运行数据网关的这台银河麒麟电脑。
- **本机控制台页面**：网关在 `127.0.0.1` 提供的网页控制台，只能在网关主机本机打开。
- **网关服务**：systemd 服务 `neurobridge`。


### 1.1 版本关系与迁移

v1.1 接替 v1.0 的部署操作说明，旧版独立保留。本次补充安装前提、安装失败取证与日志导出、升级和卸载说明；北向网络协议及报文版本不变。请使用本次交付清单对应的新版安装包和 v1.1 指南，不混用旧版流程。

交付 ZIP 中 PDF 使用英文副本文件名，避免部分解压工具把中文文件名解码成乱码。中文标题、内容和文档版本不变，原名称对照位于总包 `metadata/document-filenames.json`。

## 2. 前提与默认参数

### 2.1 环境前提

- 银河麒麟 V10，x86_64 架构。
- 由交付方提供的数据网关安装包，文件名形如 `neurobridge-bootstrap-<版本>-<构建时间>-kylin-v10-x86_64.deb`。
- 安装、启停服务需要 root 权限。
- **先用 USB 连接耳机，再安装**。设备缺失或当前账户授权失败时，安装会明确失败；连接好耳机后重试。
- 系统须已具备 `ca-certificates`、`curl`、`g++`、`make` 和 `tar`。先执行 `dpkg --audit`，处理其他未完成的软件包配置。
- 可在联网阶段使用 `sudo apt-get install ca-certificates curl g++ make tar` 准备系统依赖；离线部署须事先由交付方准备与目标系统匹配的依赖包。

安装包在安装过程中于本机完成网关运行环境的准备，耗时数分钟。引导包携带其余运行环境输入；正常安装构建不下载这些输入。`dpkg -i` 不会自动补齐系统依赖，缺少依赖时应先准备依赖，再重新配置。构建耗时依主机性能而定，命令执行期间不要关机。

### 2.2 默认安装位置

| 项目 | 默认位置 |
| --- | --- |
| 程序目录 | `/opt/neurobridge` |
| 配置文件 | `/etc/neurobridge/gateway.toml` |
| 运行日志目录 | `/var/log/neurobridge` |
| 安装与构建日志目录 | `/var/log/neurobridge-bootstrap` |
| 录制数据目录 | `/var/lib/neurobridge/recordings` |
| 服务名 | `neurobridge` |

配置、日志和录制目录由安装程序创建。重复安装和卸载安装包都不会删除 `/etc/neurobridge/gateway.toml` 与 `/var/lib/neurobridge`，现场配置和录制数据因此得以保留。

### 2.3 默认监听地址与端口

网关的全部网络服务只监听本机回环地址 `127.0.0.1`，不向本机以外的网络提供访问。

| 服务 | 默认地址 | 用途 |
| --- | --- | --- |
| 本机控制台页面 | `http://127.0.0.1:8080/` | 浏览器访问的网页控制台 |
| 数据接口 | `ws://127.0.0.1:8765/neurobridge/v1/ws` | B 端接入连接 |
| 日志下载 | `http://127.0.0.1:8766/downloads` | 从网关内导出运行日志 |

以上端口取自配置文件，仅作为默认示例。现场已确认其他值时，以实际部署配置为准。

## 3. 安装

1. 解压银河麒麟交付 ZIP，进入包含 DEB 和 `checksums.sha256` 的目录，先核对系统和文件摘要：

```bash
cat /etc/os-release
uname -m
sha256sum -c checksums.sha256
```

仅在银河麒麟 V10、`x86_64` 和校验通过时继续。交付指南副本名为 `kylin-deployment-guide_v1.1.pdf`。

2. 连接耳机，确认第 2 节的系统依赖已安装。不要预先卸载已有网关；重装会保留现场配置和数据。
3. 以 root 身份安装（将占位文件名替换为实际文件名）：

```bash
sudo dpkg -i neurobridge-bootstrap-<版本>-<构建时间>-kylin-v10-x86_64.deb
```

预期看到 `Installation log:`、`INSTALL_BEGIN`、`PHASE build-runtime`、`PHASE deploy-runtime` 和 `INSTALL_END ... exit_code=0`。安装前没有运行环境时日志也会创建。

4. 安装结束后核对包状态和构建来源，再依第 6 节检查服务、端口和页面：

```bash
dpkg-query -W neurobridge-bootstrap
sudo cat /usr/lib/neurobridge-bootstrap/build-info.txt
systemctl is-active neurobridge
systemctl is-enabled neurobridge
```

包查询成功或显示“正在设置”只说明包管理器执行到该阶段，不能代替构建日志和服务检查。首次安装会启用开机自启并启动服务；升级/重装保留原来的运行与自启状态，原先已停用的服务不会被强行启用。确需启动时使用第 5 节命令。

### 3.1 升级、修复与失败恢复

每次配置新版包都会重新准备并安装当前包内容，不以已有 Python 运行时作为跳过依据。已有配置和数据保留。新内容准备成功后才替换程序和服务；替换阶段失败会尝试恢复原程序、配置及服务状态。日志出现 `Rollback incomplete` 时先导出日志并保留其提示的备份路径，由交付方处理。

安装返回非零时先按第 8.1 节导出日志，修正错误后重试原安装命令；若只是依赖未就绪，准备依赖后也可执行：

```bash
sudo dpkg --configure neurobridge-bootstrap
```

不要使用旧提交 `3f31a037` 的安装包验证新版流程：该包可能在发现已有运行时后跳过构建。使用交付清单核对新的源码提交和构建时间；只有 `0.2.1` 版本号相同不足以区分两个构建。

## 4. 配置

配置文件默认位于 `/etc/neurobridge/gateway.toml`。需要修改时以 root 权限编辑，按 UTF-8 保存，然后重启网关服务使配置生效。

```toml
[server]
host = "127.0.0.1"
port = 8765
path = "/neurobridge/v1/ws"

[local_ui]
enabled = true
host = "127.0.0.1"
port = 8080

[download]
enabled = true
host = "127.0.0.1"
port = 8766
path = "/downloads"
```

必须保持以上三个 `host` 均为 `127.0.0.1`。网关只在本机回环地址提供服务并校验请求来源，改成其他地址或从其他主机访问都不会成功。

如果默认端口与网关主机上的其他程序冲突，可在双方确认后修改。修改后，第 6 节和第 7 节中的地址要同步改用新端口。

## 5. 启动、停止与开机自启

安装后网关服务默认开机自动启动，不需要先登录桌面。

以 root 身份在网关主机上执行：

```bash
# 启动
sudo systemctl start neurobridge

# 停止
sudo systemctl stop neurobridge

# 查看状态
systemctl status neurobridge --no-pager
```

`Active` 一行显示 `active (running)` 表示服务正在运行，`inactive (dead)` 表示已停止。

更新配置前，先停止服务，完成后再启动。不要同时运行两个网关实例。

## 6. 判断网关是否正在运行

按以下顺序检查。三层都通过，才表示网关已就绪。

### 6.1 检查服务状态

```bash
systemctl is-active neurobridge
```

输出 `active` 表示服务进程已经启动。服务处于 `active` 只说明启动成功，还需要继续检查端口和页面。

### 6.2 检查端口监听

```bash
ss -ltnp | grep -E '8080|8765|8766'
```

预期看到这三个端口均以 `127.0.0.1` 为本地地址处于监听状态。端口没有出现时，说明网关尚未完成启动，应查看第 8 节的运行日志确认原因。

### 6.3 检查控制台页面

在**网关主机本机**的浏览器打开 `http://127.0.0.1:8080/`。页面能正常加载，即表示本机控制台已就绪。

### 6.4 确认正在采集数据

页面能打开，不等于耳机已经连接并在采集。打开采集页 `http://127.0.0.1:8080/capture/`，点击“开始”，核对页面持续出现按 600 ms 窗口到达的数据。也可以查看第 8 节运行日志中的连接和采集记录。

## 7. 控制台与页面地址

| 页面 | 地址 | 说明 |
| --- | --- | --- |
| 采集页 | `http://127.0.0.1:8080/capture/` | 查看耳机实时数据，开始或停止接收 |
| 综合页 | `http://127.0.0.1:8080/` | 网关本机控制台入口 |
| 日志下载 | `http://127.0.0.1:8766/downloads/logs/neurobridge-logs.zip` | 下载网关运行日志压缩包（下载服务启用且网关运行时可用） |

打开页面时注意：

- 必须在**运行网关的这台主机**上打开，并且必须使用 `127.0.0.1`。改用 `localhost`、`file://` 或其他主机的地址都会被拒绝。
- 不要直接双击 HTML 文件打开页面，页面必须由网关服务提供。
- 页面上的“停止”只停止当前页面的数据订阅，不会停止网关服务。

## 8. 运行日志

运行日志默认位于 `/var/log/neurobridge`，当前文件为 `neurobridge.log`，按大小轮转并保留历史归档。

```bash
# 查看最近 200 行
sudo tail -n 200 /var/log/neurobridge/neurobridge.log

# 持续跟随新日志（Ctrl+C 结束，不影响网关）
sudo tail -n 200 -f /var/log/neurobridge/neurobridge.log

# 查看服务自身的启动记录
sudo journalctl -u neurobridge --no-pager -n 200
```

日志时间按 UTC 记录，北京时间为 UTC+8。日志包含网关版本、耳机连接状态、数据时间范围和错误原因，不记录凭据和完整原始数据。

### 8.1 安装失败日志与导出

安装日志为 `/var/log/neurobridge-bootstrap/install-<UTC时间>-<进程号>.log`。每次记录构建来源、阶段、输出、退出码以及替换或回滚结果，最多保留最近 10 次安装日志；构建子日志最多保留 40 份，每份保留末尾 2 MiB。运行日志与安装日志分别保存。

```bash
sudo ls -lt /var/log/neurobridge-bootstrap
sudo tail -n 200 /var/log/neurobridge-bootstrap/install-*.log
```

安装失败、服务不存在或网页打不开时，无须网页和网关运行环境也能导出：

```bash
sudo /usr/lib/neurobridge-bootstrap/export-install-logs.sh \
  --output-dir "$HOME/下载"
```

终端会打印 `Log export:` 和生成的 `neurobridge-install-*.tar.gz` 路径。把该压缩包和原 DEB 文件名交给交付方。导出包括安装/构建日志尾部、系统版本、软件包状态、服务状态及近期服务和包管理器记录；配置只包含摘要，不复制配置正文、录制数据或设备原始数据。文件生成后归运行 sudo 的用户所有，可以直接复制。

如果 DEB 因缺少依赖而未执行配置，安装日志可能尚未生成；此时包管理器日志和状态仍会被导出。如果连导出脚本也不存在，在当前安装包目录执行以下备用步骤，再重新安装：

```bash
mkdir -p "$HOME/下载/neurobridge-support"
sudo dpkg -i ./neurobridge-bootstrap-*.deb 2>&1 | \
  tee "$HOME/下载/neurobridge-support/dpkg-install.txt"
sudo tail -n 300 /var/log/dpkg.log > \
  "$HOME/下载/neurobridge-support/dpkg-history.txt"
```

上述管道用于保留输出；不能用 `tee` 的成功状态判定 `dpkg` 成功。旧包没有持久安装日志时，只能先保留这些记录。安装日志的时间为 UTC，北京时间需加 8 小时。

## 9. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| `systemctl status neurobridge` 提示服务不存在 | 安装未完成或已被卸载。用交付方提供的安装包重新安装。 |
| 安装命令执行数分钟后返回非零 | 按第 8.1 节导出日志；旧服务可能仍在运行或已恢复，须核对日志、包状态和服务状态，修正后重新安装，不需要先卸载。 |
| 服务为 `inactive`，手动启动后立即回到停止 | 查看第 8 节日志中的启动错误。常见原因是配置文件语法错误或端口被其他程序占用。 |
| 服务为 `active` 但端口未监听 | 启动预检未通过。查看日志确认是配置问题还是端口冲突，修复后重启服务。 |
| 页面打不开 | 确认服务正在运行、端口正在监听，并确认使用的是 `127.0.0.1`，而不是 `localhost` 或其他主机地址。 |
| 页面能打开但一直没有数据 | 确认耳机已通过 USB 连接到网关主机；在采集页点击“开始”后再观察。 |
| 提示端口被占用 | 用 `ss -ltnp` 找到占用端口的进程；停止冲突程序，或与交付方确认后修改配置端口。 |
| 需要重新开始采集 | 先在采集页点击“停止”，再点击“开始”。页面上的停止不会影响网关服务。 |

## 10. 停止与卸载

停止网关服务：

```bash
sudo systemctl stop neurobridge
```

卸载安装包：

```bash
sudo dpkg --remove neurobridge-bootstrap
```

新版卸载脚本会停止并禁用本包的服务，然后移除其服务注册，防止重启后再次启动。若服务无法停止，卸载会明确失败，先处理服务状态再重试。卸载保留 `/opt/neurobridge`、`/etc/neurobridge`、`/var/log/neurobridge`、安装日志及 `/var/lib/neurobridge` 中的现场资料；需要彻底清除时先导出日志和确认数据保留要求，再由运维人员处理。不要用旧 v1.0 所述“无卸载脚本”的流程解释新版包行为。

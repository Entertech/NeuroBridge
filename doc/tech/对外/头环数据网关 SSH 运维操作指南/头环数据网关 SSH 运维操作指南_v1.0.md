# 头环数据网关 SSH 运维操作指南 v1.0

版本：v1.0

状态：未发布（评审稿）

适用对象：经授权的外部运维人员

创建日期：2026-08-10

## 1. 用途与边界

本指南说明如何通过 SSH 查看和操作已部署的头环数据网关服务。SSH 仅用于网关运维；B 端取数、订阅和录播仍通过双方确认的 WebSocket 北向协议完成。

本指南不包含网关内部设备接入、数据处理、算法、录制文件或源代码实现细节。未发布版本仅供评审和现场准备使用，不能作为验收或正式交付依据。

## 2. 使用前确认

请由网关交付方通过独立可信渠道提供下列现场参数：

| 参数 | 说明 |
| --- | --- |
| 网关 SSH 地址 | 网关在专用有线网络上的 IPv4 地址 |
| SSH 端口 | 已确认的监听端口；未确认时不要假定为 22 |
| 运维账户 | 已授权的 SSH 登录账户 |
| 登录密码 | 仅通过独立可信渠道交付；不得写入聊天、邮件、工单或日志 |
| 允许来源 | 已获批准的运维主机 IPv4 地址或网段 |

使用环境必须满足以下条件：

- 运维主机与网关位于受控的专用有线网络；不得通过公网、无线网络或不受控局域网访问。
- 运维主机已安装 OpenSSH 客户端。
- 首次连接前，已核验网关地址、端口和运维账户。
- 未经网关交付方授权，不修改网关网络、SSH 配置、系统账户或防火墙。

## 3. 建立 SSH 连接

在运维主机终端执行以下命令，并将尖括号中的内容替换为现场值：

```bash
ssh -p <SSH端口> <运维账户>@<网关SSH地址>
```

示例：

```bash
ssh -p 22 neuroops@192.168.88.10
```

首次连接时，SSH 客户端会显示主机密钥指纹。请通过独立可信渠道与网关交付方核对后再接受；如已保存的指纹发生变化，应停止连接并联系网关交付方确认。

登录成功后先执行：

```bash
whoami
neurobridge-ops status
```

`whoami` 应显示已授权的运维账户。`neurobridge-ops status` 用于查看网关业务服务状态和最近日志；它不改变网关数据或配置。

## 4. 可用运维命令

登录账户仅可使用受限的 `neurobridge-ops` 命令执行下列操作，不提供通用 root 管理权限。

| 命令 | 用途 | 影响 |
| --- | --- | --- |
| `neurobridge-ops status` | 查看服务状态和最近日志 | 只读 |
| `neurobridge-ops logs --lines 500` | 查看最近指定数量的服务日志，范围为 1–1000 | 只读 |
| `neurobridge-ops logs --follow` | 实时查看新日志；按 `Ctrl-C` 停止 | 只读 |
| `neurobridge-ops audit --lines 500` | 查看运维命令审计记录，范围为 1–1000 | 只读 |
| `neurobridge-ops project` | 显示当前受管项目目录 | 只读 |
| `neurobridge-ops restart` | 重启网关业务服务 | 会中断现有 B 端数据连接 |
| `neurobridge-ops stop` | 停止网关业务服务 | B 端无法取数，直至服务再次启动 |
| `neurobridge-ops start` | 启动网关业务服务 | 恢复后 B 端需重新建立业务连接 |
| `neurobridge-ops update` | 应用已获批准的完整版本并重新加载服务 | 会中断现有 B 端数据连接 |

仅在已获得变更授权时执行 `restart`、`stop`、`start` 或 `update`。执行 `update` 前，应确认待部署版本已经按双方约定完成交付和审核；该命令不接受临时路径或任意脚本。

## 5. 日常查看与排障

### 5.1 查看服务状态

```bash
neurobridge-ops status
```

当 B 端无法连接或未收到数据时，优先记录该命令的时间、服务状态和报错摘要，并联系网关交付方。请勿复制包含不相关主机信息的完整日志，也不要向外发送密码、现场配置或业务原始数据。

### 5.2 查看历史或实时日志

```bash
neurobridge-ops logs --lines 200
neurobridge-ops logs --follow
```

实时日志会持续输出，按 `Ctrl-C` 结束查看，不会停止网关服务。日志用于排障，不应被当作数据导出接口。

### 5.3 查看操作审计

```bash
neurobridge-ops audit --lines 200
```

审计记录包含受限运维命令的操作者、动作、参数摘要及开始/完成结果；不包含登录密码或 SSH 会话内容。SSH 登录来源和认证结果以系统 SSH 日志及现场安全流程为准。

## 6. 服务操作后的 B 端处理

执行 `restart`、`stop` 或 `update` 会断开现有 B 端 WebSocket 连接。网关服务恢复后，B 端应：

1. 重新建立 WebSocket 连接；
2. 调用 `getStatus` 确认当前状态；
3. 按北向协议重新创建所需订阅。

旧连接的 `subscriptionId` 不可复用。SSH 服务独立于网关业务服务；网关业务服务重启不代表 SSH 配置发生变化。

## 7. 常见问题

| 现象 | 建议处理 |
| --- | --- |
| `Connection timed out` 或 `Connection refused` | 核对专用网线、两端地址、端口和现场防火墙策略；不要改用公网或无线网络绕过限制。 |
| `Permission denied` | 核对运维账户、密码和允许来源地址；不要反复猜测密码，必要时联系网关交付方重置。 |
| 首次连接提示主机密钥变化 | 停止连接，通过独立可信渠道确认指纹；未经确认不得删除本地已知主机记录后继续登录。 |
| `neurobridge-ops` 命令不可用或被拒绝 | 记录命令和提示信息，联系网关交付方；不要尝试使用 `sudo` 或修改系统文件。 |
| B 端在服务操作后未恢复数据 | 按第 6 节重新连接、查询状态并重新订阅；仍未恢复时收集最少必要的状态与日志摘要后联系网关交付方。 |

## 8. 安全要求

- 运维账户、密码和允许来源范围应按网关管理员凭据管理，不得共享。
- 不得在不受控网络中暴露 SSH 地址或端口。
- 不得将密码写入命令历史、脚本、配置备份、日志、截图或工单。
- 不得在未经授权的情况下更新项目文件、执行未知命令或修改系统安全策略。
- 完成运维后，退出 SSH 会话：

```bash
exit
```

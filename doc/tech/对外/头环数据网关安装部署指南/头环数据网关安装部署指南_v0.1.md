# 头环数据网关安装部署指南 v0.1

版本：v0.1<br>
日期：2026-10-29<br>
状态：未发布（评审稿）<br>
适用人员：具有网关本地控制台和 sudo 权限的安装、交付人员

本文补充新系统首次部署流程，与有线网络配置指南、SSH 运维指南配套使用。未发布版本仅供评审和现场准备使用，不能作为验收或正式交付依据。

## 1. 适用版本与操作位置

本文仅适用于 `codex/linux-headband-ethernet-gateway` 分支，以提交 `e1906e8fc2c74a55c896c0b1376025b01ba02cf3` 为运行行为基线。后续文档提交可包含本指南；部署前仍须记录并核对交付方批准的完整提交号。其他分支、其他系统和其他架构不适用。

| 项目 | 要求 |
| --- | --- |
| 网关操作系统 | Ubuntu 24.04 LTS，64 位，使用 systemd |
| 网关 CPU 架构 | `x86_64`，安装镜像选择 `amd64` |
| 硬件 | N100/N150 等目标小主机；实际网卡、头环接入和算法须在目标机验证 |
| 安装位置 | 网关本地控制台，即直接连接网关的显示器、键盘和鼠标 |
| B 端 | 与网关通过专用网线连接的业务主机；下文网络检查示例使用 Windows |
| 交付状态 | 源码与文档支持部署流程；本文不代表目标机 POC 或现场验收已经通过 |

网关负责采集、处理和持久化，B 端负责展示和保存。B 端不直接访问头环，也不负责选择网关数据源。

## 2. 开始前准备

1. 备份网关硬盘和 U 盘中需要保留的文件。制作启动盘清空 U 盘；整盘安装清空选中的网关硬盘。已有部署还须备份现场配置和采集数据，并核验备份可恢复。
2. 准备至少 8 GB 的 U 盘，建议 16 GB 或更大，以及网关显示器、键鼠和安装账号。
3. 由交付方确认批准源码、网关与 B 端的地址、子网掩码、专用网卡、WebSocket 端口和下载端口；需要 SSH 时另行确认监听地址、端口、账号和允许来源。
4. 保留一次性联网准备的条件。先下载源码和安装依赖，成功后再切换到隔离的 B 端专线。不要提前把唯一联网网口改成专线地址。
5. 使用默认模板先验证后台和网络，模板不会自动开启实时采集。实际头环接入参数、采集开关及算法配置由交付方按目标机验证结果确认。

下文地址、网卡名和端口都是示例，不是现场已批准参数。密码、现场配置和采集数据不得提交代码仓库。

## 3. 安装 Ubuntu 系统

### 3.1 在 Mac 制作启动 U 盘

从 [Ubuntu 24.04 官方目录](https://releases.ubuntu.com/24.04/)下载 `ubuntu-24.04…-desktop-amd64.iso`。Mac 仅用于制作介质，镜像按网关架构选择；即使 Mac 使用 Apple 芯片，网关镜像仍选择 `amd64`。

从 [balenaEtcher 官网](https://etcher.balena.io/)下载适合 Mac 的版本：Apple 芯片选择 ARM64，Intel Mac 选择 x64。插入 U 盘，依次选择 ISO、目标 U 盘、Flash，等待写入与校验完成。ISO 不能仅以普通文件方式复制到 U 盘。若 macOS 提示无法读取写好的磁盘，选择忽略或推出，不要初始化。

制作说明见 [Ubuntu 启动盘教程](https://ubuntu.com/desktop/docs/en/latest/how-to/create-a-bootable-usb-stick/)。

### 3.2 在网关安装系统

将 U 盘插入网关，按机器开机提示进入启动菜单，选择 UEFI USB 启动项，再选择 Try or Install Ubuntu。按安装器完成语言、键盘、交互式安装、默认软件选择、账号密码和上海时区设置。

只有确认整盘内容均可清除时，才选择“擦除磁盘并安装 Ubuntu”。在最终确认页核对内置硬盘型号与容量。需要保留原系统或数据时，先由交付方确认分区方案，不执行整盘擦除。安装完成后按提示移除 U 盘并重启。

完整安装说明见 [Ubuntu 官方教程](https://ubuntu.com/tutorials/install-ubuntu-desktop)。保持在 Ubuntu 24.04 系列，不升级到其他大版本。

### 3.3 确认系统

**操作位置：网关本地控制台。** 打开终端执行：

```bash
cat /etc/os-release
uname -m
systemctl is-system-running
ip -br addr
```

预期 `ID=ubuntu`、`VERSION_ID="24.04"`、架构为 `x86_64`。systemd 应为 `running`；若为 `degraded`，先确认失败单元是否影响本次部署；`offline` 等状态不继续安装。其他系统或架构会被安装器拒绝。

联网时完成系统更新并按提示重启。关闭系统自动挂起，避免网关运行期间休眠。当前阶段先保留原有联网地址。

## 4. 获取批准源码并完成联网准备

**操作位置：网关本地控制台。** 在新建的源码目录执行：

```bash
sudo apt update
sudo apt install git
git clone --branch codex/linux-headband-ethernet-gateway \
  --single-branch https://github.com/Entertech/NeuroBridge.git
cd NeuroBridge
git branch --show-current
git rev-parse HEAD
```

将显示的分支和完整提交号与批准交付记录核对。本文基线提交见第 1 节；分支名本身不能代替版本批准。无法联网时，由交付方在联网环境准备依赖与完整批准源码，不能只复制一个 ISO 或源码目录就跳过依赖准备。

随后执行一次性联网准备：

```bash
./linux/prepare-ubuntu24.04-environment.sh
```

该步骤需要互联网，安装系统依赖并准备 `/opt/neurobridge/venv` 中的运行环境。后续安装使用本地源码，不会自动联网补齐缺失依赖。

**本脚本会停用默认的 `ssh.socket` 和 `ssh.service`。不要通过当前 SSH 会话执行首次环境准备；它可能中断远程访问。** 准备完成不代表 SSH 已可登录，须在第 7 节显式配置后才启用。

必须等脚本明确报告准备完成，再切断联网链路。失败时保留错误摘要，在本地控制台修复后重试；不要继续运行后续安装命令。

## 5. 首次创建配置并应用专用网络

### 5.1 创建配置

**操作位置：网关本地控制台，当前源码根目录。**

```bash
sudo install -d -m 0750 /etc/neurobridge
sudo test -e /etc/neurobridge/gateway.toml
```

若配置已存在，保留原文件并直接编辑。只有上一条检查确认文件不存在的全新部署，才执行下面的复制命令：

```bash
sudo install -m 0640 config/gateway.toml.example \
  /etc/neurobridge/gateway.toml
```

编辑配置：

```bash
sudoedit /etc/neurobridge/gateway.toml
```

| 配置项 | 确认内容 |
| --- | --- |
| `[server]` 的 `host`、`port`、`path` | 网关专用地址、双方确认的固定端口和路径 |
| `[network]` 的 `mode` | 本指南首次部署使用 `static` |
| `[network]` 的 `interface` | 实际 B 端专用网卡名称，多网口时必须明确指定 |
| `[network]` 的 `subnet_cidr` | 与网关、B 端地址匹配的私有网段 |
| `[download]` | 是否启用及固定端口，`host` 与 `[server].host` 一致 |
| 其他配置 | 保留模板，由交付方确认采集、存储和算法设置；不凭本文修改未确认参数 |

以下片段只用于修改现有文件内对应字段，不能覆盖整份模板或重复添加同名 TOML 节：

```toml
[server]
host = "192.168.88.10"
port = 8765
path = "/neurobridge/v1/ws"

[network]
mode = "static"
interface = "enp1s0"
subnet_cidr = "192.168.88.0/24"

[download]
host = "192.168.88.10"
port = 8766
```

网卡名和数值必须替换为现场确认值。需要 DHCP 的场景应另行确认配置；不能仅将 `static` 改为 `dhcp` 就认为已经配置完成。

### 5.2 从临时联网切换到 B 端专线

先物理断开原网络，再将确认的专用网口与 B 端直连。临时联网结束后不要继续共享或桥接互联网。

在本地控制台应用配置：

```bash
sudo /opt/neurobridge/venv/bin/neurobridge-network-config \
  --config /etc/neurobridge/gateway.toml --apply
```

若仅因该口残留原网络地址或路由而拒绝应用，确认原网络已物理断开、该口已批准改为 B 端专线后，才执行：

```bash
sudo /opt/neurobridge/venv/bin/neurobridge-network-config \
  --config /etc/neurobridge/gateway.toml --apply --replace-active
```

`--replace-active` 会替换活跃网络设置，不可在远程会话中试错使用。若报错涉及其他 Netplan 文件、选错网口或接口迁移，该参数不能代替检查；保留错误并由交付方处理，不删除未知配置。

检查地址，网卡名替换为实际值：

```bash
ip -br addr show enp1s0
```

示例预期为 `192.168.88.10/24`。详细两端配置见《头环数据网关有线网络配置指南》。

## 6. 安装并显式启动网关

**操作位置：网关本地控制台，当前源码根目录。**

```bash
sudo ./linux/install-ubuntu.sh
```

安装器部署程序到 `/opt/neurobridge`、构建本地处理组件、设置服务账号和目录权限、应用网络配置，并启用开机自启。首次安装成功后，不会主动执行启动命令；重启整机则会因开机自启而启动服务。已有服务运行时，安装器也不保证自动停止它，因此本节只用于新系统首次部署。

**首次安装用 `install-ubuntu.sh`；`update-ubuntu.sh` 会在安装后立即重启服务，不适合用作“安装后等待确认”的入口。**

确认配置可读、可解析：

```bash
sudo -u neurobridge /opt/neurobridge/venv/bin/python -c \
  'from neurobridge.config import load; load("/etc/neurobridge/gateway.toml"); print("configuration OK")'
```

确认后显式启动：

```bash
sudo systemctl start neurobridge.service
sudo systemctl is-enabled neurobridge.service
sudo systemctl --no-pager --full status neurobridge.service
sudo journalctl -u neurobridge.service -n 100 --no-pager
sudo ss -lntp
```

预期服务为 `enabled`、`active (running)`，日志显示在批准地址监听 WebSocket。进程运行不等于头环已连接，也不等于算法结果有效；后续分别验收。

| 位置 | 用途 |
| --- | --- |
| `/etc/neurobridge/gateway.toml` | 部署配置 |
| `/var/lib/neurobridge/recordings` | 采集与录播数据，由交付方管理 |
| `/var/log/neurobridge/neurobridge.log` | 持久化日志，每日轮转，默认保留 14 份归档 |

Linux 后台当前不提供本机采集控制台页面；不能照搬其他平台控制台地址来判断 Linux 服务是否可用。

## 7. 配置 SSH 运维入口（可选）

**操作位置：网关本地控制台，当前源码根目录。** 先确认专用地址已实际配置在网卡上，且 B 端运维来源地址固定，再执行：

```bash
sudo ./linux/setup-ssh-operations.sh
```

按提示填写现场确认的账号、密码、监听地址、来源和端口。密码通过隐藏输入设置，不写入命令或文档。需要快速模式时，按《头环数据网关 SSH 运维操作指南》执行。

配置成功后验证：

```bash
sudo sshd -t
sudo systemctl is-enabled ssh.service
sudo systemctl is-active ssh.service
sudo ss -lntp
```

SSH 应只监听批准地址和端口。其服务独立于网关业务服务；网关停机不会自动关闭 SSH。重启后需复核 SSH 状态，默认 `ssh.socket` 不应重新启用。

在 B 端使用交付方确认的账户、IP、端口登录；首次连接须核对主机指纹：

```text
ssh -p <SSH端口> <运维账户>@<网关IP>
```

登录后可使用 `neurobridge-ops status`、`logs --follow`、`audit`、`start`、`stop` 和 `restart`。

**当前分支的 `neurobridge-ops update` 固定切换并拉取 `master`，会离开本指南分支。维持本分支部署时，不使用该更新命令；更新由交付方在本地控制台按批准版本执行。** 此限制补充现有 SSH 指南的通用更新说明，不改变启停、日志和审计命令。

## 8. B 端连接与首次验证

**操作位置：B 端主机。** 为专用网卡设置与网关同网段、不同地址的静态 IPv4。示例为 `192.168.88.20`、掩码 `255.255.255.0`，默认网关和 DNS 留空，不启用网络共享或桥接。

Windows PowerShell 验证示例：

```powershell
ipconfig
Test-NetConnection 192.168.88.10 -Port 8765
```

端口检查成功后，打开交付文件中的 `b-client-test/index.html`；源码交付时对应 `web/b-client-test/index.html`，直接在浏览器打开即可。填写批准的地址，示例为：

```text
ws://192.168.88.10:8765/neurobridge/v1/ws
```

自研客户端在 WebSocket 握手时必须提供 `neurobridge.v1` 子协议。建立连接后：

1. 调用 `getStatus`，检查设备连接、算法状态和 `availableStreams`。
2. 读取一次算法结果使用 `getLatest`；连续数据使用 `subscribe`，按当前可用流选择。
3. 成功响应后接收事件，检查 `code`、`valid`、`mode` 和时间戳；连续数据按 600 ms 窗口组织，不假定每窗口固定样本数。
4. 停止接收时使用本次返回的 `subscriptionId` 调用 `unsubscribe`。取消订阅不等于停止网关采集。
5. 实际断线或重启后重新连接，先 `getStatus` 再重新订阅，旧订阅标识不复用。双方不发送 Ping/Pong 或 JSON 心跳。

模板尚未启用实时采集时，无历史数据的机器只能先验证状态查询和连接。没有实时数据和可用历史会话时，数据请求失败是预期行为，不能凭 `mode` 字段认定正在有效录播。

真实采集由交付方配置并开启后，检查设备连接、原始数据、算法结果各自是否正常，确认 `mode="live"`。离线录播使用交付方准备的历史会话，按《头环数据网关北向网络协议》验证 `mode="replay"`。当前实现的录播由 `getLatest` 或 `subscribe` 请求触发；不要假定设备断开就必然让已有订阅自动开始录播。本文不新增接口或替代已发布协议；涉及录播进度、自动会话选择和循环的细节仍需专项确认。

## 9. 下载、日常运行与更新

启用下载服务时，可从专线上的 B 端访问下列示例地址，实际地址、端口与路径以配置为准：

```text
http://192.168.88.10:8766/downloads
http://192.168.88.10:8766/downloads/recordings/<recordingId>.zip
http://192.168.88.10:8766/downloads/logs/neurobridge-logs.zip
```

正在采集的会话不能导出。首次会话 ZIP 导出可能需要生成附带说明 PDF，目标机须具备 Pandoc、Chrome/Chromium 和可显示中文的字体；环境准备脚本未自动安装这些附加工具。需要该功能时，由交付方在隔离前准备并实测导出，不能仅凭下载索引可访问就判定 ZIP 导出通过。

在网关本地控制台执行常用操作：

```bash
sudo systemctl status neurobridge.service
sudo journalctl -u neurobridge.service -f
sudo systemctl restart neurobridge.service
sudo systemctl stop neurobridge.service
```

更新前备份配置和数据、结束需要保留的采集，并通知 B 端重新建连。在交付方已准备且核对过的本分支源码根目录，于本地控制台执行：

```bash
./linux/update-ubuntu.sh
```

该入口不拉取源码，会重新部署并立即重启网关。缺失依赖时不会自动联网修复。不要用 `neurobridge-ops update` 获取本分支更新，也不要在普通 SSH 会话中手工切换分支绕过现有运维限制。

## 10. 验收记录与排障

逐项记录实际结果，未执行项目标为“未验证”，不可将其他系统结果代替目标网关结果。

| 检查项 | 通过依据 |
| --- | --- |
| 系统与批准版本 | Ubuntu 24.04、x86_64、完整提交号与批准记录一致 |
| 配置与监听 | 专用网卡地址正确，只在批准地址与端口提供服务 |
| B 端基础交互 | 状态查询、数据请求、订阅与取消订阅符合正式协议 |
| 真实采集与处理 | 目标设备原始数据和算法结果分别验证，记录有效性及时间范围 |
| 离线场景 | 无历史和有历史两种情况分别验证，录播与实时标识不混淆 |
| 头环断开及恢复 | 状态可观察，恢复后实时数据继续产生 |
| B 端断开及恢复 | 后台继续工作，客户端重新连接并创建新订阅 |
| 业务服务与整机重启 | 后台自启正常；如启用 SSH，其地址、监听和来源限制仍生效 |
| 文件导出 | 已结束会话 ZIP、附带说明和日志 ZIP 均可完整下载 |

| 现象 | 处理 |
| --- | --- |
| 环境准备后 SSH 断开 | 准备脚本停用了默认 SSH；改在本地控制台完成第 7 节，不临时开放通配监听 |
| 安装拒绝系统或架构 | 核对系统与 `uname -m`，不绕过检查复用其他平台结果 |
| 配网提示活跃接口或 Netplan 冲突 | 核对实际网口和原网络，按第 5 节处理；冲突未确认前不强行覆盖 |
| 服务绑定地址失败 | 用 `ip -br addr` 核对本机实际地址和配置，查看服务日志 |
| B 端无法握手 | 核对网线、地址、端口、路径、现场防火墙和 `neurobridge.v1` 子协议 |
| 连接成功但无数据 | 区分未开启采集、设备未连接、算法无有效结果和没有历史数据；检查状态及错误原因 |
| ZIP 导出失败 | 确认会话已结束，并检查 PDF 工具及中文字体是否准备完整 |

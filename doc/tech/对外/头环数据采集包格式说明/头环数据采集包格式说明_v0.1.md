# 头环数据采集包格式说明 v0.1

版本：v0.1

日期：2026-08-05

## 1. 适用范围

本文定义网关“**一键保存 ZIP**”导出的采集数据包。数据包用于经授权的数据交付、离线分析和问题复核；它不是实时 WebSocket 接口，也不改变《头环数据网关北向网络协议》的请求、响应或订阅规则。

数据包包含敏感生理数据。接收方应仅在获得受试者授权的受控设备中保存、传输和处理，不得上传至公共网络或提交至代码仓库。

## 2. ZIP 目录

每次采集会话导出一个 ZIP，文件名为 `neurobridge-<sessionId>.zip`。ZIP 根目录为 `<sessionId>/`：

```text
<sessionId>/
├── manifest.json
├── raw/
│   ├── eeg.jsonl
│   └── hr.jsonl
└── algorithm/
    ├── bio.jsonl
    ├── hr.jsonl
    ├── hrv.jsonl
    ├── attention.jsonl
    ├── flow.jsonl
    ├── pressure.jsonl
    ├── relaxation.jsonl
    ├── pleasure.jsonl
    ├── coherence.jsonl
    ├── arousal.jsonl
    └── sleep.jsonl
```

所有 `.jsonl` 文件均为 UTF-8 JSON Lines：每个非空行是一个完整 JSON 对象；同一文件按记录写入顺序排列。某项本次没有产生结果时，对应文件保留为空文件。

## 3. 时间与有效性约定

- 所有 `*Ms` 时间戳均为 UTC Unix Epoch 毫秒。
- 原始数据的 `receivedAtMs` 是网关接收到该数据包的时间。
- 算法结果的 `timestampMs` 是该项结果所对应输入数据的最新接收时间；`computedAtMs` 是网关完成该次计算的时间。
- 各算法指标独立写入，记录条数和时间戳不要求相同。例如心率、HRV、注意力和压力可以在不同时间产生记录。
- `valid=false` 时，接收方应结合 `invalidReasons` 判断是否使用该记录；无效记录仍会保留，便于追溯。

## 4. 原始数据文件

### 4.1 `raw/eeg.jsonl`

保存原始脑波数据。网关每接收到一条脑波数据即追加一行，不合并、不重排。

### 4.2 `raw/hr.jsonl`

保存原始心率数据。网关每接收到一条心率数据即追加一行，不与脑波数据混写。

两类原始数据行使用相同字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sessionId` | string | 采集会话标识，与 ZIP 根目录一致 |
| `receivedAtMs` | int64 | 网关接收此条原始数据的时间 |
| `windowStartMs` / `windowEndMs` | int64 | 此条数据所属的网关采集窗口时间范围 |
| `sequence` | int | 此会话、此文件内从 1 开始递增的序号 |
| `packetBytes` | int | 当前原始数据包的字节数 |
| `encoding` | string | 固定为 `"base64"` |
| `bytesBase64` | string | 当前原始数据包的 Base64 编码，保持接收顺序 |
| `valid` | boolean | 当前数据包长度是否符合当前采集配置 |
| `invalidReasons` | string array | `valid=false` 的原因；有效时为空数组 |

## 5. 算法数据文件

每个算法文件只保存一类指标的独立时间线。通用字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sessionId` | string | 采集会话标识 |
| `metric` | string | 当前文件对应的指标名 |
| `timestampMs` | int64 | 该指标所对应输入数据的最新接收时间 |
| `computedAtMs` | int64 | 网关完成该次算法计算的时间 |
| `source` | object | 输入关联信息，字段见下表 |
| `value` | number or object | 当前指标值；对象型指标保留其完整结构 |
| `algorithm` | object | 可直接合并到实时算法对象的当前指标片段 |
| `valid` | boolean | 此算法记录是否有效 |
| `invalidReasons` | string array | 无效原因；有效时为空数组 |

`source` 字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `receivedAtMsStart` / `receivedAtMsEnd` | int64 | 参与本次计算的输入数据接收时间范围 |
| `packetCount` | int | 参与本次计算的输入数据条数 |
| `windowStartMs` / `windowEndMs` | int64 | 关联采集窗口时间范围 |

### 5.1 算法文件与指标对应关系

| 文件 | `metric` | `value` 内容 |
| --- | --- | --- |
| `bio.jsonl` | `bio` | 生物信号结果对象：脑波波形、频段能量和质量值 |
| `hr.jsonl` | `hr` | 心率值 |
| `hrv.jsonl` | `hrv` | 心率变异性值 |
| `attention.jsonl` | `attention` | 注意力值 |
| `flow.jsonl` | `flow` | 心流结果对象 |
| `pressure.jsonl` | `pressure` | 压力值 |
| `relaxation.jsonl` | `relaxation` | 放松度 |
| `pleasure.jsonl` | `pleasure` | 愉悦度 |
| `coherence.jsonl` | `coherence` | 和谐度 |
| `arousal.jsonl` | `arousal` | 激活度 |
| `sleep.jsonl` | `sleep` | 新产生的睡眠结果对象 |

`sleep.jsonl` 仅在本次计算明确产生新的睡眠结果时新增记录，不以重复的历史睡眠状态填充。

示例：`attention.jsonl` 中的两条独立记录：

```json
{"sessionId":"rec-example","metric":"attention","timestampMs":1785921067200,"computedAtMs":1785921067218,"source":{"receivedAtMsStart":1785921066600,"receivedAtMsEnd":1785921067200,"packetCount":50,"windowStartMs":1785921066600,"windowEndMs":1785921067200},"value":58.81,"algorithm":{"attention":58.81},"valid":true,"invalidReasons":[]}
{"sessionId":"rec-example","metric":"attention","timestampMs":1785921068400,"computedAtMs":1785921068419,"source":{"receivedAtMsStart":1785921067800,"receivedAtMsEnd":1785921068400,"packetCount":50,"windowStartMs":1785921067800,"windowEndMs":1785921068400},"value":59.47,"algorithm":{"attention":59.47},"valid":true,"invalidReasons":[]}
```

## 6. `manifest.json`

`manifest.json` 是数据包清单和完整性校验入口：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `formatVersion` | string | 数据包格式版本，当前为 `"1.0"` |
| `sessionId` | string | 会话标识 |
| `startedAtMs` | int64 or null | 会话创建时间 |
| `files` | array | ZIP 内每个数据文件的清单 |
| `files[].path` | string | 相对 ZIP 根目录的文件路径 |
| `files[].records` | int | 文件中的 JSON 记录数 |
| `files[].timestampStartMs` / `.timestampEndMs` | int64 or null | 文件记录的时间范围 |
| `files[].sha256` | string | 文件原始字节的 SHA-256 摘要，用于完整性校验 |

接收方应先读取 `manifest.json`，再按需读取相应原始流或算法指标文件；校验时计算文件 SHA-256 并与清单比对。

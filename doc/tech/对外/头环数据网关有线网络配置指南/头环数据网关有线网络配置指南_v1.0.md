# 头环数据网关有线网络配置指南 v1.0

版本：v1.0

状态：未发布（评审稿）

适用对象：经授权的网关交付与 B 端运维人员

创建日期：2026-08-10

## 1. 用途与边界

本指南说明如何将已部署的头环数据网关从临时联网环境切换到网关与 Windows B 端主机之间的专用有线直连网络，并为两端配置静态 IPv4 地址。

本文只涉及网关与 B 端主机可观察的有线网络配置和连通性验证，不包含设备接入、数据处理或其他网关内部实现细节。未发布版本仅供评审和现场准备使用，不能作为验收或正式交付依据。

本文使用以下操作位置标记：

- **网关本地控制台**：在网关连接显示器、键盘的本机终端执行。
- **Windows B 端主机**：在连接网关专用网线的 Windows 主机上执行。

## 2. 前提与默认参数

请在切换前由网关交付方确认网关已安装包含“专用有线网络自动配置”功能的批准版本。网关在原网络中更新或准备软件时，不应修改其当前网口地址；所有地址切换均在断开原网络后、通过网关本地控制台完成。

下表是本指南的默认直连示例。现场已确认其他值时，以现场部署配置为准，双方必须同时改用同一网段内且不重复的地址。

| 项目 | 默认示例 | 说明 |
| --- | --- | --- |
| 网关 IPv4 | `192.168.88.10` | 网关在专用网口的静态地址。 |
| B 端 IPv4 | `192.168.88.20` | Windows B 端专用网卡的静态地址。 |
| 子网掩码 | `255.255.255.0` | 即 CIDR `/24`。 |
| 默认网关 | 不填写 | 专用直连网口不应提供默认路由。 |
| DNS | 不填写 | 专用直连网口不使用 DNS。 |
| WebSocket 地址 | 以交付参数为准 | 使用已确认的网关地址、端口和路径；接口规则见 [头环数据网关北向网络协议 v0.2](../头环数据网关北向网络协议/头环数据网关北向网络协议_v0.2.md)。 |

专用网线不得接入公网、无线网络、普通局域网或网络桥接设备。Windows B 端不得启用 Internet Connection Sharing（网络共享）或网络桥接。

## 3. 网关侧切换

### 3.1 确认专用网口

**操作位置：网关本地控制台。**

查看网口名称和当前地址：

```bash
ip -br addr
```

选择用于连接 B 端的有线网口。网口名称因设备而异，例如 `enp1s0`；不要假定所有网关都使用同一个名称。无线网口不用于本指南的专用直连。

如果网关有多个有线网口，必须明确选择连接 B 端的一个网口；不要依赖自动选择。未确认网口时停止操作并联系网关交付方。

### 3.2 断开原网络并更新网关配置

**操作位置：网关本地控制台。**

1. 断开网关与原网络的网线。
2. 将网关有线网口与 Windows B 端主机使用单根专用网线直连。
3. 编辑部署配置：

   ```bash
   sudoedit /etc/neurobridge/gateway.toml
   ```

4. 按已确认的值填写。以下仅为第 2 节默认示例；`enp1s0` 必须替换为实际 B 端网口名。

   ```toml
   [server]
   host = "192.168.88.10"

   [network]
   mode = "static"
   interface = "enp1s0"
   subnet_cidr = "192.168.88.0/24"

   [download]
   host = "192.168.88.10"
   ```

   如果下载服务未启用，仍应保持其 `host` 与 `[server].host` 一致，以便后续启用时不会绑定到错误地址。

5. 应用专用网络配置：

   ```bash
   sudo /opt/neurobridge/venv/bin/neurobridge-network-config \
     --config /etc/neurobridge/gateway.toml \
     --apply --replace-active
   ```

   `--replace-active` 仅用于这一次已确认的切换：原网络必须已物理断开，且操作者必须确认该网口将专用于 B 端。日常安装或更新不会自动使用该参数。

6. 重启网关服务并确认地址：

   ```bash
   sudo systemctl restart neurobridge.service
   ip -br addr show enp1s0
   ```

   预期看到 `192.168.88.10/24`。服务重启会中断已有 WebSocket 连接；B 端恢复连接后须先调用 `getStatus`，再重新订阅。

如果配置器报告目标网口已有其他 Netplan 配置、当前网络状态无法检查或参数不合法，停止操作并联系网关交付方。不要手工删除未知网络配置、强制覆盖管理网口或临时接入不受控网络绕过检查。

## 4. Windows B 端静态 IPv4 配置

### 4.1 图形界面配置

**操作位置：Windows B 端主机。**

1. 打开“控制面板 → 网络和 Internet → 网络连接”。
2. 右键连接网关专用网线的“以太网”适配器，选择“属性”。
3. 选择“Internet 协议版本 4 (TCP/IPv4)”，点击“属性”。
4. 选择“使用下面的 IP 地址”，按第 2 节已确认值填写：

   | 字段 | 默认示例 |
   | --- | --- |
   | IP 地址 | `192.168.88.20` |
   | 子网掩码 | `255.255.255.0` |
   | 默认网关 | 留空 |
   | 首选 DNS 服务器 | 留空 |

5. 保存设置。不要在该以太网适配器上配置默认网关、DNS、网络桥接或网络共享。

Windows 若同时使用其他网络适配器进行本机办公，应确保没有将该适配器与本专用以太网桥接；B 端访问网关时会优先使用同网段的专用以太网直连路由。

### 4.2 命令行配置（可选）

**操作位置：以管理员身份运行的 Windows PowerShell。**

先查看实际适配器名称：

```powershell
Get-NetAdapter
```

再使用实际名称替换下面的 `Ethernet`：

```powershell
netsh interface ipv4 set address name="Ethernet" source=static address=192.168.88.20 mask=255.255.255.0 gateway=none
```

命令只应作用于连接网关专用网线的适配器；不要对仍承担办公或管理网络连接的适配器执行此命令。

## 5. 连通性与业务验证

**操作位置：Windows B 端主机。**

确认 Windows 地址：

```powershell
ipconfig
```

确认已确认的 WebSocket TCP 端口可达；将 `<端口>` 替换为交付方确认的实际值：

```powershell
Test-NetConnection 192.168.88.10 -Port <端口>
```

预期 `TcpTestSucceeded` 为 `True`。随后以交付方确认的 WebSocket 地址、路径和子协议建立连接。连接或服务重启后，B 端先调用 `getStatus`，再创建新的订阅；旧 `subscriptionId` 不可复用。

## 6. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 网关工具拒绝重配网口 | 确认原网络已物理断开，且正在操作的确为 B 端专用网口。不要通过未知网络或删除未知配置绕过检查。 |
| Windows 无法连通网关端口 | 核对网线、两端 IP/子网掩码、Windows 适配器选择、网关服务状态，以及双方确认的端口和路径。 |
| `Test-NetConnection` 失败 | 在网关本地控制台执行 `ip -br addr show <网口名>`，确认网关地址；再检查服务状态：`sudo systemctl status neurobridge.service --no-pager`。 |
| B 端连接恢复后没有连续数据 | 按北向协议重新连接，先调用 `getStatus`，再重新订阅；不要复用断线前的订阅标识。 |

# 头环蓝牙网关北向网络协议

版本：v0.1  
日期：2026-08-04  
状态：**实现基线；联调前由双方确认网络地址、证书、访问控制与字段选择**

## 1. 目的与结论

本文定义头环蓝牙网关与第三方 B 端主机之间的北向接口。它落实《[头环蓝牙网关对接方案 v0.1](头环蓝牙网关对接方案_v0.1.md)》的“B 端按需请求、连续数据每 600 ms 返回一组”的要求。

首期统一采用 **WebSocket Secure（WSS）+ UTF-8 JSON 文本帧**：

- 网关是 WebSocket 服务端，B 端主机是客户端；B 端主动连接网关并通过请求决定读取或订阅哪些数据。
- 正式环境使用 `wss://`，默认监听 `8443` 端口、路径 `/neurobridge/v1/ws`。证书、端口、网段和 B 端主机地址白名单均由部署配置提供，不能写死在程序或文档示例中。
- 仅在隔离的本机/验收测试环境，且经双方书面确认后，允许以配置方式启用 `ws://`；不得将明文模式作为现场或生产默认值。
- 所有业务消息使用 JSON，便于 B/S 和桌面端调试；原始字节流以 Base64 承载，避免另行约定 TCP 分帧或二进制解码。以后若原始波形带宽成为瓶颈，再以独立的二进制子协议升级，不能改变本版本 JSON 的语义。
- **所有网关到 B 端的输出**（成功响应、失败响应、数据事件和状态事件）使用同一根对象：`{ "protocolVersion": "1.0", "code": 200, "data": {}, "message": "OK" }`。B 端到网关的请求保持第 3 节格式。

该选择同时支持请求-响应和服务端连续推送，适合 B 端主机控制 `getLatest`、`subscribe`、`unsubscribe` 与录播切换；也使实时与录播复用同一条连接和同一份数据模型。

```text
第三方 B 端主机                         网关
     │  WSS：连接、请求、订阅              │
     ├──────────────────────────────────►│
     │◄──── 状态、确认、每 600 ms 数据 ───┤
     │                                     │
     │                             BLE：头环通知
     │                             算法：本地计算
```

## 2. 版本与连接控制

### 2.1 WebSocket 握手

```text
wss://{gateway-host}:8443/neurobridge/v1/ws
```

| 项目 | 规定 |
| --- | --- |
| WebSocket 子协议 | `neurobridge.v1` |
| 编码 | UTF-8 JSON 对象；一个 WebSocket 文本帧对应一个完整业务消息 |
| TLS | WSS 必须校验证书链与主机名；自签名证书仅在双方明确配置可信根时使用 |
| 首个业务请求 | 无应用层鉴权；B 端连接后建议先发送 `getStatus` |
| 连接保活 | 使用标准 WebSocket Ping/Pong 控制帧；完整规则见第 2.1.1 节 |
| 版本不兼容 | 握手子协议不匹配时拒绝握手；已建立连接收到未知的 `protocolVersion` 时返回 `UNSUPPORTED_VERSION` |

v0.1 **不使用 Token、账号密码或业务帧鉴权**。网关只可部署在受控内网；访问控制由有线隔离网络、VLAN/防火墙和 B 端主机源 IP/MAC 白名单承担。禁止将该端口暴露到公网。WSS 仅用于链路加密和服务端身份校验，不承担客户端身份识别。

### 2.1.1 连接保活（Ping/Pong）

保活使用 RFC 6455 定义的 WebSocket **控制帧**，不使用 JSON 业务消息，因此 Ping/Pong 不带 `{protocolVersion, code, data, message}` 包络。

| 项目 | 规定 |
| --- | --- |
| 发起方 | 网关；B 端不主动发起 Ping |
| Ping 帧 | WebSocket opcode `0x9`；负载固定为空字节串 |
| 发送间隔 | 网关对每条已建立连接每 15 秒发送一次 Ping，不因实时数据推送而跳过 |
| Pong 帧 | B 端收到 Ping 后必须立即回复 WebSocket opcode `0xA`；负载必须与 Ping 完全一致，即空字节串 |
| 计数规则 | 某次 Ping 的 15 秒内未收到对应 Pong，记为一次未响应；收到任意一次有效 Pong 后，将连续未响应计数清零 |
| 超时关闭 | 连续 3 次未响应后，网关以 WebSocket Close code `4000`、reason `KEEPALIVE_TIMEOUT` 关闭连接，并释放该连接创建的全部订阅 |
| 业务包络 | Ping/Pong 是协议控制帧，B 端不可将其当作 JSON 事件或依据 `code` 处理 |

多数 WebSocket 客户端库会自动回复 Pong；浏览器的 WebSocket API 也会自动处理服务器 Ping，但 JavaScript 代码通常不能手动构造 Ping/Pong。B 端若使用的库关闭了自动 Pong，必须启用该能力。

连接被关闭、网络断开或发生 `KEEPALIVE_TIMEOUT` 后，B 端应以 1、2、4、8、15、30 秒的退避间隔重连（达到 30 秒后保持 30 秒）。重连成功后，先调用 `getStatus`，再按业务需要重新调用 `subscribe`；旧 `subscriptionId` 已失效，不能复用。

### 2.2 网关输出包络与通用字段

网关输出的根对象**只能**包含以下四个字段；字段名称、类型和层级不得因消息类型不同而改变。`data` 始终为 JSON 对象：成功时承载响应结果或事件负载，失败时承载可选的上下文。

| 根字段 | 类型 | 规则 |
| --- | --- | --- |
| `protocolVersion` | string | 固定为 `"1.0"` |
| `code` | int | HTTP 风格响应码；`200` 是成功，非 `200` 是失败 |
| `data` | JSON object | 成功结果、事件负载或失败上下文；无内容时为 `{}`，不使用 `null` |
| `message` | string | 成功时固定为 `"OK"`；失败时必须是可读的错误原因 |

服务端数据事件的 `data` 字段如下：

```json
{
  "protocolVersion": "1.0",
  "code": 200,
  "data": {
    "event": "data",
    "gatewayBootId": "20260804T100000Z-7bf0",
    "subjectId": "SUBJECT-001",
    "mode": "live",
    "timestampMs": 1785800000123,
    "valid": true,
    "payload": {}
  },
  "message": "OK"
}
```

| 字段/规则 | 适用位置 | 约定 |
| --- | --- | --- |
| `requestId` | B 端请求、网关请求响应 | 由 B 端生成；网关在 `data.requestId` 原样返回；服务端事件不包含该字段 |
| 单实例范围 | 整个 v0.1 协议 | 单头环、单网关实例；不传 `deviceId` 或 `gatewayId` |
| `timestampMs` | 数据/状态事件、状态响应 | Unix Epoch 毫秒（UTC） |
| 业务空值 | 所有业务字段 | 值暂不可用、算法尚未产生结果或硬件不支持时使用 `null`；不得使用 `0` 表示未知 |
| 数值编码 | 所有 JSON number | 不得传 `NaN`、`Infinity` 或字符串化数字 |

#### `gatewayBootId` 与 `subjectId` 获取表

| 字段 | 网关来源 | B 端首次获取 | 后续获取 | B 端是否传入 | 取值说明 | 用途 |
| --- | --- | --- | --- | --- | --- | --- |
| `gatewayBootId` | 网关进程启动时生成，进程存活期间不变 | 建连后调用 `getStatus`，读取 `data.result.gatewayBootId` | 每条数据/状态事件的 `data.gatewayBootId` | 否 | 网关重启时变更 | 标识网关进程实例；值变更表示应重新获取状态并重新订阅 |
| `subjectId` | 当前录播的元数据；实时模式可由部署配置提供 | 建连后调用 `getStatus`，读取 `data.result.subjectId` | 数据/状态事件的 `data.subjectId`；选择录播后还可读取 `selectReplay` 响应的 `data.result.subjectId` | 实时请求：否；`selectReplay`：可选筛选条件 | 未配置或未知时为 `null` | 标识录播或展示中的受试者；B 端未知时显示为空，不得自行补造 |

### 2.3 字段标注约定与请求根对象

为保持示例为合法 JSON，字段说明使用下列表格而不是在 JSON 内加入注释。`必填`中的“条件”表示仅在相应动作、流、模式或错误场景中出现；未标注为可空的字段不得传 `null`。

| 标记 | 含义 |
| --- | --- |
| 是 | 字段必须存在且不得为 `null` |
| 否 | 字段可省略 |
| 条件 | 满足该行描述的条件时必须存在 |
| 可空 | 字段必须存在，但值允许为 `null` |

B 端发送的所有请求使用以下根对象；请求不使用 `code`、`data`、`message` 包络。

| 字段路径 | 类型 | 必填 | 注释 |
| --- | --- | --- | --- |
| `protocolVersion` | string | 是 | 协议版本，v0.1 固定为 `"1.0"` |
| `messageType` | string | 是 | 固定为 `"request"`，用于与网关输出区分 |
| `requestId` | UUID string | 是 | B 端为本次请求生成的唯一标识；网关在响应的 `data.requestId` 原样返回 |
| `action` | string | 是 | 请求动作：`getStatus`、`getLatest`、`subscribe`、`unsubscribe` 或 `selectReplay` |
| `params` | JSON object | 是 | 动作参数；对象不能为空时见各动作字段表 |

所有请求响应的 `data` 至少包含下列字段：

| 字段路径 | 类型 | 必填 | 注释 |
| --- | --- | --- | --- |
| `data.requestId` | UUID string | 是 | 与请求中的 `requestId` 完全相同 |
| `data.action` | string | 是 | 与请求中的 `action` 相同 |
| `data.result` | JSON object | 是 | 动作成功结果；无结果时使用 `{}`，不使用 `null` |

## 3. 请求与响应

WebSocket 连接建立后，B 端可直接发送请求。所有成功响应均使用 `code: 200`、`message: "OK"`，并在 `data` 中返回原 `requestId`、`action` 与 `result`；失败使用第 7 节的非 200 包络。

| 动作 | 用途 | 成功后的返回 | 是否持续收到数据 | 是否改变数据源/订阅状态 | 典型使用时机 |
| --- | --- | --- | --- | --- | --- |
| `getStatus` | 查询头环连接、佩戴、电量、当前模式及可用流 | 一次状态响应 | 否 | 否 | 建连、重连或需要刷新界面状态时 |
| `getLatest` | 获取指定算法流的最近一次计算结果 | 一次最新值响应 | 否 | 否 | B 端只需当前注意力、放松度等数值，不需实时曲线时 |
| `subscribe` | 建立对原始数据、算法或状态流的连续订阅 | 一次订阅确认，随后 `data.event="data"`/`"status"` 事件 | 是，连续流最多每 600 ms 一组 | 新建订阅；返回 `subscriptionId` | 展示实时波形、脑波节律或持续变化的算法结果时 |
| `unsubscribe` | 取消一个已有连续订阅 | 一次取消确认 | 否 | 删除指定 `subscriptionId` 对应订阅 | 离开页面、停止展示或切换业务场景时 |
| `selectReplay` | 选择录播文件并启动指定倍率回放 | 一次录播选择确认；已有订阅随后收到 `mode="replay"` 的事件 | 仅对已有订阅持续发送 | 切换当前数据源为录播；不自动创建订阅 | 无头环演示，或需要播放历史数据时 |

调用顺序如下：

| 场景 | 推荐顺序 | 说明 |
| --- | --- | --- |
| 实时展示 | `getStatus` → `subscribe` | 先确认头环已连接和所需流可用，再接收持续事件 |
| 只读一次当前值 | `getStatus` → `getLatest` | 不会创建订阅，也不会持续推送 |
| 录播展示 | `getStatus` → `subscribe` → `selectReplay` | 先订阅可避免回放开始后错过首批数据；`selectReplay` 之前收到的实时事件可按 `mode` 过滤 |
| 停止展示 | `unsubscribe` | 传入之前 `subscribe` 返回的 `subscriptionId`；断线后订阅自动释放，无需再次取消 |

例如，`subscribe` 的成功响应如下：

```json
{
  "protocolVersion": "1.0",
  "code": 200,
  "data": {
    "requestId": "fa3af4d9-1dc1-436d-af45-5855d3994fe7",
    "action": "subscribe",
    "result": {
      "subscriptionId": "sub-01HXYZ",
      "streams": ["algorithm.eeg", "algorithm.hr"],
      "intervalMs": 600
    }
  },
  "message": "OK"
}
```

### 3.1 `getStatus`

读取网关、头环连接、佩戴、电量、信号与当前运行模式。B 端连接后应先调用该接口。

```json
{
  "protocolVersion": "1.0",
  "messageType": "request",
  "requestId": "e99942e1-e9ce-4d29-a6f4-8e0bd50a6e42",
  "action": "getStatus",
  "params": {}
}
```

响应的 `data.result` 至少包括 `gatewayBootId`、`subjectId`、`mode`、`connectionState`（`connected`/`connecting`/`disconnected`/`replaying`）、`wearState`（`worn`/`notWorn`/`unknown`）、`batteryPercent`、`signalQuality`、`algorithmState`、`availableStreams` 与 `serverTimeMs`。

| 字段路径 | 类型 | 必填 | 注释 |
| --- | --- | --- | --- |
| `data.result.gatewayBootId` | string | 是 | 本次网关进程启动标识；变化表示网关已重启 |
| `data.result.subjectId` | string | 可空 | 当前实时或录播数据源的受试者标识；实时未配置时为 `null` |
| `data.result.mode` | string | 是 | 当前数据源模式：`live` 或 `replay` |
| `data.result.connectionState` | string | 是 | `connected`、`connecting`、`disconnected` 或 `replaying` |
| `data.result.wearState` | string | 是 | `worn`、`notWorn` 或 `unknown` |
| `data.result.batteryPercent` | number | 可空 | 电量百分比；范围和换算以头环 profile 为准 |
| `data.result.signalQuality` | number | 可空 | 当前信号质量；来源和范围由设备/算法 profile 确定 |
| `data.result.algorithmState` | string | 是 | `ready`、`warmingUp`、`unavailable` 或 `error` |
| `data.result.availableStreams` | string array | 是 | 当前可订阅的流名称列表，取值见第 4.1 节 |
| `data.result.serverTimeMs` | int64 | 是 | 网关当前 Unix Epoch 毫秒（UTC） |

### 3.2 `getLatest`

获取指定算法字段的最近一次有效计算结果，不启动持续传送。`streams` 只能包含第 4 节定义的算法流；缺省为 `algorithm.eeg` 和 `algorithm.hr`。

```json
{
  "protocolVersion": "1.0",
  "messageType": "request",
  "requestId": "a671a32d-4ba7-4d18-a6e5-fabc54df3f8e",
  "action": "getLatest",
  "params": {
    "streams": ["algorithm.eeg", "algorithm.hr"]
  }
}
```

响应的 `data.result` 使用与第 5 节 `payload` 相同的结构，并包含该结果的 `timestampMs` 与 `valid`。没有可用结果时，响应仍为 `code: 200`，但 `data.result.valid=false` 且 `data.result.payload` 为空对象。

| 字段路径 | 类型 | 必填 | 注释 |
| --- | --- | --- | --- |
| `params.streams` | string array | 否 | 仅允许 `algorithm.eeg`、`algorithm.hr`；缺省时两者都返回 |
| `data.result.timestampMs` | int64 | 是 | 最近结果对应的 Unix Epoch 毫秒（UTC） |
| `data.result.valid` | boolean | 是 | `true` 表示 `payload` 是可展示/保存的有效算法结果 |
| `data.result.payload` | JSON object | 是 | 仅包含所请求且已产生的算法字段，字段定义见第 5.2 节 |

### 3.3 `subscribe` 与 `unsubscribe`

`subscribe` 启动一个独立订阅。成功后网关立即确认，随后以 `data.event: "data"` 推送。对连续流，网关按 **600 ms 窗口** 至多发送一条事件；窗口内无新数据时不补发空事件，除非订阅了 `status`。

```json
{
  "protocolVersion": "1.0",
  "messageType": "request",
  "requestId": "fa3af4d9-1dc1-436d-af45-5855d3994fe7",
  "action": "subscribe",
  "params": {
    "streams": ["algorithm.eeg", "algorithm.hr", "eeg.raw", "status"],
    "includeInvalid": true
  }
}
```

成功响应的 `data.result` 包含 `subscriptionId`、`streams`、`intervalMs: 600`。`subscriptionId` 只在当前 WebSocket 连接有效；断线后 B 端重连并重新订阅。

| 字段路径 | 类型 | 必填 | 注释 |
| --- | --- | --- | --- |
| `params.streams` | string array | 是 | 至少一个流名称，取值见第 4.1 节；重复项按一个流处理 |
| `params.includeInvalid` | boolean | 否 | `true` 时推送 `valid=false` 的数据窗口；缺省为 `false` |
| `data.result.subscriptionId` | string | 是 | 当前连接内唯一的订阅标识；用于 `unsubscribe` |
| `data.result.streams` | string array | 是 | 网关实际接受的流名称；不得包含未请求的流 |
| `data.result.intervalMs` | int | 是 | 连续流的最小发送窗口，v0.1 固定为 `600` |

`unsubscribe` 的 `params` 只包含 `subscriptionId`。网关确认后不得再向该订阅发送数据事件。重复取消不存在的订阅返回 `SUBSCRIPTION_NOT_FOUND`。

| 字段路径 | 类型 | 必填 | 注释 |
| --- | --- | --- | --- |
| `params.subscriptionId` | string | 是 | 待取消的、当前 WebSocket 连接创建的订阅标识 |
| `data.result.subscriptionId` | string | 是 | 已取消的订阅标识，与请求相同 |

### 3.4 `selectReplay`

选择并启动录播。实时和录播通过 `mode` 区分，事件结构保持不变。

```json
{
  "protocolVersion": "1.0",
  "messageType": "request",
  "requestId": "6a60efc9-cf92-44d1-b0bb-f64746cb43a1",
  "action": "selectReplay",
  "params": {
    "recordingId": "demo-001",
    "subjectId": "SUBJECT-001",
    "playbackRate": 1.0
  }
}
```

`playbackRate` 允许 `0.5`、`1.0`、`2.0`，缺省为 `1.0`。网关不得以“尽快发送”替代指定倍率；若后续需要快发模式，必须以新的协议版本扩展。播放结束发送 `data.event: "replayEnded"`，其中包含 `recordingId`、`subjectId` 与结束时间。

| 字段路径 | 类型 | 必填 | 注释 |
| --- | --- | --- | --- |
| `params.recordingId` | string | 是 | 网关已配置、可访问的录播文件/会话标识 |
| `params.subjectId` | string | 否 | 可选的录播受试者筛选条件；B 端未知时应省略，网关使用录播元数据中的受试者 |
| `params.playbackRate` | number | 否 | 回放倍率，仅允许 `0.5`、`1.0`、`2.0`；缺省 `1.0` |
| `data.result.recordingId` | string | 是 | 实际选择并启动的录播标识 |
| `data.result.subjectId` | string | 可空 | 该录播关联的受试者标识 |
| `data.result.playbackRate` | number | 是 | 网关实际采用的回放倍率 |
| `data.recordingId` | string | 条件 | 仅 `data.event="replayEnded"` 时存在，表示已结束的录播 |
| `data.endedAtMs` | int64 | 条件 | 仅 `data.event="replayEnded"` 时存在，表示发送结束事件的 Unix Epoch 毫秒 |

## 4. 流名称、BLE 映射与算法映射

### 4.1 可订阅流

| 流 | 含义 | 默认频率 | 数据来源 |
| --- | --- | --- | --- |
| `algorithm.eeg` | 脑电频段、质量、睡眠、放松度、愉悦度、注意力、心流 | 算法结果更新时，最多每 600 ms | 本地算法 `appendEEG`/`appendSCEEG` |
| `algorithm.hr` | 心率、HRV、压力、和谐度、激活度 | 算法结果更新时，最多每 600 ms | 本地算法 `appendHR` |
| `eeg.raw` | 原始 EEG 字节分组 | 每 600 ms | BLE EEG 通知 |
| `hr.raw` | 原始 HR 字节分组 | 每 600 ms | BLE HR 通知 |
| `status` | 连接、佩戴、电量、信号状态变化 | 状态变化时；连续订阅时最多每 600 ms | BLE 与网关状态机 |

网关只发送被订阅的流。未订阅 `eeg.raw`/`hr.raw` 时，不得在算法流中夹带原始数据。

### 4.2 BLE 输入规范

下表基于 [Enter-Biomodule-BLE-PC-SDK](https://github.com/Entertech/Enter-Biomodule-BLE-PC-SDK) 的 `FlowtimeCollector`。这是当前首期设备适配配置；新头环型号必须新增设备 profile，不能复用本表而猜测 UUID 或帧格式。

| BLE 特征 | UUID | 单次通知 | 网关规范化字段 |
| --- | --- | --- | --- |
| EEG | `0000ff31-1212-abcd-1523-785feabcd123` | 20 个无符号字节，SDK 以 `>20B` 解包 | `eeg.raw` |
| HR | `0000ff51-1212-abcd-1523-785feabcd123` | 1 个无符号字节，SDK 以 `>B` 解包 | `hr.raw` |
| 佩戴状态 | `0000ff32-1212-abcd-1523-785feabcd123` | 1 个无符号字节；当前 SDK 将 `0` 映射为已佩戴 | `status.wearState` |
| 电量 | `00002A19-0000-1000-8000-00805F9B34FB` | 1 个无符号字节；SDK 做百分比换算 | `status.batteryPercent` |

网关必须原样保留 EEG/HR 原始字节后再交给算法。对于当前双通道 Flowtime profile，一个 600 ms EEG 窗口应为 **50 个通知 × 20 字节 = 1000 字节**；HR 算法窗口为 **3 个 1 字节通知**。这与算法 SDK 的 `appendEEG`/`appendHR` 默认 0.6 秒触发设计相对应。若实际包数不符，网关必须标记 `valid=false` 和 `invalidReasons`，不得用填零、截断或拼接相邻窗口的方式伪造完整数据。

单通道 `appendSCEEG` 的字节数、设备 profile 与采样率尚未由本项目头环确认，因此 v0.1 只定义其算法输出字段，不允许在没有 profile 的情况下发送 `eeg.raw` 或声明数据有效。

### 4.3 本地算法输出结构

下表映射 [AffectiveCloud-Algorithm-SDK](https://github.com/Entertech/AffectiveCloud-Algorithm-SDK) C++ 实时结构：`EEGAffectiveRes`、`SCEEGAffectiveRes`、`HRAffectiveRes`。原算法字段名采用 camelCase 输出；数值范围与单位以算法 SDK 的验收结果为准，未验证前不在北向协议中臆定为 0–100。

| 北向字段 | 算法来源 | 说明 |
| --- | --- | --- |
| `algorithm.eeg.wave.left/right` | `EEGTriggerRes.eeglWave` / `eegrWave` | 双通道脑波数组；仅订阅 `algorithm.eeg` 时可发送 |
| `algorithm.eeg.wave.single` | `SCEEGTriggerRes.eegWave` | 单通道脑波数组 |
| `algorithm.eeg.bandPower` | `eegAlpha/Beta/Theta/Delta/Gamma/LowBeta/HighBetaPower` | 频段能量；单通道不包含 low/high beta 时置 `null` |
| `algorithm.eeg.quality` | `eegQuality` | 算法输出的脑电质量值 |
| `algorithm.sleep` | `SleepTriggerRes` | `updated`、`degree`、`state`、`stage`、`spindle` |
| `algorithm.relaxation/pleasure/attention` | `EEGAffectiveRes` | 双通道实时情感结果；单通道当前仅有 `relaxation` |
| `algorithm.flow` | `FlowTriggerRes` | `meditation` 与 `meditationTips` |
| `algorithm.hr` | `HRTriggerRes` | `value` 与 `hrv` |
| `algorithm.pressure/coherence/arousal` | `HRAffectiveRes` | 心率相关情感结果 |

完整版历史报表（如 `getEEGReport`、`getSleepReport`）不属于 v0.1 实时北向流；若 B 端需要，应在后续版本新增分页/文件下载接口，避免把全程数组反复塞入 600 ms 消息。

## 5. `data.payload` 负载格式与示例

### 5.1 原始数据格式

`eeg.raw` 使用以下对象。`bytesBase64` 是 BLE 接收顺序的完整原始字节，不进行数值缩放或字节序转换；`windowStartMs`/`windowEndMs` 由网关记录。

```json
{
  "eegRaw": {
    "encoding": "base64",
    "sampleFormat": "u8",
    "packetBytes": 20,
    "packetCount": 50,
    "byteLength": 1000,
    "windowStartMs": 1785800000000,
    "windowEndMs": 1785800000600,
    "bytesBase64": "..."
  },
  "hrRaw": {
    "sampleFormat": "u8",
    "packetCount": 3,
    "values": [72, 73, 72]
  }
}
```

`sampleFormat: "u8"` 指的是传输前的单字节无符号整数，不代表最终生理量。B 端若需要解释原始数据，必须使用双方确认的头环解析规范，而不能从本协议推断通道布局或采样率。

| 字段路径 | 类型 | 必填 | 注释 |
| --- | --- | --- | --- |
| `payload.eegRaw` | JSON object | 条件 | 仅订阅 `eeg.raw` 时存在 |
| `payload.eegRaw.encoding` | string | 是 | 固定为 `"base64"`，表示 `bytesBase64` 的编码方式 |
| `payload.eegRaw.sampleFormat` | string | 是 | 固定为 `"u8"`，原始字节按无符号 8 位整数解释 |
| `payload.eegRaw.packetBytes` | int | 是 | 一条 EEG BLE 通知的字节数；当前 Flowtime profile 为 `20` |
| `payload.eegRaw.packetCount` | int | 是 | 本窗口实际收到的 EEG 通知数量；双通道正常窗口为 `50` |
| `payload.eegRaw.byteLength` | int | 是 | 原始字节总数，必须等于 `packetBytes × packetCount` |
| `payload.eegRaw.windowStartMs` | int64 | 是 | 窗口起始的 Unix Epoch 毫秒（UTC） |
| `payload.eegRaw.windowEndMs` | int64 | 是 | 窗口结束的 Unix Epoch 毫秒（UTC）；正常窗口与起始时间相差约 600 ms |
| `payload.eegRaw.bytesBase64` | string | 是 | 保持 BLE 接收顺序的完整原始字节，经 Base64 编码后的字符串 |
| `payload.hrRaw` | JSON object | 条件 | 仅订阅 `hr.raw` 时存在 |
| `payload.hrRaw.sampleFormat` | string | 是 | 固定为 `"u8"` |
| `payload.hrRaw.packetCount` | int | 是 | 本窗口实际收到的 HR 通知数量；当前算法正常窗口为 `3` |
| `payload.hrRaw.values` | int array | 是 | 按接收顺序排列的 HR 原始单字节值；数组长度必须等于 `packetCount` |


| 字段路径 | 类型 | 必填 | 注释 |
| --- | --- | --- | --- |
| `data.event` | string | 是 | 事件类型：连续数据为 `"data"`，状态变化为 `"status"`，录播结束为 `"replayEnded"` |
| `data.subscriptionId` | string | 条件 | 由 `subscribe` 产生的连续数据或状态事件必须存在；录播结束事件可省略 |
| `data.gatewayBootId` | string | 是 | 网关进程启动标识；B 端应与 `getStatus` 获取的值比较，变化表示网关已重启，应重新订阅 |
| `data.subjectId` | string | 可空 | 当前数据源的受试者标识；B 端通过 `getStatus` 或 `selectReplay` 响应获取，实时未配置时为 `null` |
| `data.mode` | string | 是 | 数据来源模式：`live` 或 `replay` |
| `data.timestampMs` | int64 | 是 | 该数据组或状态事件的 Unix Epoch 毫秒（UTC） |
| `data.valid` | boolean | 是 | `true` 为有效数据；`false` 时 `payload` 可仅含 `status` 与 `invalidReasons`，B 端不得展示或持久化为有效测量结果 |
| `data.payload` | JSON object | 是 | 已订阅流的业务负载；`data.event="status"` 时至少含 `status` |
| `data.payload.invalidReasons` | string array | 条件 | 仅 `data.valid=false` 时出现，列出窗口无效原因，例如 `EEG_PACKET_COUNT_MISMATCH` |
| `data.recordingId` | string | 条件 | 仅 `data.event="replayEnded"` 时存在 |
| `data.endedAtMs` | int64 | 条件 | 仅 `data.event="replayEnded"` 时存在，表示结束事件产生时间 |

| 字段路径 | 类型 | 必填 | 注释 |
| --- | --- | --- | --- |
| `payload.status` | JSON object | 条件 | 订阅 `status` 或事件类型为 `status` 时存在 |
| `payload.status.connectionState` | string | 是 | `connected`、`connecting`、`disconnected` 或 `replaying` |
| `payload.status.wearState` | string | 是 | `worn`、`notWorn` 或 `unknown` |
| `payload.status.batteryPercent` | number | 可空 | 设备电量百分比，尚未读取或不支持时为 `null` |
| `payload.status.signalQuality` | number | 可空 | 信号质量，未产生或无法评估时为 `null` |

## 6. 实时、录播与状态事件

- 实时数据的 `mode` 为 `live`；录播数据为 `replay`。B 端必须以该字段区分两类数据，不能仅以 `recordingId` 推断。
- 录播的 `timestampMs` 表示录制时数据的原始时间；发送时刻由 WebSocket 到达时间体现，不能覆盖该值。
- 发生 BLE 断连、重连、佩戴、电量或算法运行状态变化时，向订阅了 `status` 的连接发送 `data.event: "status"`。状态事件需在 `data.payload.status` 中包含完整 `status` 对象而非仅差量，便于 B 端重连后的状态恢复。
- 录播期间若无真实头环连接，`connectionState` 可为 `replaying`，不得伪造为 `connected`。

## 7. 错误与限流

失败响应与成功响应使用相同根对象；`code` 为非 200 的 HTTP 风格整数，`message` 是错误原因，`data` 提供机器可读的错误标识与上下文：

```json
{
  "protocolVersion": "1.0",
  "code": 503,
  "data": {
    "requestId": "fa3af4d9-1dc1-436d-af45-5855d3994fe7",
    "reason": "DEVICE_NOT_CONNECTED",
    "retryable": true,
    "details": {}
  },
  "message": "Headband is not connected."
}
```

| 字段路径 | 类型 | 必填 | 注释 |
| --- | --- | --- | --- |
| `data.requestId` | UUID string | 条件 | 由请求触发的错误必须存在，与原请求相同；连接级错误可省略 |
| `data.reason` | string | 是 | 稳定的机器可读错误原因，取值见下表 |
| `data.retryable` | boolean | 是 | `true` 表示 B 端可按退避策略重试；`false` 表示需修正请求或配置 |
| `data.details` | JSON object | 是 | 错误上下文，例如 `recordingId`、`subscriptionId` 或字段校验详情；无额外信息时为 `{}` |

| `code` | `data.reason` | `message` 含义 | 可重试 |
| --- | --- | --- | --- |
| `400` | `INVALID_REQUEST` | 缺少字段、字段类型错误或枚举值错误 | 否 |
| `404` | `DEVICE_NOT_FOUND` / `REPLAY_NOT_FOUND` / `SUBSCRIPTION_NOT_FOUND` | 设备、录播或订阅不存在 | 否 |
| `409` | `STREAM_NOT_AVAILABLE` | 流不支持、算法未启用或设备 profile 不匹配 | 否，需调整请求或配置 |
| `429` | `RATE_LIMITED` | 请求频率或订阅数超过部署限制 | 是 |
| `500` | `INTERNAL_ERROR` | 未预期网关错误 | 是 |
| `503` | `DEVICE_NOT_CONNECTED` / `ALGORITHM_NOT_READY` | 头环未连接或原始数据不足以产生算法结果 | 是 |
| `505` | `UNSUPPORTED_VERSION` | 协议版本不支持 | 否 |

v0.1 默认限制为每连接最多 4 个订阅、每设备每连接最多 1 个相同流订阅、单条 JSON 负载最大 256 KiB。超限时返回 `code: 429`（`RATE_LIMITED`）或 `code: 400`（`INVALID_REQUEST`）；不得静默丢弃事件。具体上限可在部署配置中收紧，但不能放宽到破坏 B 端的验收假设而不通知对方。

## 8. 联调验收

1. B 端能够通过 WSS 建连、调用 `getStatus`，并正确处理证书校验失败、白名单拒绝与网络不可达。
2. 请求 `getLatest` 时只返回所请求的算法字段；未产生算法结果时返回 `valid=false`，不以零值冒充结果。
3. 订阅连续流后，验证每组数据为 600 ms，双通道 EEG 为 50 个 20 字节 BLE 包/1000 原始字节，HR 为 3 个字节；窗口不完整时验证错误状态与 `valid=false`。
4. 验证 `unsubscribe`、WebSocket 断开和重连后不会残留旧订阅；验证网关每 15 秒 Ping、B 端自动/手动 Pong、连续 3 次未响应时以 `4000/KEEPALIVE_TIMEOUT` 关闭并释放订阅，以及退避重连后的重新订阅。
5. 验证头环断线、重连、未佩戴、电量变更、算法异常和服务端重启均生成可处理的状态或错误。
6. 验证录播使用同一 `data.payload` 结构、保留 `mode=replay` 与原始时间戳，并按 `0.5x`、`1x`、`2x` 正确节奏回放。
